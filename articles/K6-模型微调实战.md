## 引言：模型微调的工程本质

模型微调（Fine-tuning）不是简单的"在特定数据上再训练一遍"，而是一门**在低维子空间中寻找最优参数适配**的工程技术。

核心认知：

```
预训练模型的本质：在通用数据分布D_general上学习到的参数θ_pre

微调的本质：在特定任务分布D_task上，找到Δθ使得
           Loss(θ_pre + Δθ, D_task) << Loss(θ_pre, D_task)

关键洞察：
- 全量微调：Δθ ∈ R^d，其中d是模型参数数量（数十亿）
- PEFT：Δθ = A × B，其中A ∈ R^{d×r}, B ∈ R^{r×d}, r << d
- 有效参数从数十亿降到数百万（r=16时，参数量降低1000倍）

质量差异的根源：
- 差微调：过拟合训练数据，泛化能力差
- 好微调：在保持通用能力的同时，提升领域能力
```

**关键洞察**：微调的效果不取决于"训练数据量"，而取决于**任务分布与预训练分布的匹配度**以及**参数更新策略的合理性**。

## 理论基础：为什么微调能提升领域性能

### 1. 预训练模型的知识表示

#### 神经网络的层次化特征

```python
"""
Transformer模型的层次化知识表示：

层1-6（底层）：语法和局部模式
- token级别的特征
- 词性、句法结构
- 代码中的关键字、标识符

层7-18（中层）：语义和上下文
- 短语和句子级别的含义
- 实体关系、指代消解
- 代码中的函数语义、变量作用域

层19-32（高层）：抽象推理和任务模式
- 篇章级别的理解
- 逻辑推理、常识推理
- 代码中的架构模式、算法逻辑

微调的作用：
- 底层：通常不需要大调整（语法通用）
- 中层：轻度调整（领域术语适配）
- 高层：重点调整（任务模式适配）

数学解释：
设模型有L层，第l层的参数为θ_l

预训练后的参数：θ_pre = [θ_1, θ_2, ..., θ_L]

微调后的参数：θ_fine = [θ_1 + Δθ_1, θ_2 + Δθ_2, ..., θ_L + Δθ_L]

其中 ||Δθ_l|| 随着l增加而增大（高层变化更大）

PEFT的核心假设：
Δθ_l 存在于低秩子空间中，即 Δθ_l = A_l × B_l
其中 rank(A_l × B_l) = r << dim(θ_l)
"""
```

#### 参数空间的低维结构

```python
"""
参数空间的低维结构假设：

假设1：Intrinsic Dimensionality（Aghajanyan et al., 2021）
- 预训练模型的有效维度d* << 实际维度d
- 对于GPT-3 175B，d* ≈ 10^4（而不是175B）
- 说明只需要在很低维的子空间中搜索

假设2：Optimal Subspace（Li et al., 2018）
- 存在低维子空间S，dim(S) = d_intrinsic
- 在S中优化可以达到全量微调90%+的效果
- PEFT就是寻找这个子空间的方法

假设3：Over-parameterization Benefits（Neyshabur et al., 2019）
- 过参数化使得优化更容易（更多局部最小值）
- 但也意味着不需要更新所有参数
- 随机子网络就能达到好效果（ Lottery Ticket Hypothesis）

LoRA的数学基础：
对于权重矩阵W ∈ R^{d×k}，更新可以表示为：
W' = W + ΔW = W + A × B

其中：
- A ∈ R^{d×r}，B ∈ R^{r×k}
- r << min(d, k) 是低秩维度
- 通常 r = 8, 16, 32, 64

参数量对比：
- 全量更新：d × k
- LoRA更新：d × r + r × k = r × (d + k)
- 节省比例：(d × k) / [r × (d + k)] ≈ min(d,k) / (2r)

例如：d=4096, k=4096, r=16
- 全量：16,777,216
- LoRA：131,072
- 节省：128倍
"""
```

### 2. 领域适配的信息论解释

```python
"""
领域适配的信息论视角：

预训练模型学到的通用分布：P_general(x, y)
目标领域分布：P_task(x, y)

两个分布的差异：
KL(P_task || P_general) = E_{(x,y)~P_task}[log P_task(x,y) / P_general(x,y)]

微调的目标：
minimize KL(P_task || P_fine)

其中P_fine是微调后模型的分布

数据效率分析：

设需要N_full个样本进行全量微调达到目标性能
设需要N_peft个样本进行PEFT达到相同性能

通常：N_peft ≈ N_full 或 N_peft < N_full

原因：
- PEFT减少了过拟合风险（参数少）
- 预训练知识被保留（大部分参数冻结）
- 更容易优化（低维空间）

最优数据量：
- 简单任务（分类、匹配）：100-1000条
- 中等任务（生成、摘要）：1000-10000条
- 复杂任务（推理、代码）：10000-100000条
- 经验法则：当验证集损失不再下降时停止收集数据
"""
```

### 3. 梯度更新的几何解释

```python
"""
梯度更新的几何解释：

损失函数景观（Loss Landscape）：
L(θ) = E_{(x,y)~D_task}[loss(f_θ(x), y)]

全量微调的梯度：
∇_θ L = [∂L/∂θ_1, ∂L/∂θ_2, ..., ∂L/∂θ_d]

更新规则：
θ_{t+1} = θ_t - η × ∇_θ L

问题：
- 高维空间中的梯度方向可能相互冲突
- 某些参数更新会损害预训练知识
- 需要很小的学习率（通常2e-5到5e-5）

LoRA的梯度：
∇_A L = (∂L/∂W') × B^T
∇_B L = A^T × (∂L/∂W')

其中 W' = W + A×B

优势：
- 只在低维子空间中更新
- 保留了预训练权重W
- 可以合并（merge）到原模型，无推理开销

梯度冲突分析：
设有两个任务task1和task2

全量微调的梯度：
∇_θ L_total = ∇_θ L_1 + ∇_θ L_2

如果∇_θ L_1 和 ∇_θ L_2方向相反（冲突）：
- 全量微调会损害其中一个任务
- 需要多任务学习技巧

LoRA的梯度：
∇_A L_total = ∇_A L_1 + ∇_A L_2

由于A和B是任务特定的：
- 可以为每个任务学习独立的A和B
- 切换任务只需切换A和B
- 避免了梯度冲突
"""
```

## 演进史：从全量微调到参数高效训练的四个时代

### 第一阶段：全量微调时代（2018-2020）

```python
"""
全量微调时代（BERT/GPT-1时期）：

技术特点：
- 模型较小（BERT-base: 110M, GPT-1: 117M）
- 全量微调所有参数
- 需要大量显存和计算资源

典型流程：
1. 加载预训练模型
2. 添加任务头（Classification Head）
3. 全量训练所有参数
4. 学习率：2e-5 ~ 5e-5
5. 训练轮数：3-5 epochs

局限性：
1. 显存需求高
   - BERT-base: ~4GB
   - BERT-large: ~12GB
   - 对于当时的GPU（V100 16GB）还可以接受

2. 灾难性遗忘
   - 微调后通用能力下降
   - 只在特定任务上好

3. 存储成本高
   - 每个任务需要保存完整的模型副本
   - 100个任务 = 100 × 模型大小

数学表达：
θ_fine = argmin_θ Loss(θ, D_task)
其中θ包含所有参数
"""
```

### 第二阶段：特征提取与适配器（2019-2021）

```python
"""
适配器时代（Adapter Layers）：

核心思想：
- 冻结预训练模型的大部分参数
- 在Transformer层之间插入小的适配器模块
- 只训练适配器参数

适配器结构：
```
输入 x ──→ [Transformer Layer] ──→ 适配器 ──→ 输出
                    ↑
                 冻结参数
                    
适配器内部：
x ──→ Down-project(d→r) ──→ Nonlinear ──→ Up-project(r→d) ──→ x'
       (Linear)            (ReLU/GELU)      (Linear)
```

参数量：
- 每个适配器：2 × d × r（down + up）
- 12层BERT：24 × d × r
- 如果d=768, r=64：约1.1M参数（vs 原模型110M，节省99%）

代表工作：
- Adapter-BERT（Houlsby et al., 2019）
- MAD-X（Pfeiffer et al., 2020）

优势：
- 参数高效（节省99%）
- 多任务切换方便（换适配器即可）
- 避免灾难性遗忘

劣势：
- 推理有额外开销（增加了层数）
- 适配器设计需要经验
- 效果略逊于全量微调

数学表达：
h' = h + f_adapter(h)
其中f_adapter(h) = W_up × σ(W_down × h)
只训练W_up和W_down
"""
```

### 第三阶段：提示微调与前缀微调（2021-2022）

```python
"""
提示微调时代：

核心思想：
- 不修改模型参数
- 在输入中加入可训练的"软提示"（Soft Prompts）
- 通过优化提示来适配任务

两种主要方法：

1. Prefix Tuning（Li & Liang, 2021）
   - 在每层Transformer前添加可训练前缀
   - 前缀维度：prefix_length × hidden_size
   - 只训练前缀参数

   ```
   原始输入：[CLS] 今天天气很好 [SEP]
   前缀输入：[P1][P2]...[Pk] [CLS] 今天天气很好 [SEP]
                        ↑
                     可训练
   ```

2. Prompt Tuning（Lester et al., 2021）
   - 只在输入层添加软提示
   - 更简单，但效果略差
   - 提示长度通常10-100个token

参数量：
- Prefix Tuning：L × prefix_length × d（L是层数）
- Prompt Tuning：prompt_length × d
- 如果L=12, prefix_length=20, d=768：约184K参数

优势：
- 极少的参数量
- 完全保留预训练模型
- 多任务切换方便

劣势：
- 效果不如LoRA稳定
- 对长序列任务效果差
- 难以处理复杂任务

数学表达：
对于Prefix Tuning：
[h_1, ..., h_prefix, h_input, ...] = Transformer([P, X])
其中P是可训练的前缀参数
"""
```

### 第四阶段：LoRA与参数高效微调（2022-2026）

```python
"""
LoRA时代（Hu et al., 2022）及后续发展：

核心思想：
- 冻结预训练权重W
- 引入低秩分解W' = W + A×B
- 只训练A和B

LoRA的优势：
1. 无推理开销
   - 训练时：W' = W + A×B
   - 推理时：可以合并W' = W + A×B（一次性计算）
   - 推理速度与原模型相同

2. 参数高效
   - r=16时，参数量降低100倍以上
   - 存储成本低（一个任务只需存A和B）

3. 效果接近全量微调
   - 在许多任务上达到全量微调95%+的效果
   - 特别是在大模型（>10B）上

LoRA的演进：

1. AdaLoRA（2023）
   - 自适应秩分配
   - 重要的矩阵分配更高的秩
   - 动态调整r值

2. QLoRA（2023）
   - 4-bit量化 + LoRA
   - 在消费级GPU上微调65B模型
   - 显存需求降低10倍以上

3. DoRA（2024）
   - 权重分解低秩适配
   - 将权重分解为幅度和方向
   - 方向部分用LoRA更新
   - 更稳定，效果更好

4. LoRA-FA（2024）
   - LoRA with Frozen Attention
   - 冻结Attention，只训练MLP
   - 进一步减少参数

5. PiSSA（2025）
   - Principal Singular values and Singular vectors Adaptation
   - 使用主奇异值分解初始化LoRA
   - 更快收敛，更好效果

2026年现状：
- LoRA是工业界标准
- QLoRA让个人开发者也能微调大模型
- 多LoRA部署成为标配（一个基础模型 + 多个LoRA适配器）
- LoRA与MoE（混合专家）结合
"""
```

## 深度解析：PEFT核心技术与算法原理

### 1. LoRA的数学原理与实现

#### 低秩适配的数学推导

```python
"""
LoRA的完整数学推导：

问题设定：
对于预训练权重矩阵 W_0 ∈ R^{d×k}，微调时得到W = W_0 + ΔW

约束优化问题：
minimize Loss(W_0 + ΔW, D_task)
subject to rank(ΔW) ≤ r

这是一个低秩约束优化问题。

根据Eckart-Young-Mirsky定理：
最优的秩r近似可以通过SVD获得：
ΔW ≈ U_r × Σ_r × V_r^T

其中U_r ∈ R^{d×r}, Σ_r ∈ R^{r×r}, V_r ∈ R^{k×r}

LoRA的简化：
令 A = U_r × Σ_r^{1/2} ∈ R^{d×r}
令 B = Σ_r^{1/2} × V_r^T ∈ R^{r×k}

则 ΔW ≈ A × B

前向传播：
h = W_0 × x + ΔW × x
  = W_0 × x + A × B × x

反向传播：
∂L/∂A = (∂L/∂h) × (B × x)^T
∂L/∂B = A^T × (∂L/∂h) × x^T

初始化策略：
- A：随机高斯初始化（标准差与输入维度相关）
- B：零初始化

为什么B初始化为零？
- 保证训练开始时ΔW = A × B = 0
- 即W' = W_0，输出与预训练模型相同
- 避免训练初期的性能下降

缩放因子：
h = W_0 × x + (α/r) × A × B × x

其中α是超参数（通常α=2r）：
- α/r控制LoRA的"学习率"
- 当改变r时，保持α/r不变可以稳定训练
- 例如r=8, α=16 → α/r=2
      r=16, α=32 → α/r=2
"""

class LoRALayer:
    """LoRA层的NumPy实现"""
    
    def __init__(self, in_features: int, out_features: int, rank: int = 8, alpha: int = 16):
        self.rank = rank
        self.alpha = alpha
        self.scaling = alpha / rank
        
        # 预训练权重（冻结）
        self.W = np.random.randn(out_features, in_features) * 0.02
        self.W.requires_grad = False  # 冻结
        
        # LoRA参数（可训练）
        self.A = np.random.randn(out_features, rank) * 0.01
        self.B = np.zeros((rank, in_features))
        
        self.A.requires_grad = True
        self.B.requires_grad = True
    
    def forward(self, x: np.ndarray) -> np.ndarray:
        """前向传播"""
        # 原始输出
        original = x @ self.W.T
        
        # LoRA分支
        lora = x @ (self.A @ self.B).T * self.scaling
        
        return original + lora
    
    def merge(self) -> np.ndarray:
        """合并LoRA到原权重（用于推理）"""
        return self.W + self.scaling * (self.A @ self.B)
    
    def get_trainable_params(self) -> int:
        """获取可训练参数量"""
        return self.A.size + self.B.size
    
    def get_total_params(self) -> int:
        """获取总参数量"""
        return self.W.size + self.A.size + self.B.size
```

#### LoRA在Transformer中的应用

```python
"""
Transformer中的LoRA应用：

Transformer层包含以下权重矩阵：
1. Self-Attention:
   - W_q (Query): d×d
   - W_k (Key): d×d
   - W_v (Value): d×d
   - W_o (Output): d×d

2. Feed-Forward Network (FFN):
   - W_gate (Gating): d×4d  (for Gated MLP)
   - W_up (Up-project): d×4d
   - W_down (Down-project): 4d×d

LoRA应用策略：

策略1：只应用于Attention（标准做法）
- target_modules = ["q_proj", "k_proj", "v_proj", "o_proj"]
- 参数量：4 × 2 × d × r
- 效果：通常足够好

策略2：应用于Attention + FFN
- target_modules = ["q_proj", "k_proj", "v_proj", "o_proj", 
                   "gate_proj", "up_proj", "down_proj"]
- 参数量：7 × 2 × d × r（FFN更多）
- 效果：更好，但参数更多

策略3：只应用于关键矩阵（实验性）
- target_modules = ["v_proj", "o_proj"]
- 参数量：2 × 2 × d × r
- 效果：可能足够，需要实验验证

最优配置（经验值）：
- 小模型（<7B）：r=16, target=attention+ffn
- 大模型（7B-70B）：r=8或16, target=attention
- 超大模型（>70B）：r=8, target=attention

不同模型的模块名：
- LLaMA/Qwen: q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj, down_proj
- BERT: query, key, value, dense
- T5: q, k, v, o, wi, wo
- GPT-2: c_attn, c_proj, c_fc
"""

class TransformerLoRAConfig:
    """Transformer LoRA配置"""
    
    # 不同模型的模块名映射
    MODEL_MAPPING = {
        'llama': {
            'attention': ['q_proj', 'k_proj', 'v_proj', 'o_proj'],
            'ffn': ['gate_proj', 'up_proj', 'down_proj']
        },
        'qwen': {
            'attention': ['q_proj', 'k_proj', 'v_proj', 'o_proj'],
            'ffn': ['gate_proj', 'up_proj', 'down_proj']
        },
        'glm': {
            'attention': ['query_key_value', 'dense'],
            'ffn': ['dense_h_to_4h', 'dense_4h_to_h']
        },
        'bert': {
            'attention': ['query', 'key', 'value', 'dense'],
            'ffn': ['intermediate.dense', 'output.dense']
        }
    }
    
    def __init__(self, model_type: str = 'llama', rank: int = 16, alpha: int = 32):
        self.model_type = model_type
        self.rank = rank
        self.alpha = alpha
        self.target_modules = self.MODEL_MAPPING[model_type]['attention']
    
    def get_lora_config(self) -> dict:
        """获取LoRA配置"""
        return {
            'r': self.rank,
            'lora_alpha': self.alpha,
            'target_modules': self.target_modules,
            'lora_dropout': 0.05,
            'bias': 'none',
            'task_type': 'CAUSAL_LM'
        }
    
    def estimate_parameters(self, hidden_size: int, num_layers: int) -> dict:
        """估算参数量"""
        num_targets = len(self.target_modules)
        
        # 每个target的LoRA参数量: 2 × hidden_size × rank
        params_per_layer = num_targets * 2 * hidden_size * self.rank
        total_params = params_per_layer * num_layers
        
        return {
            'per_layer': params_per_layer,
            'total': total_params,
            'total_mb': total_params * 4 / (1024 ** 2),  # FP32
            'percentage': total_params / (hidden_size ** 2 * num_layers * 12) * 100
        }
```

### 2. QLoRA：量化+LoRA

#### 4-bit量化的数学原理

```python
"""
QLoRA的核心：4-bit Normal Float Quantization

量化目标：
将FP16/BF16权重W ∈ R^d 量化为4-bit整数Q ∈ {0, 1, ..., 15}^d

量化公式：
W ≈ scale × (Q - zero_point)

Normal Float（NF4）量化：
1. 假设权重服从正态分布N(0, σ^2)
2. 将正态分布分成16个等概率区间
3. 每个区间用一个值表示（该区间的期望值）
4. 量化值就是这些期望值

NF4量化步骤：
1. 计算权重的分位数：q_i = Φ^{-1}(i/16)，i=0,1,...,16
   其中Φ是正态分布CDF

2. 计算量化值：v_i = E[X | q_i ≤ X < q_{i+1}]
   即第i个区间的期望值

3. 量化：
   Q = argmin_i |W - v_i|

4. 反量化：
   W_dequant = v_Q

优势：
- 对于正态分布数据，NF4比均匀量化（INT4）更好
- 信息损失最小
- 适合神经网络权重（通常近似正态分布）

双重量化（Double Quantization）：
为了进一步减少存储，对量化常数也进行量化：
- 第一级：W → FP4/INT4 + scale(FP16)
- 第二级：scale(FP16) → FP8 + scale2(FP16)

分页优化器（Paged Optimizers）：
使用NVIDIA统一内存，当GPU显存不足时自动将优化器状态分页到CPU内存。

内存对比（以7B模型为例）：

训练模式          模型权重    梯度      优化器状态   总计
FP32训练          28 GB      28 GB     56 GB       112 GB
FP16混合精度       14 GB      14 GB     56 GB       84 GB
INT8量化           7 GB       14 GB     56 GB       77 GB
LoRA (FP16)        14 GB      ~0.1 GB   ~0.2 GB     14.3 GB
QLoRA (4-bit)      3.5 GB     ~0.1 GB   ~0.2 GB     3.8 GB

QLoRA可以在24GB消费级GPU（RTX 3090/4090）上微调65B模型！
"""

class QLoRAQuantizer:
    """QLoRA量化器演示"""
    
    def __init__(self, bits: int = 4, group_size: int = 64):
        self.bits = bits
        self.num_levels = 2 ** bits
        self.group_size = group_size
    
    def quantize(self, weights: np.ndarray) -> tuple:
        """
        量化权重
        
        返回：(quantized_weights, scales, zeros)
        """
        original_shape = weights.shape
        weights_flat = weights.flatten()
        
        # 分组
        num_groups = len(weights_flat) // self.group_size
        weights_grouped = weights_flat[:num_groups * self.group_size].reshape(
            num_groups, self.group_size
        )
        
        quantized = []
        scales = []
        zeros = []
        
        for group in weights_grouped:
            # 计算scale和zero point
            w_min = group.min()
            w_max = group.max()
            
            scale = (w_max - w_min) / (self.num_levels - 1)
            zero_point = -w_min / scale if scale != 0 else 0
            
            # 量化
            q = np.round((group - w_min) / scale).clip(0, self.num_levels - 1)
            
            quantized.extend(q.astype(np.uint8))
            scales.append(scale)
            zeros.append(zero_point)
        
        return (
            np.array(quantized).reshape(original_shape),
            np.array(scales),
            np.array(zeros)
        )
    
    def dequantize(self, quantized: np.ndarray, scales: np.ndarray, 
                   zeros: np.ndarray) -> np.ndarray:
        """反量化"""
        num_groups = len(quantized) // self.group_size
        quantized_grouped = quantized.reshape(num_groups, self.group_size)
        
        dequantized = []
        for i, group in enumerate(quantized_grouped):
            scale = scales[i]
            zero = zeros[i]
            w = (group.astype(np.float32) - zero) * scale
            dequantized.extend(w)
        
        return np.array(dequantized)
    
    def memory_savings(self, original_params: int) -> dict:
        """计算内存节省"""
        original_bytes = original_params * 4  # FP32
        quantized_bytes = original_params * 0.5  # 4-bit = 0.5 byte
        
        # 加上scale和zero的存储
        num_groups = original_params / self.group_size
        overhead = num_groups * 2 * 4  # FP32 for scale and zero
        
        total_bytes = quantized_bytes + overhead
        
        return {
            'original_mb': original_bytes / (1024 ** 2),
            'quantized_mb': total_bytes / (1024 ** 2),
            'savings_ratio': original_bytes / total_bytes
        }
```

### 3. 高级PEFT技术

#### AdaLoRA：自适应秩分配

```python
"""
AdaLoRA（Zhang et al., 2023）：

核心思想：
- 不同权重矩阵的重要性不同
- 重要的矩阵分配更高的秩
- 不重要的矩阵分配更低的秩（甚至为0）

数学公式：
对于每个权重矩阵W_i，分配秩r_i

目标函数：
minimize Loss(θ) + λ × Σ_i r_i

约束：
Σ_i r_i ≤ R_total（总秩预算）

重要性度量：
Saliency = ||∂L/∂W_i||_F × ||W_i||_F

训练过程：
1. 初始时所有矩阵使用相同的秩
2. 每T步计算每个矩阵的重要性
3. 将秩从低重要性矩阵转移到高重要性矩阵
4. 使用奇异值分解（SVD）进行秩的裁剪和扩展

优势：
- 自动找到最优的秩分配
- 总参数量固定，但分配更合理
- 通常比固定秩的LoRA效果好

配置：
- target_r: 目标平均秩（如8）
- init_r: 初始秩（如12）
- tinit: 开始剪枝的步数（如0）
- tfinal: 结束剪枝的步数（如总步数）
- deltaT: 剪枝频率（如10步）
- beta1, beta2: 重要性平滑系数
"""

class AdaLoRAConfig:
    """AdaLoRA配置"""
    
    def __init__(self):
        self.target_r = 8
        self.init_r = 12
        self.lora_alpha = 32
        self.tinit = 0
        self.tfinal = 1000
        self.deltaT = 10
        self.beta1 = 0.85
        self.beta2 = 0.85
        self.orth_reg_weight = 0.5
```

#### DoRA：权重分解低秩适配

```python
"""
DoRA（Liu et al., 2024）：Weight-Decomposed Low-Rank Adaptation

核心思想：
- 将权重分解为幅度（magnitude）和方向（direction）
- W = m × (V / ||V||)
- 只更新方向部分（用LoRA）
- 幅度部分可以微调或冻结

数学公式：
W' = W + ΔW

分解：
W = ||W||_c × (W / ||W||_c)

其中：
- ||W||_c = column-wise norm（列范数）
- W / ||W||_c = 方向矩阵

DoRA更新：
W' = ||W||_c × (W + ΔW) / ||W + ΔW||_c

其中ΔW = A × B（LoRA）

优势：
1. 更稳定
   - 幅度和方向解耦
   - 避免梯度爆炸或消失

2. 更好的学习能力
   - 方向更新更灵活
   - 保持预训练的知识结构

3. 实验效果
   - 在多种任务上优于LoRA
   - 特别是在需要较大改变的任务上

实现：
```python
class DoRALayer(nn.Module):
    def __init__(self, in_features, out_features, rank=8):
        super().__init__()
        self.weight = nn.Parameter(torch.randn(out_features, in_features))
        self.magnitude = nn.Parameter(torch.ones(out_features, 1))
        
        # LoRA参数
        self.lora_A = nn.Parameter(torch.randn(out_features, rank))
        self.lora_B = nn.Parameter(torch.zeros(rank, in_features))
    
    def forward(self, x):
        # 计算方向
        direction = self.weight + self.lora_A @ self.lora_B
        
        # 归一化
        direction = direction / direction.norm(dim=1, keepdim=True)
        
        # 应用幅度
        weight = self.magnitude * direction
        
        return x @ weight.T
```
"""

```python
"""
模型质量评估指标：

1. 领域任务性能：
   - 与全量微调的差距
   - 与基座模型的提升
   - 典型差距：LoRA达到全量95%+

   - 训练收敛稳定性

评估方法：

方法1：自动评测
- 使用领域benchmark
- 计算准确率、F1、BLEU等
- 与基座模型和全量微调对比

方法2：人工评估
- 专家评分
- A/B测试
- 用户满意度调查

方法3：实际应用测试
- 在线A/B测试
- 业务指标对比
- 错误案例分析

评估案例：

代码生成任务（HumanEval）：
- 基座模型（DeepSeek-Coder-6.7B）： pass@1 = 48%
- 全量微调：pass@1 = 65%
- LoRA（r=16）：pass@1 = 62%
- QLoRA（r=16）：pass@1 = 60%
- Prefix Tuning：pass@1 = 55%

结论：
- LoRA达到全量微调的95%
- QLoRA达到全量微调的92%
- Prefix Tuning达到全量微调的85%
"""

class ModelQualityEvaluator:
    """模型质量评估器"""
    
    def __init__(self):
        self.benchmarks = {}
    
    def evaluate(self, model, test_dataset: list, metrics: list) -> dict:
        """评估模型质量"""
        results = {}
        
        for metric in metrics:
            if metric == 'accuracy':
                results['accuracy'] = self._evaluate_accuracy(model, test_dataset)
            elif metric == 'bleu':
                results['bleu'] = self._evaluate_bleu(model, test_dataset)
            elif metric == 'perplexity':
                results['perplexity'] = self._evaluate_perplexity(model, test_dataset)
        
        return results
    
    def _evaluate_accuracy(self, model, test_dataset: list) -> float:
        """评估准确率"""
        correct = 0
        total = len(test_dataset)
        
        for example in test_dataset:
            prediction = self._generate(model, example['input'])
            if prediction.strip() == example['output'].strip():
                correct += 1
        
        return correct / total if total > 0 else 0
    
    def _evaluate_bleu(self, model, test_dataset: list) -> float:
        """评估BLEU分数"""
        from nltk.translate.bleu_score import sentence_bleu
        
        scores = []
        for example in test_dataset:
            prediction = self._generate(model, example['input'])
            reference = example['output'].split()
            hypothesis = prediction.split()
            
            score = sentence_bleu([reference], hypothesis)
            scores.append(score)
        
        return sum(scores) / len(scores) if scores else 0
    
    def _evaluate_perplexity(self, model, test_dataset: list) -> float:
        """评估困惑度"""
        # 简化的困惑度计算
        total_loss = 0
        total_tokens = 0
        
        for example in test_dataset:
            # 实际应计算负对数似然
            loss = 2.0  # 示例值
            tokens = len(example['output'].split())
            
            total_loss += loss * tokens
            total_tokens += tokens
        
        avg_loss = total_loss / total_tokens if total_tokens > 0 else 0
        perplexity = np.exp(avg_loss)
        
        return perplexity
    
    def _generate(self, model, input_text: str) -> str:
        """生成输出"""
        return f"Generated: {input_text}"

## 面试题与参考答案

### Q1：LoRA的核心思想是什么？为什么有效？

**参考答案**：

LoRA（Low-Rank Adaptation）的核心思想是：**冻结预训练权重W，通过低秩分解W' = W + A×B来微调模型**。

为什么有效：

1. **低维子空间假设**：
   预训练模型的参数更新ΔW存在一个低维的内在维度（Intrinsic Dimensionality）。Aghajanyan等人（2021）发现，对于大模型，有效维度d*远小于实际维度d。LoRA通过低秩分解（rank r << d）恰好在这个低维子空间中进行优化。

2. **预训练知识的保留**：
   冻结W保留了预训练学到的通用知识。只有A和B被更新，且A×B的参数量只有W的0.1%-1%，大大减少了过拟合风险。

3. **优化稳定性**：
   B初始化为零，保证训练开始时W' = W（即输出不变）。这样模型从预训练的良好状态开始优化，避免了训练初期的性能下降。

4. **无推理开销**：
   训练时W' = W + A×B，推理时可以预先合并W' = W + A×B，推理速度与原模型完全相同。

数学上，对于权重矩阵W ∈ R^{d×k}，LoRA使用：
```
W' = W + (α/r) × A × B
```
其中A ∈ R^{d×r}, B ∈ R^{r×k}，参数量从d×k降到r×(d+k)。

当r=16, d=k=4096时，参数量降低约128倍。

### Q2：QLoRA和LoRA的区别是什么？QLoRA如何在消费级GPU上训练大模型？

**参考答案**：

**QLoRA和LoRA的区别**：

1. **基础模型精度**：
   - LoRA：基础模型使用FP16/BF16
   - QLoRA：基础模型使用4-bit量化（Normal Float 4）

2. **显存需求**：
   - LoRA（7B模型）：~20GB显存
   - QLoRA（7B模型）：~6GB显存
   - QLoRA（65B模型）：~40GB显存（可在单卡A100上训练）

3. **训练稳定性**：
   - LoRA：更稳定，梯度精度高
   - QLoRA：量化引入噪声，但使用分页优化器和双重量化来缓解

**QLoRA在消费级GPU上训练大模型的技术**：

1. **4-bit Normal Float量化**：
   - 将FP16权重压缩到4-bit
   - 使用正态分布的分位数进行非均匀量化
   - 信息损失比均匀量化（INT4）更小

2. **双重量化（Double Quantization）**：
   - 对量化常数（scale）再进行量化
   - 进一步减少显存占用

3. **分页优化器（Paged Optimizers）**：
   - 使用NVIDIA统一内存
   - 当GPU显存不足时，自动将优化器状态分页到CPU内存
   - 避免OOM错误

4. **LoRA适配器**：
   - 只训练LoRA参数（A和B）
   - LoRA参数保持FP16精度
   - 反向传播时，梯度计算使用反量化后的FP16权重

**显存对比**（以7B模型为例）：
- FP32训练：112GB
- FP16 + LoRA：20GB
- 4-bit + QLoRA：6GB
- 节省：约18倍

### Q3：如何选择LoRA的秩r？

**参考答案**：

选择LoRA秩r的原则：

1. **任务复杂度**：
   - 简单任务（分类、匹配）：r=4-8
   - 中等任务（生成、摘要）：r=8-16
   - 复杂任务（代码、推理）：r=16-64

2. **模型规模**：
   - 小模型（<7B）：r=8-16
   - 大模型（7B-70B）：r=8-16（大模型本身表达能力强，不需要太大的r）
   - 超大模型（>70B）：r=8

3. **数据量**：
   - 小数据（<1K）：r=4-8（避免过拟合）
   - 中数据（1K-10K）：r=8-16
   - 大数据（>10K）：r=16-32

4. **实验方法**：
   - 从r=8开始训练
   - 评估验证集性能
   - 如果效果差，尝试r=16或32
   - 如果过拟合，减少r

5. **自适应方法（AdaLoRA）**：
   - 自动为不同矩阵分配不同的秩
   - 重要的矩阵分配更高的秩
   - 避免手动调参

经验法则：
- 对于大多数任务，r=16是一个好的起点
- r > 64通常没有必要（收益递减）
- r < 4通常表达能力不足

### Q4：微调时如何避免灾难性遗忘？

**参考答案**：

灾难性遗忘（Catastrophic Forgetting）是指模型在微调后忘记预训练学到的知识。解决方法：

1. **LoRA/QLoRA（参数高效微调）**：
   - 冻结大部分预训练参数
   - 只更新少量LoRA参数
   - 预训练知识被保留在冻结的权重中
   - 这是最有效的方法

2. **混合数据训练**：
   - 将领域数据和通用数据混合（比例如9:1或8:2）
   - 通用数据帮助保持通用能力
   - 需要准备高质量的通用数据样本

3. **正则化方法**：
   - L2正则化：惩罚参数偏离预训练值
   - EWC（Elastic Weight Consolidation）：根据参数重要性加权惩罚
   - 公式：Loss = Loss_task + λ × Σ F_i × (θ_i - θ*_i)^2
   - 其中F_i是Fisher信息矩阵，衡量参数重要性

4. **知识蒸馏**：
   - 使用预训练模型作为教师模型
   - 微调模型同时学习领域数据和教师模型的输出
   - 保持与预训练模型的行为一致

5. **回放机制**：
   - 保留一部分预训练数据
   - 微调时定期回放这些数据
   - 类似人类记忆的"复习"

6. **多任务学习**：
   - 同时训练多个任务
   - 任务间共享表示
   - 避免单一任务的过度优化

**推荐策略**：
- 首选：LoRA（天然避免遗忘）+ 少量通用数据
- 次选：全量微调 + EWC + 混合数据
- 避免：全量微调 + 纯领域数据（遗忘最严重）

### Q5：如何评估微调后模型的效果？

**参考答案**：

微调后模型的评估需要从多个维度进行：

1. **领域任务性能**：
   - 使用领域benchmark测试
   - 与基座模型对比（提升幅度）
   - 与全量微调对比（差距）
   - 指标：准确率、F1、BLEU、ROUGE等

2. **通用能力保持**：
   - 通用问答能力（如MMLU、C-Eval）
   - 安全性（是否更容易产生有害输出）
   - 幻觉率（是否更容易编造信息）

3. **稳定性**：
   - 不同随机种子的结果一致性
   - 超参数敏感度
   - 训练曲线平滑度

4. **实际应用测试**：
   - 在线A/B测试
   - 用户满意度调查
   - 业务指标（如转化率、留存率）

**评估流程**：
```
1. 自动评测
   - 领域benchmark（如HumanEval用于代码）
   - 通用benchmark（如MMLU）
   - 计算定量指标

2. 人工评估
   - 抽样100-500个案例
   - 专家评分（1-5分）
   - 维度：准确性、完整性、安全性、可用性

3. 对比分析
   - 基座模型 vs 微调模型
   - 错误案例分析（bad cases）
   - 提升和退化分析

4. 在线测试
   - 小流量A/B测试（5%-10%）
   - 监控用户反馈
   - 逐步扩大流量
```

### Q6：2026年模型微调的发展趋势是什么？

**参考答案**：

2026年模型微调的发展趋势：

1. **更高效的PEFT方法**：
   - DoRA（权重分解）成为新标准
   - PiSSA（主奇异值适配）提升收敛速度
   - 自适应秩分配（AdaLoRA）普及

2. **多模态微调**：
   - 文本+图像+代码的联合微调
   - GLM-5、Gemini 2.0支持多模态PEFT
   - 跨模态知识迁移

3. **长上下文微调**：
   - 支持1M+上下文的微调
   - Kimi K2.6、Claude 4的长上下文PEFT
   - 适用于文档分析、代码库理解

4. **联邦微调**：
   - 数据不出域的分布式微调
   - 隐私保护（差分隐私、同态加密）
   - 适用于金融、医疗等敏感领域

5. **自动化微调**：
   - AutoPEFT：自动选择最佳PEFT方法
   - 超参数自动优化（贝叶斯优化、进化算法）
   - 一键微调平台（如Hugging Face AutoTrain）

6. **模型即服务（MaaS）**：
   - 云端的微调API
   - 用户只需提供数据
   - 自动完成训练、评估、部署

7. **开源生态成熟**：
   - LLaMA-Factory、Axolotl等工具成熟
   - 一键微调脚本
   - 社区共享的LoRA适配器（Hugging Face LoRA Hub）
