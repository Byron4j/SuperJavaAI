## 引言：Agentic开发的本质

Cursor 3 + Composer 2不是"更强的代码补全工具"，而是标志着AI编程从**辅助模式**进入**委托模式**的范式转移。

核心认知：

```
人机协作范式演进：

阶段1：工具使用（Tool Use）
  开发者："AI帮我补全这行代码"
  AI角色：更快的自动补全

阶段2：协作编程（Pair Programming）
  开发者："AI帮我审查这段代码"
  AI角色：结对编程伙伴

阶段3：任务委托（Task Delegation）★ 当前
  开发者："AI帮我实现这个需求"
  AI角色：可委托任务的智能体

核心转变：
┌─────────────────────────────────────────┐
│  从：人驱动，AI辅助                       │
│  到：目标驱动，AI执行，人验收             │
└─────────────────────────────────────────┘
```

**关键洞察**：Agentic开发的本质不是"AI写代码更快"，而是**开发者的角色从"实现者"转变为"定义者和验收者"**——这意味着软件工程的方法论、团队协作模式、技能要求都在发生根本性变化。

### 1. 上下文管理架构

```python
class ProjectContextManager:
    """
    Cursor 3的项目级上下文管理
    """
    
    def __init__(self, project_path):
        self.project_path = project_path
        self.index = ProjectIndex()
        self.context_window = 200000  # 200K tokens
        self.relevance_engine = RelevanceEngine()
    
    def build_project_index(self):
        """
        构建项目索引（类似代码搜索引擎）
        """
        # 1. 解析所有文件
        files = self.scan_project(self.project_path)
        
        for file_path in files:
            # AST解析
            ast = self.parse_file(file_path)
            
            # 提取符号定义
            symbols = self.extract_symbols(ast)
            
            # 提取文档和注释
            docs = self.extract_documentation(ast)
            
            # 计算嵌入向量
            embedding = self.compute_embedding(
                code=read_file(file_path),
                symbols=symbols,
                docs=docs
            )
            
            # 存入索引
            self.index.add(Document(
                path=file_path,
                symbols=symbols,
                embedding=embedding,
                last_modified=get_mtime(file_path)
            ))
    
    def get_relevant_context(self, cursor_position, query=None):
        """
        获取与当前位置相关的上下文
        """
        # 1. 当前文件上下文
        current_file = self.get_current_file()
        nearby_code = current_file.get_surrounding_lines(cursor_position, radius=50)
        
        # 2. 相关定义
        symbol_under_cursor = self.get_symbol_at(cursor_position)
        related_definitions = self.index.find_definitions(symbol_under_cursor)
        
        # 3. 相关引用
        related_references = self.index.find_references(symbol_under_cursor)
        
        # 4. 语义相似代码（基于query或当前代码）
        search_query = query or nearby_code
        semantic_matches = self.index.semantic_search(
            query=search_query,
            top_k=10
        )
        
        # 5. 最近修改的文件
        recent_files = self.index.get_recently_modified(hours=24, top_k=5)
        
        # 6. 组装上下文（按优先级排序，填满context window）
        context_parts = []
        remaining_tokens = self.context_window
        
        priority_queue = [
            (100, nearby_code, "当前代码"),
            (90, related_definitions, "相关定义"),
            (80, related_references, "相关引用"),
            (70, semantic_matches, "语义相似"),
            (60, recent_files, "最近修改")
        ]
        
        for priority, content, label in priority_queue:
            tokens = estimate_tokens(content)
            if tokens < remaining_tokens:
                context_parts.append(f"## {label}\n{content}")
                remaining_tokens -= tokens
            else:
                # 截断到剩余空间
                truncated = truncate_to_tokens(content, remaining_tokens)
                context_parts.append(f"## {label}\n{truncated}")
                break
        
        return "\n\n".join(context_parts)
    
    def update_index_incremental(self, changed_files):
        """
        增量更新索引（文件变更时）
        """
        for file_path in changed_files:
            # 只重新解析变更的文件
            ast = self.parse_file(file_path)
            symbols = self.extract_symbols(ast)
            embedding = self.compute_embedding(read_file(file_path))
            
            self.index.update(file_path, Document(
                path=file_path,
                symbols=symbols,
                embedding=embedding,
                last_modified=time.now()
            ))
```

### 2. Agent Mode执行循环

```python
class AgentExecutionLoop:
    """
    Composer 2的Agent模式执行循环
    """
    
    def __init__(self):
        self.tools = {
            'read_file': FileReader(),
            'write_file': FileWriter(),
            'edit_file': FileEditor(),
            'run_command': CommandRunner(),
            'search_code': CodeSearcher(),
            'list_dir': DirectoryLister()
        }
        self.safety_checker = SafetyChecker()
    
    def execute_task(self, task_description):
        """
        执行开发任务
        """
        execution_log = []
        
        # 1. 任务理解
        task_analysis = self.analyze_task(task_description)
        
        # 2. 制定计划
        plan = self.create_execution_plan(task_analysis)
        
        for step in plan.steps:
            print(f"执行步骤 {step.number}: {step.description}")
            
            # 3. 收集上下文
            context = self.gather_context(step)
            
            # 4. 生成操作
            action = self.generate_action(step, context)
            
            # 5. 安全检查
            safety_check = self.safety_checker.check(action)
            
            if not safety_check.allowed:
                # 请求用户确认
                user_decision = self.ask_user_confirmation(
                    action=action,
                    reason=safety_check.reason,
                    risk_level=safety_check.risk_level
                )
                
                if not user_decision.approved:
                    execution_log.append({
                        'step': step.number,
                        'status': 'blocked_by_user',
                        'reason': safety_check.reason
                    })
                    continue
            
            # 6. 执行操作
            try:
                result = self.execute_action(action)
                
                # 7. 验证结果
                verification = self.verify_result(step, result)
                
                if not verification.success:
                    # 自动修复
                    fix_action = self.generate_fix(verification.error)
                    result = self.execute_action(fix_action)
                    
                    verification = self.verify_result(step, result)
                    
                    if not verification.success:
                        # 需要人工介入
                        self.request_human_help(step, verification.error)
                
                execution_log.append({
                    'step': step.number,
                    'status': 'success',
                    'action': action,
                    'result': result
                })
                
            except Exception as e:
                execution_log.append({
                    'step': step.number,
                    'status': 'error',
                    'error': str(e)
                })
                
                # 尝试恢复
                recovery = self.attempt_recovery(step, e)
                if recovery.success:
                    execution_log[-1]['recovery'] = recovery
        
        # 8. 生成总结
        summary = self.generate_execution_summary(execution_log)
        
        return summary
    
    def safety_checker(self, action):
        """
        安全检查器
        """
        risks = []
        
        if action.type == 'write_file':
            # 检查是否覆盖重要文件
            if action.path in PROTECTED_FILES:
                risks.append('attempting_to_modify_protected_file')
            
            # 检查是否有备份
            if not backup_exists(action.path):
                risks.append('no_backup_available')
        
        if action.type == 'run_command':
            # 检查危险命令
            dangerous_patterns = ['rm -rf', 'dd if=', 'mkfs', 'DROP TABLE']
            for pattern in dangerous_patterns:
                if pattern in action.command:
                    risks.append(f'dangerous_command_detected: {pattern}')
        
        return SafetyResult(
            allowed=len(risks) == 0,
            risks=risks,
            risk_level='high' if risks else 'low'
        )
```

```python
class ProjectLevelUnderstanding:
    """
    Cursor 3如何理解整个项目
    """
    
    def __init__(self, project_root):
        self.root = project_root
        self.semantic_index = SemanticCodeIndex()
        self.dependency_graph = DependencyGraph()
    
    def analyze_project_structure(self):
        """
        分析项目结构
        """
        structure = {
            'modules': [],
            'entry_points': [],
            'config_files': [],
            'dependencies': {}
        }
        
        # 检测技术栈
        if os.path.exists('package.json'):
            structure['tech_stack'] = 'Node.js'
            structure['dependencies'] = self.parse_package_json()
        elif os.path.exists('pom.xml'):
            structure['tech_stack'] = 'Java/Maven'
            structure['dependencies'] = self.parse_pom_xml()
        elif os.path.exists('requirements.txt'):
            structure['tech_stack'] = 'Python'
            structure['dependencies'] = self.parse_requirements()
        
        # 检测架构模式
        if os.path.exists('src/components'):
            structure['architecture'] = 'Component-based'
        elif os.path.exists('src/controllers'):
            structure['architecture'] = 'MVC'
        
        # 查找入口点
        structure['entry_points'] = self.find_entry_points()
        
        return structure
    
    def understand_cross_file_dependencies(self, changed_file):
        """
        理解跨文件依赖（重构时关键）
        """
        # 1. 直接依赖
        direct_deps = self.dependency_graph.get_dependents(changed_file)
        
        # 2. 间接依赖（传递闭包）
        indirect_deps = set()
        queue = list(direct_deps)
        while queue:
            file = queue.pop(0)
            if file not in indirect_deps:
                indirect_deps.add(file)
                queue.extend(self.dependency_graph.get_dependents(file))
        
        # 3. 接口契约
        interfaces = self.extract_interfaces(changed_file)
        implementations = []
        for interface in interfaces:
            implementations.extend(
                self.dependency_graph.find_implementations(interface)
            )
        
        return {
            'direct_dependents': direct_deps,
            'indirect_dependents': indirect_deps,
            'implementations': implementations,
            'total_affected_files': len(direct_deps | indirect_deps | set(implementations))
        }
    
    def generate_refactoring_plan(self, target_change):
        """
        生成跨文件重构计划
        """
        impact = self.understand_cross_file_dependencies(target_change.file)
        
        plan = RefactoringPlan()
        
        # 1. 修改接口定义
        plan.add_step(ModifyInterface(
            file=target_change.file,
            changes=target_change.interface_changes
        ))
        
        # 2. 更新所有实现
        for impl_file in impact.implementations:
            plan.add_step(UpdateImplementation(
                file=impl_file,
                interface_changes=target_change.interface_changes
            ))
        
        # 3. 更新所有调用点
        for dep_file in impact.direct_dependents:
            plan.add_step(UpdateCallSites(
                file=dep_file,
                old_signature=target_change.old_signature,
                new_signature=target_change.new_signature
            ))
        
        # 4. 更新测试
        test_files = self.find_related_tests(impact.direct_dependents)
        for test_file in test_files:
            plan.add_step(UpdateTests(
                file=test_file,
                changes=target_change
            ))
        
        # 5. 验证
        plan.add_step(RunTests(
            scope='affected'
        ))
        
        return plan
```

### 2. 智能错误修复

```python
class IntelligentErrorFixing:
    """
    Composer 2的自动错误修复
    """
    
    def __init__(self):
        self.error_classifier = ErrorClassifier()
        self.fix_strategies = {
            'syntax_error': SyntaxFixer(),
            'type_error': TypeFixer(),
            'import_error': ImportFixer(),
            'test_failure': TestFailureAnalyzer(),
            'lint_error': LintFixer()
        }
    
    def auto_fix(self, error_output, project_context):
        """
        自动分析和修复错误
        """
        # 1. 解析错误信息
        errors = self.parse_errors(error_output)
        
        fixes = []
        for error in errors:
            # 2. 分类错误
            error_type = self.error_classifier.classify(error)
            
            # 3. 选择修复策略
            fixer = self.fix_strategies.get(error_type)
            
            if fixer:
                # 4. 生成修复
                fix = fixer.generate_fix(
                    error=error,
                    context=project_context
                )
                
                # 5. 验证修复
                if self.verify_fix(fix, project_context):
                    fixes.append(fix)
                else:
                    # 尝试备选修复
                    alternative_fix = fixer.generate_alternative_fix(error)
                    if self.verify_fix(alternative_fix, project_context):
                        fixes.append(alternative_fix)
        
        return fixes
    
    def parse_errors(self, output):
        """
        解析不同类型的错误输出
        """
        errors = []
        
        # 编译错误（Java/TypeScript）
        compile_pattern = r'(.*):(\d+):(\d+):\s*(error|warning):\s*(.*)'
        for match in re.finditer(compile_pattern, output):
            errors.append(CompileError(
                file=match.group(1),
                line=int(match.group(2)),
                column=int(match.group(3)),
                severity=match.group(4),
                message=match.group(5)
            ))
        
        # 测试失败
        test_pattern = r'FAILED\s+(.*?)\s+-\s+(.*)'
        for match in re.finditer(test_pattern, output):
            errors.append(TestFailure(
                test_name=match.group(1),
                failure_message=match.group(2)
            ))
        
        # Lint错误
        lint_pattern = r'(.*):(\d+):(\d+):\s*(E|W)\s*(\d+)\s*(.*)'
        for match in re.finditer(lint_pattern, output):
            errors.append(LintError(
                file=match.group(1),
                line=int(match.group(2)),
                rule_id=match.group(5),
                message=match.group(6)
            ))
        
        return errors
```

```python
class LegacyModernization:
    """
    使用Cursor 3重构遗留系统
    """
    
    def __init__(self, project_path):
        self.cursor = CursorAgent()
        self.project = ProjectLoader(project_path)
    
    def modernize_spring_boot(self, target_version="3.2"):
        """
        Spring Boot 2.x → 3.x 迁移
        """
        # 1. 分析当前状态
        analysis = self.cursor.analyze_codebase(
            instructions="识别所有Spring Boot 2.x特有的API和配置"
        )
        
        migration_tasks = []
        
        # 2. 迁移任务列表
        if analysis.has_spring_boot_2:
            migration_tasks.extend([
                "升级pom.xml依赖版本",
                "替换javax.*为jakarta.*",
                "更新Spring Security配置",
                "迁移WebMvcConfigurer",
                "更新配置文件格式",
                "替换废弃的API"
            ])
        
        # 3. 执行迁移
        for task in migration_tasks:
            result = self.cursor.execute_task(
                task=task,
                context=analysis,
                safety_level="high"  # 高安全级别，每步确认
            )
            
            if result.has_errors:
                # 自动修复
                fix_result = self.cursor.fix_errors(result.errors)
                
                if fix_result.has_remaining_errors:
                    self.request_human_help(fix_result)
        
        # 4. 验证
        verification = self.cursor.run_command("mvn clean test")
        
        if verification.returncode != 0:
            # 修复测试失败
            self.cursor.fix_test_failures(verification.output)
        
        # 5. 生成迁移文档
        migration_doc = self.cursor.generate_documentation(
            template="migration_report",
            changes=self.cursor.get_change_log()
        )
        
        return migration_doc
```

### 题目1：Agentic开发和传统AI辅助编程有什么区别？

```markdown
## 参考答案

**传统AI辅助编程（Copilot模式）**：
- 交互方式：人写代码，AI补全/建议
- 上下文：当前文件，局部理解
- 决策权：人完全控制
- 任务范围：单行/单函数
- 错误处理：人发现并修复

**Agentic开发（Cursor 3模式）**：
- 交互方式：人定义目标，AI规划并执行
- 上下文：整个项目，全局理解
- 决策权：AI自主决策，人验收
- 任务范围：跨文件、端到端功能
- 错误处理：AI自动检测并修复

**核心区别**：
1. **主动性**：辅助是被动的（等用户触发），Agent是主动的（自主规划执行）
2. **范围**：辅助是局部的，Agent是全局的
3. **责任**：辅助是人负责，Agent是AI负责执行、人负责验收
4. **交互频率**：辅助是持续微交互，Agent是阶段性交付

**类比**：
- 辅助编程 = 副驾驶：主驾驶是人，副驾驶给建议
- Agentic开发 = 自动驾驶：人设定目的地，车自己开，人监督

**适用场景**：
- 辅助：日常编码、探索性开发
- Agent：明确需求的功能实现、大规模重构、模板代码生成
```

### 题目2：如何设计一个有效的.cursorrules文件？

```markdown
## 参考答案

**核心要素**：

1. **技术栈定义**
```
项目使用：
- 后端：Spring Boot 3.2 + Java 17
- 前端：Vue 3 + TypeScript + Pinia
- 数据库：PostgreSQL 15
- 禁止：使用lombok（团队约定）
```

2. **代码风格**
```
命名规范：
- 类名：PascalCase
- 方法/变量：camelCase
- 常量：UPPER_SNAKE_CASE
- 数据库字段：snake_case

代码组织：
- 每个类不超过300行
- 方法不超过50行
- 参数不超过5个
```

3. **架构约束**
```
分层要求：
- Controller层：只做参数校验和调用Service
- Service层：包含业务逻辑，禁止直接访问Repository
- Repository层：数据访问，使用Spring Data JPA

设计模式：
- 优先使用依赖注入
- 使用Builder模式构建复杂对象
- 异常统一使用GlobalExceptionHandler处理
```

4. **安全规则**
```
安全要求：
- 所有用户输入必须校验
- SQL必须使用参数化查询
- 敏感数据必须加密存储
- JWT密钥禁止硬编码
```

5. **测试要求**
```
测试规范：
- 所有Service方法必须有单元测试
- 所有Controller必须有集成测试
- 测试覆盖率 >= 80%
- 使用JUnit 5 + Mockito
```

**设计原则**：
- 具体：避免"写干净的代码"这类模糊描述
- 可验证：规则可以被自动检查
- 优先级：关键规则（如安全）放在前面
- 更新：随项目演进定期更新

**效果评估**：
- 有cursorrules：AI生成代码风格一致性 > 90%
- 无cursorrules：一致性约 60-70%
```
