## 引言：为什么这三个模式总是同时出现

在软件工程面试中，"策略模式、模板方法模式、责任链模式"这三个行为型模式经常被同时考察。这不是巧合——它们共同解决了**算法复用与扩展**这一核心问题，但采取了完全不同的思路：

```
问题域：如何组织代码中的"行为"（算法/策略/处理逻辑）？

┌─────────────────────────────────────────────────────┐
│ 策略模式：封装算法族，让它们可以互相替换              │
├─────────────────────────────────────────────────────┤
│ 模板方法：定义算法骨架，延迟步骤到子类                 │
├─────────────────────────────────────────────────────┤
│ 责任链：解耦请求发送者与接收者，链式传递请求           │
└─────────────────────────────────────────────────────┘

共同目标：在运行时动态决定行为，而不是通过硬编码的if-else
```

本文将从**JDK源码**和**Spring框架源码**两个维度，深入剖析这三个模式的实现原理，并提供可直接落地的工业级实践方案。

## 理论基础：行为型模式的设计原则

### 1. 开闭原则（Open/Closed Principle）

这三个模式的核心价值都体现在对开闭原则的支持上：

```
传统做法（违反OCP）：大量if-else，新增类型必须修改原有代码

策略模式做法（符合OCP）：
  PaymentStrategy strategy = factory.getStrategy(type);
  strategy.pay(amount);
  // 新增UnionPay：只需新增类，无需修改工厂或调用方代码
```

### 2. 组合优于继承（Composition over Inheritance）

这是策略模式与模板方法模式的根本分歧：

```
策略模式：使用组合（Composition）
- 运行时动态切换，更灵活
- 需要显式管理对象关系

模板方法：使用继承（Inheritance）
- 自动复用骨架代码，更简洁
- 编译时绑定，不够灵活
```

## 一、策略模式（Strategy Pattern）

### 1.1 模式定义与意图

**GoF定义**：Define a family of algorithms, encapsulate each one, and make them interchangeable.

**核心意图**：
- 将算法从使用算法的类中抽离出来
- 运行时动态切换算法
- 消除大量的条件分支语句（if-else / switch-case）

```
策略模式结构

    Context <>-------- Strategy ◄---------┐
      - strategy    + execute()           │
      + operation()     ▲                 │
                        │                 │
              StrategyA  StrategyB  StrategyC
              +execute() +execute() +execute()

关键理解：Context不直接实现算法，而是委托给Strategy
```

### 1.2 源码深度分析：JDK中的策略模式

#### 1.2.1 java.util.Comparator

```java
// JDK中最经典的策略模式应用
List<String> names = Arrays.asList("Alice", "Bob", "Charlie");

// 策略1：自然顺序
Collections.sort(names);

// 策略2：降序排列（Lambda策略）
Collections.sort(names, (a, b) -> Integer.compare(b.length(), a.length()));

// 策略3：Comparator链式组合（组合策略模式）
Collections.sort(names, 
    Comparator.comparingInt(String::length)
              .thenComparing(Comparator.reverseOrder()));
```

**源码剖析**：

```java
// java.util.Collections.sort 的源码
public static <T> void sort(List<T> list, Comparator<? super T> c) {
    Object[] a = list.toArray();
    // 调用TimSort，传入Comparator作为排序策略
    Arrays.sort(a, (Comparator) c);
    // ...
}

// TimSort核心逻辑：
// 在比较元素时调用 c.compare(a[i], a[j])
// 这就是策略模式的典型应用：将比较逻辑委托给Comparator
```

**关键洞察**：`Comparator`接口就是策略接口，`Collections.sort()`的第二个参数就是策略对象。TimSort算法本身不关心如何比较两个元素，它只负责排序的逻辑框架，具体的比较策略由调用方注入。

#### 1.2.2 java.util.concurrent.RejectedExecutionHandler

```java
// ThreadPoolExecutor的拒绝策略，也是典型的策略模式
public interface RejectedExecutionHandler {
    void rejectedExecution(Runnable r, ThreadPoolExecutor executor);
}

// JDK内置的四种拒绝策略
public static class AbortPolicy implements RejectedExecutionHandler {
    public void rejectedExecution(Runnable r, ThreadPoolExecutor e) {
        throw new RejectedExecutionException("Task " + r.toString() + 
                                             " rejected from " + e.toString());
    }
}

public static class CallerRunsPolicy implements RejectedExecutionHandler {
    public void rejectedExecution(Runnable r, ThreadPoolExecutor e) {
        if (!e.isShutdown()) {
            r.run();  // 调用者线程自己执行
        }
    }
}

public static class DiscardPolicy implements RejectedExecutionHandler {
    public void rejectedExecution(Runnable r, ThreadPoolExecutor e) {
        // 静默丢弃
    }
}

public static class DiscardOldestPolicy implements RejectedExecutionHandler {
    public void rejectedExecution(Runnable r, ThreadPoolExecutor e) {
        if (!e.isShutdown()) {
            e.getQueue().poll();  // 丢弃最老的任务
            e.execute(r);         // 重新提交当前任务
        }
    }
}
```

**使用方式**：

```java
// 创建线程池时指定拒绝策略
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    5, 10, 60L, TimeUnit.SECONDS,
    new LinkedBlockingQueue<>(100),
    new ThreadPoolExecutor.CallerRunsPolicy()
);

// 自定义拒绝策略
ThreadPoolExecutor executor2 = new ThreadPoolExecutor(
    5, 10, 60L, TimeUnit.SECONDS,
    new LinkedBlockingQueue<>(100),
    (r, e) -> {
        log.error("Task rejected: {}, active: {}, queue: {}",
```

#### 1.3.3 Spring 中的策略工厂实现

```java
/**
 * Spring中优雅实现策略模式的最佳实践
 * 核心思想：利用Spring的依赖注入自动收集所有策略实现
 */
@Component
public class PaymentStrategyFactory {
    
    // Spring会自动注入所有PaymentStrategy的实现类
    private final Map<String, PaymentStrategy> strategyMap;
    
    public PaymentStrategyFactory(List<PaymentStrategy> strategies) {
        this.strategyMap = strategies.stream()
            .collect(Collectors.toMap(
                PaymentStrategy::getType,
                Function.identity(),
                (existing, replacement) -> {
                    throw new IllegalStateException(
                        "Duplicate strategy type: " + existing.getType());
                },
                LinkedHashMap::new
            ));
        
        log.info("Registered payment strategies: {}", strategyMap.keySet());
    }
    
    public PaymentStrategy getStrategy(String type) {
        PaymentStrategy strategy = strategyMap.get(type);
        if (strategy == null) {
            throw new IllegalArgumentException(
                "Unknown payment type: " + type + 
                ". Supported types: " + strategyMap.keySet());
        }
        return strategy;
    }
    
    public boolean supports(String type) {
        return strategyMap.containsKey(type);
    }
    
    public Set<String> getSupportedTypes() {
        return Collections.unmodifiableSet(strategyMap.keySet());
    }
}
```

```java
        return result;
    }
```

### 1.4 实战案例：电商促销系统

```

   ┌──────────────────┐
   │ PromotionEngine  │
   │ - strategies:    │
   │   Map<String,    │
   │   PromotionStrategy>
   │ + calculate(     │
   │   Order): BigDecimal
   └────────┬─────────┘
            │
            ▼
   ┌──────────────────┐
   │PromotionStrategy │◄──────────────────────────────┐
   │+ calculate(Order)│                               │
   │  : BigDecimal    │                               │
   └──────────────────┘                               │
            ▲                                         │
            │                                         │
    ┌───────┴───────┬───────────────┬───────────────┐│
    │               │               │               ││
 ┌──┴───┐     ┌────┴────┐    ┌─────┴─────┐  ┌────┴───┐
 │Discount│    │  Full   │    │   Nth     │  │  Member │
 │Strategy│    │Reduction│    │   Free    │  │ Discount│
 │-rate   │    │-threshold│   │-n         │  │-level   │
 │-minAmount│   │-reduction│   │-m         │  │-rates[] │
 └────────┘    └─────────┘    └───────────┘  └─────────┘
   打折策略      满减策略         第N件免单       会员等级折扣
```

```java
/**
 * 促销策略接口
 */
public interface PromotionStrategy {
    String getType();
    BigDecimal calculateDiscount(Order order);
    boolean isApplicable(Order order);
}

/**
 * 打折策略：直接按比例打折
 */
@Component
public class DiscountStrategy implements PromotionStrategy {
    
    @Value("${promotion.discount.rate:0.8}")
    private BigDecimal discountRate;
    
    @Value("${promotion.discount.minAmount:100}")
    private BigDecimal minAmount;
    
    @Override
    public String getType() { return "DISCOUNT"; }
    
    @Override
    public boolean isApplicable(Order order) {
        return order.getTotalAmount().compareTo(minAmount) >= 0;
    }
    
    @Override
    public BigDecimal calculateDiscount(Order order) {
        if (!isApplicable(order)) return BigDecimal.ZERO;
        return order.getTotalAmount()
            .multiply(BigDecimal.ONE.subtract(discountRate))
            .setScale(2, RoundingMode.HALF_UP);
    }
}

/**
 * 满减策略：满X元减Y元
 */
@Component
public class FullReductionStrategy implements PromotionStrategy {
    
    private final List<ReductionRule> rules = Arrays.asList(
        new ReductionRule(new BigDecimal("100"), new BigDecimal("10")),
        new ReductionRule(new BigDecimal("200"), new BigDecimal("30")),
        new ReductionRule(new BigDecimal("500"), new BigDecimal("100"))
    );
    
    @Override
    public String getType() { return "FULL_REDUCTION"; }
    
    @Override
    public boolean isApplicable(Order order) {
        return rules.stream()
            .anyMatch(rule -> order.getTotalAmount().compareTo(rule.getThreshold()) >= 0);
    }
    
    @Override
    public BigDecimal calculateDiscount(Order order) {
        if (!isApplicable(order)) return BigDecimal.ZERO;
        return rules.stream()
            .filter(rule -> order.getTotalAmount().compareTo(rule.getThreshold()) >= 0)
            .map(ReductionRule::getReduction)
            .max(BigDecimal::compareTo)
            .orElse(BigDecimal.ZERO);
    }
    
    @Data
    private static class ReductionRule {
        private final BigDecimal threshold;
        private final BigDecimal reduction;
    }
}

/**
 * 第N件免单策略
 */
@Component
public class NthFreeStrategy implements PromotionStrategy {
    
    @Value("${promotion.nthfree.n:3}")
    private int n;
    
    @Override
    public String getType() { return "NTH_FREE"; }
    
    @Override
    public boolean isApplicable(Order order) {
        return order.getItems().size() >= n;
    }
    
    @Override
    public BigDecimal calculateDiscount(Order order) {
        if (!isApplicable(order)) return BigDecimal.ZERO;
        
        List<OrderItem> sortedItems = order.getItems().stream()
            .sorted(Comparator.comparing(OrderItem::getPrice))
            .collect(Collectors.toList());
        
        int freeCount = sortedItems.size() / n;
        BigDecimal discount = BigDecimal.ZERO;
        for (int i = 0; i < freeCount; i++) {
            discount = discount.add(sortedItems.get(i).getPrice());
        }
        return discount;
    }
}

/**
 * 促销引擎：统筹所有策略
 */
@Component
public class PromotionEngine {
    
    @Autowired
    private List<PromotionStrategy> strategies;
    
    /**
     * 计算最优优惠
     */
    public PromotionResult calculateBestPromotion(Order order) {
        PromotionResult bestResult = null;
        BigDecimal maxDiscount = BigDecimal.ZERO;
        
        for (PromotionStrategy strategy : strategies) {
            if (strategy.isApplicable(order)) {
                BigDecimal discount = strategy.calculateDiscount(order);
                if (discount.compareTo(maxDiscount) > 0) {
                    maxDiscount = discount;
                    bestResult = new PromotionResult(
                        strategy.getType(), discount,
                        order.getTotalAmount().subtract(discount)
                    );
                }
            }
        }
        
        return bestResult != null ? bestResult : 
            new PromotionResult("NONE", BigDecimal.ZERO, order.getTotalAmount());
    }
}
```

#### 1.5.1 枚举策略

```java
/**
 * 简单场景下，枚举可以实现策略模式
 * 适用条件：策略数量固定且较少，策略逻辑简单

public enum DiscountStrategyEnum {
    NORMAL(1, "无折扣") {
        @Override
        public BigDecimal calculate(BigDecimal amount) { return amount; }
    },
    VIP(2, "VIP折扣") {
        @Override
        public BigDecimal calculate(BigDecimal amount) {
            return amount.multiply(new BigDecimal("0.8"));
        }
    },
    SUPER_VIP(3, "超级VIP折扣") {
        @Override
        public BigDecimal calculate(BigDecimal amount) {
            return amount.multiply(new BigDecimal("0.5"));
        }
    };
    
    private final int code;
    private final String desc;
    
    DiscountStrategyEnum(int code, String desc) {
        this.code = code;
        this.desc = desc;
    }
    
    public abstract BigDecimal calculate(BigDecimal amount);
    
    public static DiscountStrategyEnum of(int code) {
        return Arrays.stream(values())
            .filter(s -> s.code == code)
            .findFirst()
            .orElseThrow(() -> new IllegalArgumentException("Unknown code: " + code));
    }
}
```

#### 1.5.2 函数式策略（Java 8+）

```java
/**
 * 使用函数式接口实现策略模式
 */
public class FunctionalStrategy {
    
    @FunctionalInterface
    public interface DiscountFunction {
        BigDecimal apply(BigDecimal amount);
    }
    
    public static final DiscountFunction NO_DISCOUNT = amount -> amount;
    public static final DiscountFunction VIP_DISCOUNT = amount -> 
        amount.multiply(new BigDecimal("0.8"));
    
    public static DiscountFunction percentageDiscount(BigDecimal rate) {
        return amount -> amount.multiply(rate);
    }
    
    public static DiscountFunction combine(DiscountFunction... strategies) {
        return amount -> {
            BigDecimal result = amount;
            for (DiscountFunction strategy : strategies) {
                result = strategy.apply(result);
            }
            return result;
        };
    }
}

// 使用示例
public class OrderService {
    private DiscountFunction discountFunction = FunctionalStrategy.NO_DISCOUNT;
    
    public void setDiscountFunction(DiscountFunction function) {
        this.discountFunction = function;
    }
    
    public BigDecimal calculatePrice(BigDecimal amount) {
        return discountFunction.apply(amount);
    }
}
```

## 二、模板方法模式（Template Method Pattern）

### 2.1 模式定义与意图

**GoF定义**：Define the skeleton of an algorithm in an operation, deferring some steps to subclasses.

**核心意图**：
- 定义算法执行的固定流程（骨架）
- 将可变部分延迟到子类实现
- 通过钩子方法（Hook Method）提供扩展点

```
模板方法模式结构

AbstractTemplate (abstract)
  # primitiveOp1()   ◄──── 抽象方法：子类必须实现
```

```java
// InputStream的read(byte[])是模板方法
public abstract class InputStream implements Closeable {
    
    /**
     * 模板方法：读取字节数组
     * 骨架逻辑：循环调用read()直到读取足够数据或遇到EOF
     */
    public int read(byte b[], int off, int len) throws IOException {
        if (b == null) throw new NullPointerException();
        if (off < 0 || len < 0 || len > b.length - off)
            throw new IndexOutOfBoundsException();
        if (len == 0) return 0;
        
        int c = read();  // 调用抽象方法
        if (c == -1) return -1;
        b[off] = (byte)c;
        
        int i = 1;
        try {
            for (; i < len ; i++) {
                c = read();  // 调用抽象方法
                if (c == -1) break;
                b[off + i] = (byte)c;
            }
        } catch (IOException ee) {}
        return i;
    }
    
    public abstract int read() throws IOException;
}
```

```java
class TimSort<T> {
    /**
     * 模板方法：排序的核心逻辑
     * 固定部分：TimSort的合并策略、最小run计算等
     * 可变部分：通过Comparator比较元素
     */
    static <T> void sort(T[] a, int lo, int hi, Comparator<? super T> c) {
        if (c == null) {
            sort(a, lo, hi);  // 使用自然排序
            return;
        }
        
        int nRemaining = hi - lo;
        if (nRemaining < 2) return;
        
        int minRun = minRunLength(nRemaining);
        
        do {
            int runLen = countRunAndMakeAscending(a, lo, hi, c);
            if (runLen < minRun) {
                int force = Math.min(nRemaining, minRun);
                binarySort(a, lo, lo + force, lo + runLen, c);
                runLen = force;
            }
            
            pushRun(lo, runLen);
            mergeCollapse(c);  // 传递Comparator策略
            
            lo += runLen;
            nRemaining -= runLen;
        } while (nRemaining != 0);
        
        mergeForceCollapse(c);
    }
    
    // 通过Comparator策略比较
    private static <T> int countRunAndMakeAscending(T[] a, int lo, int hi, 
                                                     Comparator<? super T> c) {
        int runHi = lo + 1;
        if (runHi == hi) return 1;
        
        if (c.compare(a[runHi++], a[lo]) < 0) {
            while (runHi < hi && c.compare(a[runHi], a[runHi - 1]) < 0)
                runHi++;
            reverseRange(a, lo, runHi);
        } else {
            while (runHi < hi && c.compare(a[runHi], a[runHi - 1]) >= 0)
                runHi++;
        }
        return runHi - lo;
    }
}
```

### 2.4 实战案例：数据导入框架

```java
/**
 * 数据导入抽象模板
 * 
 * 设计要点：
 * 1. templateMethod必须是final的，防止子类篡改流程
 * 2. 固定步骤使用private方法，子类不可见
 * 3. 可变步骤使用protected abstract方法，强制子类实现
 * 4. 钩子方法使用protected方法，子类可选覆盖
 */
public abstract class DataImporterTemplate {
    
    /**
     * 模板方法：定义导入的标准流程
     */
    public final ImportResult importData(String filePath) {
        long startTime = System.currentTimeMillis();
        ImportResult result = new ImportResult();
        
        try {
            validateFile(filePath);
            List<String> rawLines = readFile(filePath);
            result.setTotalCount(rawLines.size());
            
            List<ImportRow> parsedRows = parseData(rawLines);      // 子类实现
            List<ImportRow> transformedRows = transformData(parsedRows);  // 子类实现
            
            if (needValidate()) {
                List<String> errors = validateData(transformedRows);
                if (!errors.isEmpty()) {
                    result.setSuccess(false);
                    result.setErrors(errors);
                    return result;
                }
            }
            
            if (needDeduplicate()) {
                transformedRows = deduplicate(transformedRows);
            }
            
            int savedCount = batchSave(transformedRows);  // 子类实现
            result.setSuccessCount(savedCount);
            afterImport(transformedRows);
            result.setSuccess(true);
            
        } catch (Exception e) {
            result.setSuccess(false);
            result.setErrors(Collections.singletonList(e.getMessage()));
            log.error("Import failed: {}", filePath, e);
        } finally {
            cleanup(filePath);
            result.setDurationMs(System.currentTimeMillis() - startTime);
            sendNotification(result);
        }
        
        return result;
    }
    
    // ========== 固定步骤（private，子类不可见） ==========
    private void validateFile(String filePath) {
        File file = new File(filePath);
        if (!file.exists()) throw new IllegalArgumentException("File not found");
    }
    
    private List<String> readFile(String filePath) throws IOException {
        return Files.readAllLines(Paths.get(filePath), StandardCharsets.UTF_8);
    }
    
    private void cleanup(String filePath) { log.info("Cleanup: {}", filePath); }
    
    private void sendNotification(ImportResult result) {
        if (result.isSuccess()) {
            log.info("Import completed: {} rows in {}ms", 
                     result.getSuccessCount(), result.getDurationMs());
        }
    }
    
    // ========== 抽象步骤（protected abstract，子类必须实现） ==========
    protected abstract List<ImportRow> parseData(List<String> rawLines);
    protected abstract List<ImportRow> transformData(List<ImportRow> rows);
    protected abstract int batchSave(List<ImportRow> rows);
    
    // ========== 钩子方法（protected，子类可选覆盖） ==========
    protected boolean needValidate() { return true; }
    protected List<String> validateData(List<ImportRow> rows) { 
        List<String> errors = new ArrayList<>();
        for (int i = 0; i < rows.size(); i++) {
            if (rows.get(i).getKey() == null) {
                errors.add("Row " + (i + 1) + ": key is empty");
            }
        }
        return errors;
    }
    protected boolean needDeduplicate() { return false; }
    protected List<ImportRow> deduplicate(List<ImportRow> rows) {
        Set<String> seen = new HashSet<>();
        return rows.stream().filter(r -> seen.add(r.getKey())).collect(Collectors.toList());
    }
    protected void afterImport(List<ImportRow> rows) {}
}
```

## 三、责任链模式（Chain of Responsibility Pattern）

### 3.1 模式定义与意图

**GoF定义**：Avoid coupling the sender of a request to its receiver by giving more than one object a chance to handle the request.

**核心意图**：
- 解耦请求的发送者和接收者
- 多个处理器依次处理请求
- 动态组合处理链

```
责任链模式结构

Client -> HandlerA -> HandlerB -> HandlerC
           [校验]     [鉴权]      [业务处理]
           通过       通过        完成

关键特征：每个处理器可以选择处理请求并终止，或传递给下一个处理器
```

```java
// Spring MVC的拦截器链是责任链模式的典型应用
public class DispatcherServlet extends FrameworkServlet {
    
    protected void doDispatch(HttpServletRequest request, HttpServletResponse response) 
            throws Exception {
        
        HandlerExecutionChain mappedHandler = getHandler(processedRequest);
        HandlerAdapter ha = getHandlerAdapter(mappedHandler.getHandler());
        
        // 执行拦截器preHandle（责任链）
        if (!mappedHandler.applyPreHandle(processedRequest, response)) {
            return;
        }
        
        ModelAndView mv = ha.handle(processedRequest, response, mappedHandler.getHandler());
        
        mappedHandler.applyPostHandle(processedRequest, response, mv);
        processDispatchResult(processedRequest, response, mappedHandler, mv, exception);
        mappedHandler.triggerAfterCompletion(processedRequest, response, exception);
    }
}

// HandlerExecutionChain的实现
public class HandlerExecutionChain {
    
    private final Object handler;
    private final List<HandlerInterceptor> interceptorList = new ArrayList<>();
    private int interceptorIndex = -1;
    
    boolean applyPreHandle(HttpServletRequest request, HttpServletResponse response) 
            throws Exception {
        for (int i = 0; i < interceptorList.size(); i++) {
            HandlerInterceptor interceptor = interceptorList.get(i);
            if (!interceptor.preHandle(request, response, this.handler)) {
                triggerAfterCompletion(request, response, null);
                return false;
            }
            this.interceptorIndex = i;
        }
        return true;
    }
    
    void applyPostHandle(HttpServletRequest request, HttpServletResponse response, 
                         ModelAndView mv) throws Exception {
        for (int i = interceptorList.size() - 1; i >= 0; i--) {
            interceptorList.get(i).postHandle(request, response, this.handler, mv);
        }
    }
    
    void triggerAfterCompletion(HttpServletRequest request, HttpServletResponse response, 
                                Exception ex) {
        for (int i = this.interceptorIndex; i >= 0; i--) {
            try {
                interceptorList.get(i).afterCompletion(request, response, this.handler, ex);
            } catch (Throwable ex2) {
                logger.error("HandlerInterceptor.afterCompletion threw exception", ex2);
            }
        }
    }
}
```

### 3.5 责任链的两种实现方式

```
责任链的两种实现方式

方式1：链表式（显式链）
- 每个Handler持有next引用
- 优点：结构清晰，支持运行时动态调整链
- 缺点：需要显式维护next引用，组装代码较繁琐

- List<Handler> handlers，遍历列表依次执行
- 优点：使用Java集合，支持@Order排序，与Spring集成方便
- 缺点：控制权在调用方

Spring的选择：方式2（列表式）
- 可利用Spring排序机制，自动注入Handler，支持AOP代理
```

## 四、三模式对比分析

### 4.1 核心差异对比表

```
│ 维度         │ 策略模式           │ 模板方法模式        │ 责任链模式         │
├──────────────┼───────────────────┼───────────────────┼──────────────────┤
│ 设计意图     │ 封装可互换的算法   │ 复用算法骨架        │ 解耦请求与处理     │
│ 复用方式     │ 组合               │ 继承                │ 组合或继承        │
│ 运行时灵活性 │ 高（动态切换）     │ 低（编译时绑定）    │ 高（动态组装链）  │
│ 主要解决问题 │ if-else代码膨胀   │ 重复代码（流程相同）│ 请求处理者不确定  │
│ JDK典型应用  │ Comparator        │ AbstractList        │ Logger Handler链  │
│ Spring典型   │ HandlerMapping    │ JdbcTemplate        │ HandlerInterceptor│
│ 扩展方式     │ 新增策略类注册工厂 │ 新增子类继承抽象类  │ 新增Handler注册链 │
```

### 4.2 适用场景决策树

```
模式选择决策树

                    有相同的执行流程？
                         /        \
                       是          否
                      /             \
              步骤顺序固定？      策略模式
                   /    \
                 是      否
                /         \
         模板方法      考虑职责链或流程引擎

策略模式：
- 系统中有多个类，它们之间的区别仅在于行为不同
- 需要在运行时根据条件选择不同行为
- 有大量if-else/switch，且这些分支会频繁新增
- 示例：支付方式选择、排序算法选择、压缩算法选择

模板方法：
- 多个类有相同的执行流程，只有部分步骤不同
- 流程的顺序是固定的，不能改变
- 希望将公共代码提取到父类，避免重复
- 示例：数据导入、报表生成、工作流执行

责任链：
- 一个请求需要经过多个处理环节，但处理顺序可能变化
- 每个处理器可以决定是否处理请求或传递给下一个
- 希望解耦请求发送者和处理者
- 示例：审批流程、风控检查、过滤器链、中间件
```

### 4.3 组合使用模式

### 5.1 时间复杂度与空间复杂度

```
三模式性能分析

策略模式：O(1)时间（Map查找），O(n)空间。瓶颈：对象创建、Spring注入
```

### 5.2 性能优化策略

```java
/**
 * 策略模式性能优化：缓存策略实例
 */
@Component
public class OptimizedStrategyFactory {
    
    private final Map<String, PaymentStrategy> strategyCache;
    
    public OptimizedStrategyFactory(List<PaymentStrategy> strategies) {
        // 使用ConcurrentHashMap保证线程安全
        this.strategyCache = strategies.stream()
            .collect(Collectors.toConcurrentMap(
                PaymentStrategy::getType,
                Function.identity()
            ));
    }
    
    // 策略实例在启动时创建，运行时直接获取
    public PaymentStrategy getStrategy(String type) {
        PaymentStrategy strategy = strategyCache.get(type);
        if (strategy == null) {
            throw new IllegalArgumentException("Unknown type: " + type);
        }
        return strategy;
    }
}

/**
 * 责任链性能优化：支持短路和并行
 */
public class OptimizedChain {
    
    private final List<Handler> handlers;
    private final boolean parallel;
    
    public OptimizedChain(List<Handler> handlers, boolean parallel) {
        this.handlers = handlers;
        this.parallel = parallel;
    }
    
    public void handle(Request request) {
        if (parallel) {
            // 并行执行所有Handler（适用于无依赖的校验）
            List<CompletableFuture<Boolean>> futures = handlers.stream()
                .map(h -> CompletableFuture.supplyAsync(() -> h.handle(request)))
                .collect(Collectors.toList());
            
            CompletableFuture.allOf(futures.toArray(new CompletableFuture[0]))
                .join();
        } else {
            // 串行执行，支持短路
            for (Handler handler : handlers) {
                if (!handler.handle(request)) {
                    break;  // 短路
                }
            }
        }
    }
}
```

## 六、常见陷阱与最佳实践

### 6.1 策略模式陷阱

#### 陷阱1：策略接口方法过多导致"胖接口"

```java
// 错误：一个接口里塞了太多方法
public interface FatStrategy {
    void execute();
    void rollback();
    void validate();
    void prepare();
    void cleanup();
    void log();
}

// 正确：拆分接口（接口隔离原则ISP）
public interface ExecutableStrategy {
    void execute();
}

public interface Rollbackable {
    void rollback();
}

// 或者使用函数式接口
public interface Strategy {
    Result execute(Context context);
}
```

#### 陷阱2：策略工厂未处理策略不存在的情况

```java
// 错误：直接从Map取，可能NPE
PaymentStrategy strategy = strategyMap.get(type);
strategy.pay(amount); // NullPointerException

// 正确：使用Optional和自定义异常
public PaymentStrategy getStrategy(String type) {
    return Optional.ofNullable(strategyMap.get(type))
        .orElseThrow(() -> new UnsupportedPaymentTypeException(
            "Unsupported payment type: " + type
        ));
}

// 或者提供默认策略
public PaymentStrategy getStrategy(String type) {
    return strategyMap.getOrDefault(type, defaultStrategy);
}
```

#### 陷阱3：策略对象状态管理不当

```java
// 错误：策略有状态，多线程下不安全
public class StatefulStrategy implements PaymentStrategy {
    private int counter;  // 有状态！
    
    @Override
    public void pay(BigDecimal amount) {
        counter++;  // 线程不安全
    }
}

// 正确：策略应该是无状态的
public class StatelessStrategy implements PaymentStrategy {
    @Override
    public void pay(BigDecimal amount) {
        // 只使用局部变量和参数
    }
}
```

### 6.2 模板方法陷阱

#### 陷阱1：钩子方法默认行为不安全

```java
// 错误：钩子方法默认返回true，子类忘记覆盖导致意外行为
public abstract class Template {
    public final void process() {
        step1();
        if (needStep2()) step2(); // 默认true
        step3();
    }
    protected boolean needStep2() { return true; }  // 危险的默认值
}

// 正确：默认行为应该是最安全的（如跳过可选步骤）
public abstract class SafeTemplate {
    public final void process() {
        step1();
        if (needStep2()) step2(); // 默认false
        step3();
    }
    protected boolean needStep2() { return false; }  // 安全的默认值
}
```

#### 陷阱2：模板方法中暴露过多protected方法

```java
// 错误：暴露了太多protected方法
public abstract class LooseTemplate {
    protected void step1() {}  // 应该是private
    protected void step2() {}  // 应该是private
    protected abstract void step3();
    protected void step4() {}  // 应该是private
}

// 正确：固定步骤使用private，只有可变步骤使用protected
public abstract class StrictTemplate {
    private void step1() {}     // 固定步骤，private
    private void step2() {}     // 固定步骤，private
    protected abstract void step3();  // 可变步骤，abstract
    private void step4() {}     // 固定步骤，private
}
```

### 6.3 责任链陷阱

#### 陷阱1：链过长影响性能且难以调试

```java
// 错误：链上有十几个处理器
validation -> auth -> rateLimit -> logging -> audit -> risk -> business -> notify -> cache -> ...

// 正确：责任链长度控制在合理范围（通常3-5个）
validation -> auth -> risk -> business

// 不相关的校验可以并行或使用AOP
```

#### 陷阱2：Handler未正确调用doNext导致链断裂

```java
// 错误：忘记调用doNext
public class BrokenHandler extends AbstractHandler {
    @Override
    public void handle(Request request) {
        System.out.println("Handled");
        // 忘记调用 doNext(request) 了！
    }
}

// 正确：使用抽象类强制调用
public abstract class SafeAbstractHandler implements Handler {
    protected Handler next;
    
    @Override
    public final void handle(Request request) {
        boolean shouldContinue = doHandle(request);  // 子类实现
        if (shouldContinue && next != null) {
            next.handle(request);
        }
    }
    
    protected abstract boolean doHandle(Request request);
}
```

### 6.4 通用最佳实践

```
三模式通用最佳实践

1. 命名规范
   - 策略接口：xxxStrategy / xxxPolicy
   - 模板类：xxxTemplate / xxxBase
   - 责任链Handler：xxxHandler / xxxInterceptor

2. 文档规范
   - 策略：说明策略的适用场景和触发条件
   - 模板：明确标注哪些方法是必须覆盖的，哪些是可选的
   - 责任链：说明每个Handler的职责和触发条件

3. 测试策略
   - 策略：每个策略独立单元测试
   - 模板：测试模板流程和每个子类的具体实现
   - 责任链：测试单个Handler和完整链的组合

4. Spring集成最佳实践
   - 使用构造函数注入（不可变依赖）
   - 利用@Order注解控制责任链顺序
   - 使用@ConditionalOnProperty实现策略的开关配置

5. 监控与日志
   - 策略：记录策略选择和使用频次
   - 模板：记录每个步骤的执行时间
   - 责任链：记录每个Handler的处理时间和是否终止
```

### Q1：策略模式和状态模式有什么区别？

**答：**

```
核心区别：
- 策略模式：客户端主动选择策略，策略独立于上下文
- 状态模式：状态由对象内部条件自动转换

举例：
- 支付时选择支付宝/微信是策略模式
- 订单从"待支付"到"已支付"自动触发不同行为是状态模式
```

### Q2：模板方法模式和策略模式都能复用代码，怎么选？

**答：**

```
核心区别：继承 vs 组合

模板方法模式：
- 算法骨架固定，子类覆盖特定步骤
- 适用：多个类有相同流程，只有部分细节不同

策略模式：
- 整个算法可替换，上下文只负责调用
- 适用：多种完全不同的算法需要互换

示例：
- 数据导入（CSV/Excel/JSON）：模板方法
- 支付方式（支付宝/微信/银联）：策略模式
```

### Q3：责任链模式和装饰器模式有什么区别？

**答：**

```
责任链 vs 装饰器

责任链：
- 处理器可选择继续传递或终止
- 形象比喻：审批流（任意一级可以驳回）

装饰器：
- 每一层都会执行，层层包装
- 形象比喻：俄罗斯套娃

JDK示例：
- 责任链：Logger的Handler链、Servlet Filter链
- 装饰器：BufferedInputStream包装FileInputStream
```

### Q4：Spring拦截器链（HandlerInterceptor）执行顺序是怎样的？如果中途返回false会怎样？

**答：**

```
执行顺序：

请求进入：
  preHandle(1) -> preHandle(2) -> preHandle(3) -> Controller
      true          true            true

请求离开：
  postHandle(3) -> postHandle(2) -> postHandle(1)
  afterCompletion(3) -> afterCompletion(2) -> afterCompletion(1)

如果preHandle(2)返回false：

请求进入：
  preHandle(1) -> preHandle(2) [返回false]
      true          false

执行结果：
  1. preHandle(2)及后续拦截器不再执行
  2. Controller不执行
  3. postHandle都不执行
  4. afterCompletion按逆序执行已执行的拦截器：
     afterCompletion(1)
```

### Q6：如何在Spring中优雅地消除大量的if-else？结合策略模式说说。

**答：**

```java
/**
 * 核心思路：Spring依赖注入 + Map自动收集策略
 */

// 1. 定义策略接口
public interface OrderStatusHandler {
    String getStatus();
    void handle(Order order);
}

// 2. 实现策略（每个状态一个类）
@Component
public class PendingPaymentHandler implements OrderStatusHandler {
    public String getStatus() { return "PENDING_PAYMENT"; }
    public void handle(Order order) {
        // 待支付状态处理
    }
}

@Component
public class PaidHandler implements OrderStatusHandler {
    public String getStatus() { return "PAID"; }
    public void handle(Order order) {
        // 已支付状态处理
    }
}

// 3. 策略工厂（Spring自动注入）
@Component
public class OrderStatusHandlerFactory {
    private final Map<String, OrderStatusHandler> handlerMap;
    
    public OrderStatusHandlerFactory(List<OrderStatusHandler> handlers) {
        this.handlerMap = handlers.stream()
            .collect(Collectors.toMap(
                OrderStatusHandler::getStatus,
                Function.identity()
            ));
    }
    
    public OrderStatusHandler getHandler(String status) {
        return Optional.ofNullable(handlerMap.get(status))
            .orElseThrow(() -> new IllegalArgumentException("Unknown status: " + status));
    }
}

// 4. 使用（完全消除if-else）
@Service
public class OrderService {
    @Autowired
    private OrderStatusHandlerFactory handlerFactory;
    
    public void processOrderStatusChange(String orderId, String newStatus) {
        Order order = orderRepository.findById(orderId);
        
        // 无需if-else，直接根据状态获取处理器
        OrderStatusHandler handler = handlerFactory.getHandler(newStatus);
        handler.handle(order);
        
        // 状态变更只需要新增Handler类，无需修改现有代码（OCP）
    }
}
```

### Q7：模板方法模式中的钩子方法（Hook Method）有什么作用？

**答：**

```
钩子方法的作用：

1. 提供扩展点
   - 父类定义算法骨架，子类通过钩子方法在特定位置插入自定义逻辑
   - 不需要改变骨架结构

2. 条件控制
   - 钩子方法返回boolean，控制是否执行某个步骤
   - 例如：needValidate()控制是否执行校验

3. 默认行为
   - 钩子方法可以提供默认实现（通常是空实现）
   - 子类可以选择性覆盖

4. 与抽象方法的区别
   ┌─────────────────┬──────────────────┬──────────────────┐
   │     特性        │   抽象方法        │   钩子方法        │
   ├─────────────────┼──────────────────┼──────────────────┤
   │ 是否必须实现     │ 是               │ 否（有默认实现）  │
   │ 目的            │ 强制子类提供实现   │ 提供可选扩展点    │
   │ 命名习惯         │ doXxx / parseXxx  │ needXxx / beforeXxx│
   └─────────────────┴──────────────────┴──────────────────┘

示例：
public abstract class DataImporter {
    public final void importData(String file) {
        read(file);
        parse();
        if (needValidate()) {  // 钩子方法
            validate();
        }
        save();
    }
    
    protected abstract void parse();  // 抽象方法，必须实现
    protected boolean needValidate() { return true; }  // 钩子方法，默认开启校验
}
```

### Q8：责任链模式和AOP有什么关系？什么时候用责任链，什么时候用AOP？

**答：**

```
关系：
- AOP是责任链模式的一种实现方式
- Spring AOP的拦截器链（MethodInterceptor）就是责任链

对比：
┌─────────────────┬──────────────────┬──────────────────┐
│     特性        │   责任链模式      │   AOP            │
├─────────────────┼──────────────────┼──────────────────┤
│ 关注点          │ 业务逻辑的处理环节 │ 横切关注点        │
│ 典型应用        │ 审批流、风控检查   │ 日志、事务、权限  │
│ 链的组装        │ 手动组装或配置     │ 自动织入          │
│ 与业务耦合       │ 高（业务逻辑的一部分│ 低（非功能性需求）│
│ 灵活性          │ 动态调整链的顺序   │ 通过切点表达式配置 │
└─────────────────┴──────────────────┴──────────────────┘

选择原则：
- 如果处理逻辑是业务的一部分（如支付前的校验），用责任链
- 如果处理逻辑是横切关注点（如日志、监控），用AOP
- 如果处理逻辑需要动态调整顺序，用责任链
- 如果处理逻辑需要应用到多个不相关的方法，用AOP

示例：
// 责任链：支付校验（业务逻辑）
validation -> auth -> risk -> balance -> execute

// AOP：日志记录（横切关注点）
@Around("execution(* com.example.service.*.*(..))")
public Object logAround(ProceedingJoinPoint joinPoint) {
    // 记录方法调用日志
}
```

### Q9：策略模式中的策略是如何被Spring管理的？使用List注入有什么潜在问题？

**答：**

```java
/**
 * Spring管理策略的方式
 */

// 方式1：List注入（最常用）
@Component
public class StrategyFactory {
    private final Map<String, Strategy> strategyMap;
    
    // Spring会自动收集所有Strategy的实现类
    public StrategyFactory(List<Strategy> strategies) {
        this.strategyMap = strategies.stream()
            .collect(Collectors.toMap(Strategy::getType, Function.identity()));
    }
}

// 潜在问题1：策略未标注@Component，导致注入为空列表
// 解决：启动时检查，如果为空抛出异常或告警

// 潜在问题2：多个策略返回相同的type，导致Map构建失败
// 解决：使用merge函数或启动时检查重复
public StrategyFactory(List<Strategy> strategies) {
    this.strategyMap = strategies.stream()
        .collect(Collectors.toMap(
            Strategy::getType,
            Function.identity(),
            (existing, replacement) -> {
                throw new IllegalStateException(
                    "Duplicate strategy type: " + existing.getType());
            }
        ));
}

// 潜在问题3：AOP代理问题
// 如果Strategy有AOP代理，getType()方法可能返回代理类的名称
// 解决：使用@Primary或在接口中定义type为常量

// 最佳实践：启动验证
@Component
public class StrategyValidator implements CommandLineRunner {
    @Autowired
    private StrategyFactory factory;
    
    @Override
    public void run(String... args) {
        Set<String> expectedTypes = loadExpectedTypes();
        Set<String> actualTypes = factory.getSupportedTypes();
        
        if (!actualTypes.containsAll(expectedTypes)) {
            Set<String> missing = new HashSet<>(expectedTypes);
            missing.removeAll(actualTypes);
            throw new IllegalStateException("Missing strategies: " + missing);
        }
        
        log.info("Strategy validation passed. Registered: {}", actualTypes);
    }
}
```

### Q10：如何在模板方法模式中避免"脆弱的基类"问题？

**答：**

```
脆弱的基类问题：父类的修改可能导致子类行为异常

避免策略：
1. 最小化protected方法，固定步骤使用private
2. 文档化契约，明确说明哪些方法可以覆盖
3. 模板方法使用final，防止篡改流程
4. 提供空实现的适配器类

示例：
// 脆弱的基类
public abstract class BadTemplate {
    public void process() {
        step1();
        step2();  // 新增步骤，子类可能不期望
        step3();
    }
}

// 改进的基类
public abstract class GoodTemplate {
    public final void process() {
        step1();
        hookBeforeStep2();  // 提供扩展点
        step2();
        step3();
    }
    
    private void step1() { /* 固定逻辑 */ }
    private void step2() { /* 固定逻辑 */ }
    private void step3() { /* 固定逻辑 */ }
    protected void hookBeforeStep2() {}  // 钩子方法
}
```
