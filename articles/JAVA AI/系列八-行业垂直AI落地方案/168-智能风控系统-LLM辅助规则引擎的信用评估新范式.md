# 智能风控系统：LLM 辅助规则引擎的信用评估新范式，坏账率降低30%

## 一、传统风控的"阿喀琉斯之踵"

2024年某城商行信用卡中心的月度复盘会上，风控总监李总面色凝重地指着大屏："上个月伪装成电商交易的套现团伙，绕过了我们全部127条风控规则，累计套现金额超过800万。"

这不是个案。根据银保监会2024年报告，信用卡欺诈损失年均增长15%，而传统规则引擎的拦截率已连续3年止步不前。

**传统规则引擎的三大局限：**

- **规则僵化**：规则是"死的"，诈骗手法是"活的"。一条"单笔交易超过5000元预警"的规则，可以被拆分成10笔4999元轻松绕过。
- **语义盲区**：无法理解交易备注中的隐含风险。比如"借"+"还"+"下周"的组合，传统引擎识别为普通转账，但人工一眼就能看出这是"以贷养贷"的信号。
- **维护成本高**：一个中型银行的风控团队通常需要5-8名策略分析师全职维护规则，新人培养周期长达6个月。

## 二、新范式：LLM + 规则引擎的混合架构

我们的核心思路不是"用LLM替代规则引擎"，而是让两者各司其职：

```
┌──────────────────────────────────────────────────────────┐
│                      决策网关                             │
│   ┌──────────────┐   ┌──────────────┐   ┌─────────────┐ │
│   │  规则引擎层   │   │  LLM语义层   │   │  综合决策层   │ │
│   │ (高并发/确定) │ → │ (语义/模糊)  │ → │ (评分/决策)   │ │
│   └──────────────┘   └──────────────┘   └─────────────┘ │
│         ↓                    ↓                  ↓        │
│   硬规则拦截(拒绝)   软特征提取(评分)   最终风险等级       │
├──────────────────────────────────────────────────────────┤
│                    特征工程层                              │
│  交易序列特征 · 设备指纹 · 社交图谱 · 多头借贷 · 舆情     │
├──────────────────────────────────────────────────────────┤
│                    数据接入层                              │
│  交易流水 · 征信报告 · 设备信息 · 行为埋点 · 外部黑名单   │
└──────────────────────────────────────────────────────────┘
```

**分工逻辑：**

- **规则引擎**：处理明确、可量化的硬规则（黑名单匹配、单日频次上限、异常时段的确定性拦截），保证99.99%的拦截准确率。
- **LLM语义层**：处理模糊、需理解的软规则（交易备注分析、申请资料合理性判断、多头借贷风险推演），输出风险特征和置信度。
- **综合决策层**：融合硬规则结果+LLM软特征+特征工程指标，通过XGBoost模型输出最终风险评分。

## 三、Java代码实现

### 3.1 混合风控引擎核心调度

```java
@Service
public class HybridRiskEngine {

    @Autowired
    private DroolsRuleEngine ruleEngine;

    @Autowired
    private LLMRiskAnalyzer llmAnalyzer;

    @Autowired
    private XGBoostScoringModel scoringModel;

    @Autowired
    private RedisTemplate<String, String> redis;

    /**
     * 混合风控决策主流程
     */
    public RiskDecision evaluate(TransactionEvent event) {
        long start = System.currentTimeMillis();

        // Step 1: 规则引擎 - 硬规则快速拦截（< 5ms）
        RuleResult ruleResult = ruleEngine.fireRules(event);
        if (ruleResult.isReject()) {
            return RiskDecision.reject(ruleResult.getRejectReasons(),
                    "RULE_ENGINE", 0);
        }

        // Step 2: 特征提取 - 多维特征构建
        RiskFeature feature = buildRiskFeature(event);

        // Step 3: LLM语义分析 - 对"软信息"做深度理解（异步 + 缓存）
        LLMAnalysisResult llmResult = analyzeSemanticsWithCache(event);

        // Step 4: 综合评分 - XGBoost模型融合所有特征
        double finalScore = scoringModel.predict(feature, llmResult);

        // Step 5: 决策输出
        RiskDecision decision = makeDecision(finalScore, ruleResult, llmResult);

        logDecision(event, decision, System.currentTimeMillis() - start);

        return decision;
    }

    /**
     * LLM语义分析 + Redis缓存，避免重复调用
     */
    private LLMAnalysisResult analyzeSemanticsWithCache(TransactionEvent event) {
        String cacheKey = "llm_risk:" + event.getUserId() + ":" +
                event.getTransactionType();
        String cached = redis.opsForValue().get(cacheKey);

        if (cached != null) {
            return JSON.parseObject(cached, LLMAnalysisResult.class);
        }

        LLMAnalysisResult result = llmAnalyzer.analyze(event);
        // 缓存5分钟，同一用户同类交易复用结果
        redis.opsForValue().set(cacheKey, JSON.toJSONString(result),
                5, TimeUnit.MINUTES);
        return result;
    }

    private RiskFeature buildRiskFeature(TransactionEvent event) {
        return RiskFeature.builder()
                .amount(event.getAmount())
                .hourOfDay(LocalTime.now().getHour())
                .dayOfWeek(LocalDate.now().getDayOfWeek().getValue())
                .deviceChangeFlag(checkDeviceChange(event))
                .locationChangeFlag(checkLocationChange(event))
                .recentTxnCount(getRecentTxnCount(event, 24, TimeUnit.HOURS))
                .recentTxnAmount(getRecentTxnAmount(event, 24, TimeUnit.HOURS))
                .creditScore(getCreditScore(event.getUserId()))
                .overdueHistory(getOverdueHistory(event.getUserId()))
                .build();
    }
}
```

### 3.2 LLM语义分析器

这是整个系统的"灵魂"——让AI读懂那些传统规则引擎读不懂的内容：

```java
@Service
public class LLMRiskAnalyzer {

    private static final String RISK_ANALYSIS_PROMPT = """
            你是一位银行风控专家。请分析以下交易事件的风险，从以下几个维度给出评估：
            
            1. **交易备注语义分析**：备注中是否存在以下风险信号？
               - 借贷/套现暗示（如"借"、"还"、"周转"、"下个月"）
               - 商户名称异常（与常见商户库不匹配）
               - 虚假交易嫌疑（多个不相关用户向同一商户付款）
            
            2. **行为模式异常**：
               - 与用户历史消费习惯的偏差程度
               - 金额是否为常见风控阈值的整数倍（如5000、10000）
               - 时间是否在异常时段（凌晨2-5点）
            
            3. **申请资料合理性**（如是贷款申请）：
               - 收入与职位匹配度
               - 工作单位真实性（知名企业 vs 空壳公司）
               - 联系人手机号有效性
            
            请以JSON格式输出：
            {
                "riskLevel": "LOW|MEDIUM|HIGH|CRITICAL",
                "riskScore": 0.0-1.0,
                "riskDimensions": ["维度1", "维度2"],
                "analysis": "详细分析",
                "evidencePoints": ["证据1", "证据2"],
                "requiresManualReview": true/false
            }
            """;

    @Autowired
    private ChatLanguageModel chatModel;

    public LLMAnalysisResult analyze(TransactionEvent event) {
        String context = buildAnalysisContext(event);

        String response = chatModel.generate(RISK_ANALYSIS_PROMPT + "\n\n" + context);

        return parseLLMResponse(response);
    }

    private String buildAnalysisContext(TransactionEvent event) {
        StringBuilder sb = new StringBuilder();
        sb.append("## 交易信息\n");
        sb.append(String.format("- 交易金额: %.2f 元\n", event.getAmount()));
        sb.append(String.format("- 交易时间: %s\n", event.getTransactionTime()));
        sb.append(String.format("- 交易类型: %s\n", event.getTransactionType()));
        sb.append(String.format("- 商户名称: %s\n", event.getMerchantName()));
        sb.append(String.format("- 交易备注: %s\n", event.getRemark()));
        sb.append(String.format("- MCC码: %s\n", event.getMccCode()));

        sb.append("\n## 用户历史行为\n");
        sb.append(String.format("- 月均消费: %.2f 元\n", event.getMonthlyAvg()));
        sb.append(String.format("- 常用消费时段: %s\n", event.getUsualTimeRange()));
        sb.append(String.format("- 常用消费类型: %s\n", event.getUsualCategories()));
        sb.append(String.format("- 近30天交易笔数: %d\n", event.getRecent30DayCount()));

        if (event instanceof LoanApplication loanApp) {
            sb.append("\n## 贷款申请信息\n");
            sb.append(String.format("- 申请金额: %.2f 元\n", loanApp.getApplyAmount()));
            sb.append(String.format("- 申报收入: %.2f 元\n", loanApp.getDeclaredIncome()));
            sb.append(String.format("- 工作单位: %s\n", loanApp.getEmployer()));
            sb.append(String.format("- 职位: %s\n", loanApp.getPosition()));
        }

        return sb.toString();
    }

    private LLMAnalysisResult parseLLMResponse(String response) {
        // 提取JSON部分
        String jsonStr = extractJSON(response);
        LLMAnalysisResult result = JSON.parseObject(jsonStr, LLMAnalysisResult.class);

        // 校准：LLM评分 × 权重0.4（保留XGBoost模型更大权重）
        result.setRiskScore(result.getRiskScore() * 0.4);

        return result;
    }

    private String extractJSON(String text) {
        int start = text.indexOf("{");
        int end = text.lastIndexOf("}") + 1;
        if (start >= 0 && end > start) {
            return text.substring(start, end);
        }
        throw new RuntimeException("LLM响应中未找到有效JSON");
    }
}
```

### 3.3 规则引擎 + LLM关联分析

LLM不仅能分析单笔交易，还能发现多笔交易的关联模式——这是传统规则引擎的绝对盲区：

```java
@Service
public class PatternDetector {

    @Autowired
    private ChatLanguageModel chatModel;

    /**
     * 检测"化整为零"套现模式
     * 例如：同一商户短时间内收到大量4999元整数付款
     */
    public FraudPatternResult detectSplitPattern(String merchantId, int timeWindowMinutes) {
        // 查询时间窗口内的交易
        List<TransactionEvent> txns = transactionRepository
                .findByMerchantAndTimeRange(merchantId,
                        LocalDateTime.now().minusMinutes(timeWindowMinutes),
                        LocalDateTime.now());

        if (txns.size() < 5) return FraudPatternResult.clean();

        // 构建LLM分析上下文
        String context = buildTransactionSummary(txns);

        String prompt = """
                分析以下交易序列，判断是否存在"化整为零"式的欺诈模式：
                
                检测规则：
                1. 多笔交易的金额接近风控阈值（如4999、9999）
                2. 交易时间高度集中（5分钟内超过5笔）
                3. 付款人之间无明显社交关系但行为高度一致
                4. 商户经营类目与实际交易金额不匹配
                
                %s
                
                请以JSON格式输出：{"isFraud": true/false, "confidence": 0.0-1.0, "patternDesc": "模式描述"}
                """.formatted(context);

        String response = chatModel.generate(prompt);
        return JSON.parseObject(extractJSON(response), FraudPatternResult.class);
    }

    private String buildTransactionSummary(List<TransactionEvent> txns) {
        return txns.stream()
                .map(t -> String.format("用户%s 金额%.2f 时间%s 备注:%s",
                        t.getUserId(), t.getAmount(),
                        t.getTransactionTime(), t.getRemark()))
                .collect(Collectors.joining("\n"));
    }
}
```

## 五、关键设计原则

1. **LLM不做最终决策**：LLM输出风险特征和置信度，由XGBoost模型做最终评分。这保证了可解释性（XGBoost的SHAP值）和确定性。

2. **缓存策略**：同一用户同类交易在5分钟内复用LLM结果，减少95%的LLM调用量。

3. **熔断机制**：当LLM服务不可用时，自动降级为纯规则引擎模式——宁可略高误杀率，绝不放过一笔。

4. **人工反馈闭环**：每次人工审核的结论会反哺训练数据，LLM的Prompt模板每周基于最新欺诈案例更新一次。

## 六、总结

"LLM + 规则引擎"不是替代关系，而是互补关系。规则引擎负责"确定性拦截"，LLM负责"模糊识别"，两者的结合让风控系统从"火车站安检"进化到"机场安检"——既不会放过高风险案例，也不会给正常用户带来过度打扰。

风控的本质是"在不确定中寻找确定"，而LLM正是处理不确定性最好的工具。
