# AI 客服机器人：意图识别 + 多轮填槽 + 人工无缝接管，用户根本分不清是AI还是人

## 一、中国客服行业的"三高三低"

中国客服行业有一个著名的"三高三低"：**离职率高（年均50%+）、培训成本高、情绪管理成本高；满意度低、问题解决率低、职业成就感低。**

一个成熟的电商客服团队，每天要处理500+条咨询，其中80%是反复出现的标准化问题：
- "什么时候发货？"
- "我的快递到哪了？"
- "这个东西能退吗？"
- "有优惠券吗？"

这些问题不需要人类智慧，但占用了客服80%的精力。真正的挑战是那20%需要人类判断的复杂问题——而当AI能够完美搞定前80%时，剩下的20%才需要人类"出手"。

本文将展示如何构建一套完整的AI客服系统，核心包括三大能力：**意图识别、多轮填槽、人工无缝接管**。系统上线后，80%的咨询全自动处理，20%复杂问题零感知转人工。

## 二、行业痛点

### 客服行业的"不可能三角"

客服行业长期面临一个不可能三角：**质量好、响应快、成本低——三者只能取其二。** 雇大量客服→成本高但质量好；用外包→成本低但质量差；用传统机器人→响应快但体验差。

AI客服的目标是打破这个三角——用LLM的能力同时做到：质量堪比高级客服、响应速度毫秒级、成本是人工的1/10。

实现这个目标有三个关键技术挑战：

**痛点一：意图识别不准**

传统客服机器人用关键词匹配来判断意图。用户说"怎么还没收到"，匹配到"收到"关键词 → 判断为"已签收确认"。但用户实际想问的是"催快递"。

**痛点二：多轮对话断裂**

传统机器人一问一答，无法处理需要多个信息的场景。用户说"我想退货"，机器人需要收集：订单号、退货原因、商品状态……这需要多轮"填槽"能力。

**痛点三：转人工体验差**

传统方案是机器人无法回答时弹出一个"转人工点击这里"的按钮。用户的情况、上下文、进度全部丢失，人工客服要从头问起——这是最让用户抓狂的体验。

### 4.1 意图识别引擎

```java
@Service
public class IntentRecognitionEngine {

    @Autowired
    private ChatLanguageModel chatModel;

    @Autowired
    private EmbeddingModel embeddingModel;

    @Autowired
    private VectorStore vectorStore;

    // 预定义的意图类别及其典型问法(存储在向量库中)
    private static final List<String> INTENT_CATEGORIES = List.of(
        "ORDER_STATUS",    // 查询订单状态
        "DELIVERY_QUERY",  // 物流查询
        "RETURN_EXCHANGE", // 退换货
        "REFUND_REQUEST",  // 退款申请
        "PRODUCT_INQUIRY", // 商品咨询
        "COUPON_DISCOUNT", // 优惠咨询
        "COMPLAINT",       // 投诉建议
        "ACCOUNT_HELP",    // 账户问题
        "CHITCHAT"         // 闲聊
    );

    /**
     * 识别用户消息的意图（支持置信度阈值）
     */
    public IntentResult recognize(String userMessage, String conversationHistory) {
        // 方式一：向量相似度快速匹配（低延迟，适合高频问法）
        IntentResult vectorResult = vectorMatch(userMessage);

        // 方式二：如果向量匹配置信度不足，降级到LLM判断
        if (vectorResult.getConfidence() < 0.7) {
            return llmRecognize(userMessage, conversationHistory);
        }

        return vectorResult;
    }

    private IntentResult vectorMatch(String message) {
        Embedding queryEmbedding = embeddingModel.embed(message).content();

        List<TextSegment> results = vectorStore.search(
                SearchRequest.builder()
                        .queryEmbedding(queryEmbedding)
                        .maxResults(3)
                        .minScore(0.75)
                        .build()
        ).matches().stream()
                .map(m -> m.embedded())
                .collect(Collectors.toList());

        if (results.isEmpty()) {
            return IntentResult.uncertain("LOW_CONFIDENCE", 0.0);
        }

        TextSegment bestMatch = results.get(0);
        double confidence = bestMatch.metadata().get("score") != null
                ? Double.parseDouble(bestMatch.metadata().get("score"))
                : 0.5;

        return IntentResult.of(bestMatch.metadata().get("intent"), confidence);
    }

    private IntentResult llmRecognize(String message, String history) {
        String prompt = String.format("""
            你是客服意图分类器。将用户消息分类到以下意图之一：
            - ORDER_STATUS: 查询订单状态/物流
            - RETURN_EXCHANGE: 退换货
            - REFUND: 退款
            - PRODUCT_INQUIRY: 商品咨询(功能/规格/用法)
            - COUPON: 优惠券/促销
            - COMPLAINT: 投诉
            - ACCOUNT: 账户/地址/信息修改
            - CHITCHAT: 闲聊/问候

            对话历史：%s

            用户消息：%s

            输出JSON：
            {"intent":"意图名","confidence":0.0-1.0,"entities":{"key":"value"},
             "sentiment":"positive/neutral/negative/angry"}
            """, history, message);

        String response = chatModel.generate(prompt);
        return parseIntentResult(response);
    }

    private IntentResult parseIntentResult(String json) {
        try {
            String block = json.substring(json.indexOf('{'), json.lastIndexOf('}') + 1);
            JsonNode node = new ObjectMapper().readTree(block);
            return IntentResult.builder()
                    .intent(node.get("intent").asText())
                    .confidence(node.get("confidence").asDouble())
                    .entities(parseEntities(node.get("entities")))
                    .sentiment(node.get("sentiment").asText())
                    .build();
        } catch (Exception e) {
            return IntentResult.uncertain("PARSE_ERROR", 0.0);
        }
    }

    private Map<String, String> parseEntities(JsonNode entities) {
        Map<String, String> result = new HashMap<>();
        if (entities != null) {
            entities.fieldNames().forEachRemaining(f -> result.put(f, entities.get(f).asText()));
        }
        return result;
    }
}
```

### 4.2 多轮填槽引擎

```java
@Service
public class SlotFillingEngine {

    @Autowired
    private ChatLanguageModel chatModel;

    /**
     * 检查意图所需的槽位是否完整，缺失则生成追问
     */
    public SlotFillingResult process(IntentResult intent, Map<String, String> currentSlots,
                                       String userMessage, String sessionId) {
        // 获取当前意图所需的槽位定义
        List<SlotDefinition> requiredSlots = getRequiredSlots(intent.getIntent());

        // 从用户消息中提取已填充的实体
        Map<String, String> extractedEntities = extractEntities(userMessage, intent.getIntent());
        currentSlots.putAll(extractedEntities);

        // 找出缺失的槽位
        List<SlotDefinition> missingSlots = requiredSlots.stream()
                .filter(slot -> !currentSlots.containsKey(slot.getName()) || currentSlots.get(slot.getName()) == null)
                .collect(Collectors.toList());

        if (missingSlots.isEmpty()) {
            // 所有槽位已完整，可以执行业务逻辑
            return SlotFillingResult.complete(currentSlots);
        }

        // 生成追问消息
        SlotDefinition nextSlot = missingSlots.get(0);
        String followUp = generateFollowUpQuestion(nextSlot, currentSlots, userMessage);

        return SlotFillingResult.needMore(nextSlot, followUp, currentSlots, missingSlots.size());
    }

    /**
     * 定义各意图需要的槽位
     */
    private List<SlotDefinition> getRequiredSlots(String intent) {
        return switch (intent) {
            case "ORDER_STATUS" -> List.of(
                    SlotDefinition.required("orderId", "订单号", "请提供您的订单号，通常是字母+数字组合"),
                    SlotDefinition.optional("phoneLast4", "手机尾号", "为验证身份，请提供下单手机号后4位")
            );
            case "RETURN_EXCHANGE" -> List.of(
                    SlotDefinition.required("orderId", "订单号", "请提供要退换的订单号"),
                    SlotDefinition.required("reason", "原因", "请简单描述退换原因（如质量问题/大小不合适等）"),
                    SlotDefinition.required("returnType", "方式", "您希望退货退款还是换货？"),
                    SlotDefinition.optional("evidence", "凭证", "如果有质量问题，可以提供照片吗？")
            );
            case "REFUND" -> List.of(
                    SlotDefinition.required("orderId", "订单号", "请提供需要退款的订单号"),
                    SlotDefinition.required("reason", "原因", "请描述退款原因"),
                    SlotDefinition.optional("amount", "金额", "退款金额是多少？")
            );
            case "PRODUCT_INQUIRY" -> List.of(
                    SlotDefinition.required("productName", "商品名称", "请问您想了解哪个商品？"),
                    SlotDefinition.optional("aspect", "具体方面", "您想了解商品的哪个方面？（如尺寸/材质/功能）")
            );
            default -> List.of();
        };
    }

    /**
     * 从用户消息中提取实体（复用意图识别时已提取的实体 + 增加提取）
     */
    private Map<String, String> extractEntities(String message, String intent) {
        Map<String, String> entities = new HashMap<>();

        // 正则提取常见实体
        Matcher orderMatcher = Pattern.compile("\\b([A-Za-z0-9]{10,30})\\b").matcher(message);
        if (orderMatcher.find()) {
            entities.put("orderId", orderMatcher.group(1));
        }

        Matcher phoneMatcher = Pattern.compile("(\\d{4})$").matcher(message);
        if (phoneMatcher.find()) {
            entities.put("phoneLast4", phoneMatcher.group(1));
        }

        // 用LLM提取更复杂的实体
        if (entities.size() < 2) {
            String prompt = String.format("""
                从用户消息中提取实体。
                意图：%s
                消息：%s
                输出JSON：
                {"entities": {"entityName": "value"}}
                """, intent, message);

            String response = chatModel.generate(prompt);
            try {
                String json = response.substring(response.indexOf('{'), response.lastIndexOf('}') + 1);
                JsonNode node = new ObjectMapper().readTree(json);
                JsonNode entityNode = node.get("entities");
                if (entityNode != null) {
                    entityNode.fieldNames().forEachRemaining(f ->
                            entities.putIfAbsent(f, entityNode.get(f).asText()));
                }
            } catch (Exception ignored) {}
        }

        return entities;
    }

    /**
     * 生成自然追问——不是冷冰冰的"请输入订单号"，而是自然的对话
     */
    private String generateFollowUpQuestion(SlotDefinition slot,
                                               Map<String, String> filledSlots,
                                               String userMessage) {
        return chatModel.generate(String.format("""
            你是友好的电商客服。用户正在申请%s，需要收集以下信息。
            已收集到的信息：%s
            当前缺少：%s（%s）
            用户刚说：%s

            请用自然的对话方式向用户询问缺失的信息。
            要求：
            1. 语气亲切自然，不要像审问
            2. 先表示已理解用户需求
            3. 再平滑地引出问题
            4. 如果用户感到困惑，给出示例
            """, filledSlots.getOrDefault("intent", "服务"),
                filledSlots.isEmpty() ? "暂无" : filledSlots.toString(),
                slot.getName(), slot.getDescription(),
                userMessage));
    }
}

@Data
@AllArgsConstructor
class SlotDefinition {
    private String name;
    private String description;
    private String promptTemplate;
    private boolean required;

    public static SlotDefinition required(String name, String desc, String prompt) {
        return new SlotDefinition(name, desc, prompt, true);
    }

    public static SlotDefinition optional(String name, String desc, String prompt) {
        return new SlotDefinition(name, desc, prompt, false);
    }
}
```

### 4.3 人工无缝接管

```java
@Service
public class HumanHandoffService {

    @Autowired
    private RedisTemplate<String, ConversationContext> redisTemplate;

    /**
     * 判断是否需要转人工
     */
    public HandoffDecision shouldHandoff(IntentResult intent, SlotFillingResult slotResult,
                                           String sessionId, ConversationContext context) {
        // 规则1：意图置信度过低 → 转人工
        if (intent.getConfidence() < 0.4) {
            return HandoffDecision.transfer("LOW_CONFIDENCE",
                    "抱歉，我没太理解您的需求，正在为您转接人工客服...");
        }

        // 规则2：用户情绪愤怒 → 转人工
        if ("angry".equals(intent.getSentiment())) {
            return HandoffDecision.transfer("ANGRY_CUSTOMER",
                    "非常抱歉给您带来不好的体验！我马上为您转接高级客服专员处理。");
        }

        // 规则3：投诉类 → 转人工
        if ("COMPLAINT".equals(intent.getIntent()) && context.getHandoffCount() == 0) {
            return HandoffDecision.transfer("COMPLAINT_ESCALATION",
                    "您的问题我已经记录，正在为您转接投诉专员。");
        }

        // 规则4：填槽失败超过3轮 → 转人工
        if (context.getFillAttempts() > 3 && !slotResult.isComplete()) {
            return HandoffDecision.transfer("SLOT_FILLING_FAILED",
                    "信息收集遇到了一些困难，我帮您转接人工客服，他们会更快地帮您解决。");
        }

        return HandoffDecision.continueAI();
    }

    /**
     * 执行转人工——保留完整上下文
     */
    public HandoffContext performHandoff(String sessionId, ConversationContext context,
                                           HandoffDecision decision) {
        // 1. 将对话上下文序列化为结构化摘要
        String handoffSummary = chatModel.generate(String.format("""
            将以下客服对话总结为给人工客服的移交摘要（100字以内）：

            用户意图：%s
            安抚状态：%s
            已解决问题：%s
            待解决问题：%s
            用户信息：%s
            对话历史：%s

            格式：直接输出摘要文本
            """, context.getCurrentIntent(), context.getSentiment(),
                context.getResolvedItems(), context.getPendingItems(),
                context.getUserInfo(), context.getConversationSummary()));

        // 2. 将上下文保存，分配人工客服
        HandoffContext handoff = HandoffContext.builder()
                .sessionId(sessionId)
                .handoffReason(decision.getReason())
                .summary(handoffSummary)
                .conversationHistory(context.getMessages())
                .filledSlots(context.getCollectedSlots())
                .handoffTime(LocalDateTime.now())
                .build();

        // 3. 存入Redis，人工客服侧读取
        redisTemplate.opsForValue().set("handoff:" + sessionId, handoff, Duration.ofHours(2));

        // 4. 通知人工客服队列
        notifyHumanAgent(sessionId, handoffSummary, decision.getPriority());

        return handoff;
    }

    private void notifyHumanAgent(String sessionId, String summary, int priority) {
        // 接入客服系统的派单逻辑
        log.info("Dispatching session {} to human agent. Priority: {}. Summary: {}",
                sessionId, priority, summary);
    }
}
```

### 4.4 完整的对话编排

```java
@Service
public class CustomerServiceOrchestrator {

    @Autowired
    private IntentRecognitionEngine intentEngine;

    @Autowired
    private SlotFillingEngine slotEngine;

    @Autowired
    private HumanHandoffService handoffService;

    @Autowired
    private ChatLanguageModel chatModel;

    /**
     * 处理单轮对话的全流程
     */
    public BotResponse handleMessage(String sessionId, String userMessage) {
        ConversationContext context = loadContext(sessionId);

        // Step 1: 意图识别
        IntentResult intent = intentEngine.recognize(userMessage,
                context.getConversationSummary());
        context.setCurrentIntent(intent.getIntent());
        context.setSentiment(intent.getSentiment());

        // Step 2: 情绪安抚（如检测到负面情绪）
        if ("angry".equals(intent.getSentiment()) || "negative".equals(intent.getSentiment())) {
            String calming = generateCalmingResponse(userMessage, intent);
            context.addMessage("assistant", calming);
            saveContext(sessionId, context);
            return BotResponse.of(calming, intent);
        }

        // Step 3: 多轮填槽
        SlotFillingResult slotResult = slotEngine.process(
                intent, context.getCollectedSlots(), userMessage, sessionId);
        context.setCollectedSlots(slotResult.getCurrentSlots());
        context.setFillAttempts(context.getFillAttempts() + 1);

        // Step 4: 检查是否需要转人工
        HandoffDecision handoffDecision = handoffService.shouldHandoff(
                intent, slotResult, sessionId, context);

        if (handoffDecision.isTransfer()) {
            HandoffContext handoff = handoffService.performHandoff(sessionId, context, handoffDecision);
            context.setHandedOff(true);
            saveContext(sessionId, context);
            return BotResponse.handoff(handoffDecision.getTransferMessage(), handoff);
        }

        // Step 5: 槽位不完整，返回追问
        if (!slotResult.isComplete()) {
            String followUp = slotResult.getFollowUpQuestion();
            context.addMessage("assistant", followUp);
            saveContext(sessionId, context);
            return BotResponse.of(followUp, intent);
        }

        // Step 6: 槽位完整，执行业务操作或生成答案
        String answer = executeBusinessLogic(intent.getIntent(), slotResult.getCollectedSlots());
        context.addMessage("assistant", answer);
        saveContext(sessionId, context);

        return BotResponse.of(answer, intent);
    }

    /**
     * 执行业务逻辑（调用后端API）
     */
    private String executeBusinessLogic(String intent, Map<String, String> slots) {
        return switch (intent) {
            case "ORDER_STATUS" -> {
                String orderId = slots.get("orderId");
                Order order = orderRepo.findByOrderId(orderId);
                yield String.format("您的订单[%s]当前状态：%s，预计%s送达。",
                        orderId, order.getStatus(), order.getEstimatedDelivery());
            }
            case "RETURN_EXCHANGE" -> {
                String result = returnService.initiateReturn(
                        slots.get("orderId"), slots.get("reason"), slots.get("returnType"));
                yield result;
            }
            default -> chatModel.generate("根据以下信息生成客服回复：" + slots.toString());
        };
    }
}
```

### 三个容易踩的坑

**坑一：意图分类不要贪多。** 初版设计时团队往往想把所有可能的意图都定义出来，结果分类体系臃肿、边界模糊、LLM判断困难。建议从5-8个核心意图开始，上线后根据真实数据逐步扩展。我们的经验：8个核心意图覆盖了93%的咨询，剩下的7%走"其他"→人工接管。

**坑二：填槽追问要有"退出机制"。** 如果用户在3轮追问后仍无法提供信息（比如就是找不到订单号），不要死追——给一个降级方案（"用收货手机号也可以查询"）或直接转人工。无休止的追问是用户最讨厌的bot体验。

**坑三：转人工时的"冷启动"问题。** 人工客服接到转接后，如果要从头了解情况，体验依然很差。核心是传递"结构化摘要"而非"原始对话记录"——一句话告诉人工客服：用户是谁、遇到了什么问题、AI已经做了哪些尝试。我们实测：有结构化摘要的转接，人工客服处理时间缩短了60%。

## 六、总结

AI客服的终极形态不是"取代人类"，而是让AI处理80%的标准化问题，让人类专注于20%需要同理心和复杂判断的场景。三招定胜负——意图识别要准，多轮填槽要顺，转人工要无缝——缺一不可。

这个架构不只适用于电商客服。银行客服（开户流程引导）、政务客服（办事指南）、教育客服（选课咨询）——任何涉及"从用户对话中收集信息并完成业务操作"的场景都可以复用这套"意图识别+多轮填槽+人工接管"的三段式架构。本质上是将非结构化的自然语言映射到结构化的业务流程，而LLM是这个映射过程最好的"翻译器"。
