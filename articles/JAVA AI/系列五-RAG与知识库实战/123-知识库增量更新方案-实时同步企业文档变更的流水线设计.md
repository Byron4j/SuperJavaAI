# 知识库增量更新方案：实时同步企业文档变更的流水线设计，新文档上传后 30 秒可检索

> 你有没有遇到过这种情况——业务方下午 3 点上传了一份新的产品手册，结果 AI 客服直到晚上 8 点还在回答"查不到相关信息"。业务方炸了，CTO 也炸了。

---

## 一、开篇：全量重建之痛

在 RAG 系统落地的初期，几乎所有团队都会采用一种"简单粗暴"的更新策略——定时全量重建：

```java
@Scheduled(cron = "0 0 2 * * ?") // 每天凌晨2点
public void fullRebuildIndex() {
    // 1. 删除整个向量库
    vectorStore.dropIndex();
    // 2. 重新读取全部文档
    List<Document> allDocs = documentRepository.findAll();
    // 3. 重新分块+向量化+写入
    for (Document doc : allDocs) {
        List<Chunk> chunks = chunker.split(doc);
        List<float[]> embeddings = embeddingService.embed(chunks);
        vectorStore.insert(chunks, embeddings);
    }
}
```

这套方案在文档量小的时候完全没问题。但当你的知识库增长到以下规模，噩梦就开始了：

- **10 万份文档、500 万个 Chunk：** 全量重建需要 4-6 小时
- **API 调用成本：** 每次重建，embedding API 费用轻松上千
- **服务中断：** 重建期间索引处于"空白"状态，检索返回空
- **一致性黑洞：** 凌晨 2 点到第二天早上 8 点之间上传的文档，要等 24 小时才可检索

更糟糕的是——你在重建期间改了一个 typo，用户搜到的是旧版本的答案，你还以为是 LLM"幻觉"了。

**增量更新不是可选的优化，而是生产级 RAG 系统的刚需。**

本文将从变更检测、增量处理、旧数据清理三个方面，给出完整的 Spring Boot 增量更新方案。

## 三、变更检测方案（三种模式对比）

### 3.1 方案一：文件系统监听（适合本地/SMB/NFS）

```java
@Component
@Slf4j
public class FileSystemWatcherService {
    
    private final WatchService watchService;
    private final Map<WatchKey, Path> keyPathMap = new ConcurrentHashMap<>();
    private final DocumentChangePublisher publisher;
    
    @PostConstruct
    public void init() throws IOException {
        watchService = FileSystems.getDefault().newWatchService();
        
        // 递归注册所有子目录
        Path rootPath = Paths.get(config.getDocumentRoot());
        Files.walk(rootPath)
            .filter(Files::isDirectory)
            .forEach(dir -> register(dir));
        
        // 启动监听线程
        Thread watcherThread = new Thread(this::processEvents, "file-watcher");
        watcherThread.setDaemon(true);
        watcherThread.start();
    }
    
    private void register(Path dir) {
        try {
            WatchKey key = dir.register(watchService,
                StandardWatchEventKinds.ENTRY_CREATE,
                StandardWatchEventKinds.ENTRY_MODIFY,
                StandardWatchEventKinds.ENTRY_DELETE);
            keyPathMap.put(key, dir);
            log.info("Watching directory: {}", dir);
        } catch (IOException e) {
            log.error("Failed to register watch on: {}", dir, e);
        }
    }
    
    private void processEvents() {
        while (true) {
            WatchKey key;
            try {
                key = watchService.take(); // 阻塞直到有事件
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                break;
            }
            
            Path dir = keyPathMap.get(key);
            if (dir == null) continue;
            
            for (WatchEvent<?> event : key.pollEvents()) {
                WatchEvent.Kind<?> kind = event.kind();
                
                // 忽略 OVERFLOW 事件
                if (kind == StandardWatchEventKinds.OVERFLOW) continue;
                
                Path fileName = (Path) event.context();
                Path fullPath = dir.resolve(fileName);
                
                // 去重：短时间内同一文件的重复事件
                if (isDuplicateEvent(fullPath, kind)) continue;
                
                DocumentChangeEvent changeEvent = DocumentChangeEvent.builder()
                    .filePath(fullPath.toString())
                    .changeType(mapChangeType(kind))
                    .timestamp(Instant.now())
                    .fileSize(getFileSize(fullPath))
                    .md5Hash(computeMD5(fullPath))
                    .build();
                
                publisher.publish(changeEvent);
                log.info("File change detected: {} -> {}", fullPath, kind);
            }
            
            boolean valid = key.reset();
            if (!valid) {
                keyPathMap.remove(key);
                // 目录被删除，停止监听
                if (keyPathMap.isEmpty()) break;
            }
        }
    }
    
    private Map<String, Instant> recentEvents = new ConcurrentHashMap<>();
    
    private boolean isDuplicateEvent(Path path, WatchEvent.Kind<?> kind) {
        String key = path.toString() + kind.name();
        Instant lastTime = recentEvents.get(key);
        Instant now = Instant.now();
        
        if (lastTime != null && Duration.between(lastTime, now).getSeconds() < 2) {
            return true; // 2秒内的重复事件视为重复
        }
        
        recentEvents.put(key, now);
        return false;
    }
}
```

**注意 WatchService 的几个坑：**

1. **OS 限制：** macOS 上 inotify 数量有限制，Linux 上也受 `/proc/sys/fs/inotify/max_user_watches` 限制
2. **原子写入问题：** 很多编辑器（如 vim）的保存方式是"写临时文件 → 重命名"，会产生 CREATE 而非 MODIFY 事件
3. **去重：** 大文件保存可能触发多次 MODIFY 事件，必须去重

```java
@Component
public class CanalDocumentListener {
    
    @PostConstruct
    public void init() {
        CanalConnector connector = CanalConnectors.newSingleConnector(
            new InetSocketAddress("127.0.0.1", 11111),
            "example", "", "");
        
        connector.connect();
        connector.subscribe("rag_db\\.documents");
        
        Thread canalThread = new Thread(() -> {
            while (true) {
                Message message = connector.getWithoutAck(1000);
                long batchId = message.getId();
                
                for (CanalEntry.Entry entry : message.getEntries()) {
                    if (entry.getEntryType() != CanalEntry.EntryType.ROWDATA) continue;
                    
                    CanalEntry.RowChange rowChange = CanalEntry.RowChange.parseFrom(
                        entry.getStoreValue());
                    
                    for (CanalEntry.RowData rowData : rowChange.getRowDatasList()) {
                        DocumentChangeEvent event = buildEvent(rowChange.getEventType(), rowData);
                        publisher.publish(event);
                    }
                }
                connector.ack(batchId);
            }
        }, "canal-listener");
        canalThread.setDaemon(true);
        canalThread.start();
    }
    
    private DocumentChangeEvent buildEvent(CanalEntry.EventType eventType, CanalEntry.RowData rowData) {
        return DocumentChangeEvent.builder()
            .changeType(mapCanalEventType(eventType))
            .documentId(getFieldValue(rowData, "id"))
            .filePath(getFieldValue(rowData, "file_path"))
            .fileHash(getFieldValue(rowData, "md5_hash"))
            .timestamp(Instant.now())
            .sourceType("DATABASE")
            .build();
    }
}
```

### 3.3 方案三：定时轮询（兜底方案）

```java
@Component
public class PollingChangeDetector {
    
    @Scheduled(fixedDelayString = "${rag.sync.poll-interval:30000}") // 默认30秒
    public void pollChanges() {
        // 查询上次同步时间之后有变更的文档
        Instant lastSyncTime = getLastSyncTime();
        
        List<Document> changedDocs = documentRepository
            .findByUpdatedAtAfter(lastSyncTime);
        
        for (Document doc : changedDocs) {
            DocumentChangeEvent event = DocumentChangeEvent.builder()
                .changeType(ChangeType.UPDATE)
                .documentId(doc.getId())
                .filePath(doc.getFilePath())
                .fileHash(doc.getMd5Hash())
                .timestamp(Instant.now())
                .sourceType("POLLING")
                .build();
            
            publisher.publish(event);
        }
        
        // 更新最后同步时间
        updateLastSyncTime(Instant.now());
    }
}
```

## 四、增量向量化处理引擎

### 4.1 核心处理流程

```java
@Service
@Slf4j
public class DeltaIngestionProcessor {
    
    private final DocumentProcessingPipeline pipeline;
    private final EmbeddingService embeddingService;
    private final VectorStore vectorStore;
    private final MetadataRepository metadataRepository;
    private final OldVectorCleanupService cleanupService;
    
    @KafkaListener(topics = "document-change-events", groupId = "rag-delta-processor")
    public void processChangeEvent(DocumentChangeEvent event) {
        log.info("Processing change event: documentId={}, type={}", 
            event.getDocumentId(), event.getChangeType());
        
        try {
            switch (event.getChangeType()) {
                case CREATE -> handleCreate(event);
                case UPDATE -> handleUpdate(event);
                case DELETE -> handleDelete(event);
                case RENAME -> handleRename(event);
            }
        } catch (Exception e) {
            log.error("Failed to process change event: {}", event, e);
            // 发送到死信队列，人工介入
            deadLetterPublisher.publish(event, e);
        }
    }
    
    private void handleCreate(DocumentChangeEvent event) {
        // 1. 读取文档内容
        RawDocument raw = readDocument(event);
        
        // 2. 预处理管道
        ProcessedDocument processed = pipeline.execute(raw);
        
        // 3. 分块
        List<Chunk> chunks = chunker.split(processed.getContent());
        
        // 4. 向量化
        List<float[]> embeddings = embeddingService.embedBatch(chunks);
        
        // 5. 写入向量库
        vectorStore.insertBatch(chunks, embeddings, processed.getMetadata());
        
        // 6. 写入元数据库
        metadataRepository.insert(processed.getMetadata());
        
        log.info("Document created: {}, chunks: {}", 
            event.getDocumentId(), chunks.size());
    }
    
    private void handleUpdate(DocumentChangeEvent event) {
        String documentId = event.getDocumentId();
        
        // 1. 通过 MD5 判断内容是否真的变了
        String oldHash = metadataRepository.getContentHash(documentId);
        if (oldHash != null && oldHash.equals(event.getMd5Hash())) {
            log.info("Document unchanged (same MD5), skipping: {}", documentId);
            return;
        }
        
        // 2. 获取旧 Chunk ID 列表
        List<String> oldChunkIds = metadataRepository.getChunkIds(documentId);
        
        // 3. 处理新文档
        RawDocument raw = readDocument(event);
        ProcessedDocument processed = pipeline.execute(raw);
        List<Chunk> newChunks = chunker.split(processed.getContent());
        List<float[]> newEmbeddings = embeddingService.embedBatch(newChunks);
        
        // 4. 在事务中原子替换
        transactionTemplate.execute(status -> {
            // 先写新的
            List<String> newChunkIds = vectorStore.insertBatch(
                newChunks, newEmbeddings, processed.getMetadata());
            
            // 更新元数据
            metadataRepository.updateChunkMapping(documentId, newChunkIds);
            
            // 再删旧的（在这之前搜索结果仍指向旧 Chunk）
            cleanupService.scheduleCleanup(oldChunkIds, 
                Duration.ofMinutes(5)); // 5分钟后清理
            
            return null;
        });
        
        log.info("Document updated: {}, old chunks: {}, new chunks: {}", 
            documentId, oldChunkIds.size(), newChunks.size());
    }
    
    private void handleDelete(DocumentChangeEvent event) {
        String documentId = event.getDocumentId();
        
        // 1. 删除向量
        List<String> chunkIds = metadataRepository.getChunkIds(documentId);
        vectorStore.deleteBatch(chunkIds);
        
        // 2. 删除元数据
        metadataRepository.delete(documentId);
        
        log.info("Document deleted: {}, chunks removed: {}", 
            documentId, chunkIds.size());
    }
}
```

### 4.2 批量处理与背压控制

```java
@Component
public class BatchDeltaProcessor {
    
    private final BlockingQueue<DocumentChangeEvent> eventBuffer 
        = new LinkedBlockingQueue<>(10000);
    private final ScheduledExecutorService scheduler 
        = Executors.newSingleThreadScheduledExecutor();
    
    @PostConstruct
    public void init() {
        // 每2秒批量处理一次，或积压超过100条时立即处理
        scheduler.scheduleWithFixedDelay(this::processBatch, 0, 2, TimeUnit.SECONDS);
    }
    
    public void enqueue(DocumentChangeEvent event) {
        if (!eventBuffer.offer(event)) {
            // 队列满了，触发反压
            log.warn("Event buffer full, applying backpressure");
            // 可以触发告警或限流上游
            throw new BackpressureException("Delta processor overloaded");
        }
    }
    
    private void processBatch() {
        List<DocumentChangeEvent> batch = new ArrayList<>(200);
        eventBuffer.drainTo(batch, 200);
        
        if (batch.isEmpty()) return;
        
        // 合并同一文档的多次变更
        Map<String, DocumentChangeEvent> merged = batch.stream()
            .collect(Collectors.toMap(
                DocumentChangeEvent::getDocumentId,
                Function.identity(),
                (a, b) -> b // 保留最新的事件
            ));
        
        // 并行处理，控制并发度
        ExecutorService executor = Executors.newFixedThreadPool(4);
        try {
            List<CompletableFuture<Void>> futures = merged.values().stream()
                .map(event -> CompletableFuture.runAsync(
                    () -> deltaProcessor.processChangeEvent(event), executor))
                .toList();
            
            CompletableFuture.allOf(futures.toArray(new CompletableFuture[0]))
                .get(30, TimeUnit.SECONDS);
                
        } catch (TimeoutException e) {
            log.error("Batch processing timed out, {} events unprocessed", 
                merged.size() - countCompleted(futures));
        }
    }
}
```

## 五、旧向量清理策略

### 5.1 为什么不是"先删后写"

很多人的第一反应是"更新文档时，先删除旧 Chunk，再写入新 Chunk"。但这有个致命问题：

```
时间线：
T1: 用户搜索 → 触发旧 Chunk 删除 → 新 Chunk 还没写入
T2: 搜索结果为空！
T3: 新 Chunk 写入完成
```

在 T1-T3 之间，检索结果会短暂丢失。所以必须采用**先写后删**策略：

```java
@Component
public class OldVectorCleanupService {
    
    /**
     * 调度旧向量清理任务
     * @param oldChunkIds 需要清理的旧 Chunk ID
     * @param delay 延迟时间（给缓存预热和未完成的查询留缓冲）
     */
    public void scheduleCleanup(List<String> oldChunkIds, Duration delay) {
        scheduler.schedule(() -> {
            try {
                vectorStore.deleteBatch(oldChunkIds);
                log.info("Old vectors cleaned up: {} chunks", oldChunkIds.size());
            } catch (Exception e) {
                log.error("Failed to clean up old vectors, will retry", e);
                // 重试机制
                scheduleCleanup(oldChunkIds, delay.multipliedBy(2));
            }
        }, delay.toSeconds(), TimeUnit.SECONDS);
    }
    
    /**
     * 定时扫描"孤儿 Chunk"（元数据中已删除但向量库中仍存在的）
     */
    @Scheduled(cron = "0 0 3 * * ?")
    public void orphanCleanup() {
        // 从向量库获取所有 Chunk ID
        Set<String> vectorChunkIds = vectorStore.getAllChunkIds();
        
        // 从元数据库获取所有有效 Chunk ID
        Set<String> validChunkIds = metadataRepository.getAllValidChunkIds();
        
        // 找出孤儿
        Set<String> orphanIds = new HashSet<>(vectorChunkIds);
        orphanIds.removeAll(validChunkIds);
        
        if (!orphanIds.isEmpty()) {
            log.warn("Found {} orphan vectors, cleaning up...", orphanIds.size());
            vectorStore.deleteBatch(new ArrayList<>(orphanIds));
        }
    }
}
```

### 5.2 向量库操作封装

```java
@Service
public class ElasticsearchVectorStore implements VectorStore {
    
    private final RestHighLevelClient esClient;
    
    @Override
    public List<String> insertBatch(List<Chunk> chunks, 
                                     List<float[]> embeddings,
                                     Map<String, Object> metadata) {
        BulkRequest bulkRequest = new BulkRequest();
        
        for (int i = 0; i < chunks.size(); i++) {
            Chunk chunk = chunks.get(i);
            float[] embedding = embeddings.get(i);
            
            Map<String, Object> doc = new HashMap<>();
            doc.put("chunk_id", chunk.getId());
            doc.put("document_id", chunk.getDocumentId());
            doc.put("chunk_index", chunk.getIndex());
            doc.put("content", chunk.getContent());
            doc.put("embedding", floatArrayToDoubleList(embedding));
            doc.put("metadata", metadata);
            
            IndexRequest indexRequest = new IndexRequest("rag_chunks")
                .id(chunk.getId())
                .source(doc);
            
            bulkRequest.add(indexRequest);
        }
        
        try {
            BulkResponse response = esClient.bulk(bulkRequest, RequestOptions.DEFAULT);
            
            if (response.hasFailures()) {
                throw new VectorStoreException("Bulk insert has failures: " + 
                    response.buildFailureMessage());
            }
            
            esClient.indices().refresh(
                new RefreshRequest("rag_chunks"), RequestOptions.DEFAULT);
            
            return chunks.stream().map(Chunk::getId).toList();
            
        } catch (IOException e) {
            throw new VectorStoreException("Failed to insert vectors", e);
        }
    }
    
    @Override
    public void deleteBatch(List<String> chunkIds) {
        BulkRequest bulkRequest = new BulkRequest();
        
        for (String id : chunkIds) {
            bulkRequest.add(new DeleteRequest("rag_chunks", id));
        }
        
        try {
            esClient.bulk(bulkRequest, RequestOptions.DEFAULT);
        } catch (IOException e) {
            throw new VectorStoreException("Failed to delete vectors", e);
        }
    }
}
```

## 六、一致性保证机制

### 6.1 版本号机制

```java
@Entity

    private SyncStatus syncStatus; // SYNCING, SYNCED, FAILED
}
```

```java
public enum SyncStatus {
    SYNCING,    // 正在同步（检索时会排除或降权）
    SYNCED,     // 同步完成
    STALE,      // 过期（源文档已更新但尚未同步）
    FAILED      // 同步失败（需人工介入）
}
```

### 6.2 检索时的版本过滤

```java
@Service
public class SearchService {
    
    public SearchResult search(SearchRequest request) {
        BoolQueryBuilder boolQuery = QueryBuilders.boolQuery();
        
        // ... 其他查询条件 ...
        
        // 过滤掉正在同步的文档（避免返回不一致的结果）
        boolQuery.mustNot(QueryBuilders.termQuery(
            "metadata.sync_status", SyncStatus.SYNCING.name()));
        
        // 对于 STALE 状态的文档，降低权重
        FunctionScoreQueryBuilder functionScore = QueryBuilders
            .functionScoreQuery(boolQuery, new FunctionScoreQueryBuilder.FilterFunctionBuilder[]{
                new FunctionScoreQueryBuilder.FilterFunctionBuilder(
                    QueryBuilders.termQuery("metadata.sync_status", SyncStatus.STALE.name()),
                    ScoreFunctionBuilders.weightFactorFunction(0.5f))
            });
        
        // 执行检索...
    }
}
```

```yaml
    # 旧向量清理
    cleanup:
      delay-minutes: 5
      orphan-scan-cron: "0 0 3 * * ?"
      max-retry: 3

  # Kafka 配置
  kafka:
    document-change-topic: document-change-events
    dead-letter-topic: document-change-dlq
    consumer-group: rag-delta-processor
```

### 完整服务启动类

```java
@SpringBootApplication
@EnableScheduling
@EnableAsync
public class RAGDeltaSyncApplication {
    
    public static void main(String[] args) {
        SpringApplication.run(RAGDeltaSyncApplication.class, args);
    }
    
    @Bean
    public DeltaSyncOrchestrator orchestrator(
            List<ChangeDetector> detectors,
            DeltaIngestionProcessor processor,
            OldVectorCleanupService cleanupService) {
        return new DeltaSyncOrchestrator(detectors, processor, cleanupService);
    }
}

@Service
@Slf4j
public class DeltaSyncOrchestrator {
    
    private final List<ChangeDetector> detectors;
    private final DeltaIngestionProcessor processor;
    private final OldVectorCleanupService cleanupService;
    
    @EventListener(ApplicationReadyEvent.class)
    public void start() {
        log.info("Starting Delta Sync Orchestrator with {} detectors", detectors.size());
        
        for (ChangeDetector detector : detectors) {
            if (detector.isEnabled()) {
                detector.start();
                log.info("ChangeDetector [{}] started", detector.getName());
            }
        }
    }
    
    @PreDestroy
    public void stop() {
        for (ChangeDetector detector : detectors) {
            detector.stop();
        }
    }
}
```

```java
@Component
public class DeltaSyncMetrics {
    
    private final MeterRegistry meterRegistry;
    
    private final Counter totalEventsCounter;
    private final Counter successEventsCounter;
    private final Counter failedEventsCounter;
    private final Timer processingTimer;
    private final Gauge queueDepth;
    
    public DeltaSyncMetrics(MeterRegistry meterRegistry, 
                            BatchDeltaProcessor processor) {
        this.meterRegistry = meterRegistry;
        
        this.totalEventsCounter = Counter.builder("rag.delta.events.total")
            .description("Total number of delta events received")
            .register(meterRegistry);
        
        this.successEventsCounter = Counter.builder("rag.delta.events.success")
            .register(meterRegistry);
        
        this.failedEventsCounter = Counter.builder("rag.delta.events.failed")
            .register(meterRegistry);
        
        this.processingTimer = Timer.builder("rag.delta.processing.time")
            .register(meterRegistry);
        
        this.queueDepth = Gauge.builder("rag.delta.queue.depth", 
                processor, p -> p.getEventBufferSize())
            .register(meterRegistry);
    }
    
    public void recordSuccess(DocumentChangeEvent event, long durationMs) {
        successEventsCounter.increment();
        processingTimer.record(durationMs, TimeUnit.MILLISECONDS);
    }
    
    public void recordFailure(DocumentChangeEvent event) {
        failedEventsCounter.increment();
    }
}
```

## 九、总结

增量更新方案的核心思想只有一句话：**用事件驱动替代定时全量**。

回顾一下关键设计决策：

1. **多模式变更检测：** 文件监听+轮询+CDC 组合使用，互相兜底
2. **先写后删：** 更新时先写新 Chunk，延迟清理旧 Chunk，避免检索空白
3. **版本号+同步状态：** 检索时感知文档同步状态，过滤或降权未同步文档
4. **消息队列解耦：** 变更检测和增量处理之间通过 Kafka 解耦，支持削峰填谷
5. **孤儿清理：** 定时扫描孤儿向量，防止存储浪费

最终效果：**新文档上传后 30 秒内可检索，修改后 10 秒内生效，系统零停机。**
