## 二、为什么 LLM 调用特别需要缓存？

### 2.1 与普通 API 的本质区别

普通 REST API 的输入输出通常是结构化的、确定性的：

```java
// 普通API：确定性
GET /api/user/123  →  {id:123, name:"张三"}  // 每次一样

// LLM API：非确定性
POST /chat "你好吗？" → "很好！"  (第1次)
POST /chat "你好吗？" → "挺好的~"  (第2次，可能不同！)
```

LLM 的输出天生带有**随机性**（temperature 参数），这是缓存面临的最大挑战。

### 2.2 缓存带来的三大收益

| 收益维度 | 具体效果 |
|---------|---------|
| **成本** | 减少 30%~50% API 调用，直接省钱 |
| **延迟** | 缓存命中时响应 < 5ms，vs 调用 LLM 的 2~10 秒 |
| **稳定性** | 减少对 LLM API 的依赖，服务降级时有兜底 |

### 2.3 两种缓存策略

```
精确缓存（Exact Cache）
  ├── 条件：输入完全相同 → 输出相同
  ├── 适用：结构化任务（翻译、分类、格式化）
  └── 命中率：5%~20%（取决于业务）

语义缓存（Semantic Cache）
  ├── 条件：输入语义相似 → 输出相同
  ├── 适用：FAQ、客服、知识问答
  └── 命中率：30%~60%（取决于业务）
```

## 三、精确缓存：Redis 实现

精确缓存是最简单、最可靠的缓存方式。核心逻辑只有一行：

```
cacheKey = md5(question + modelName + temperature)
```

### 3.1 基础实现

```java
import org.springframework.data.redis.core.StringRedisTemplate;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.util.concurrent.TimeUnit;

@Service
public class ExactCacheService {

    private final StringRedisTemplate redisTemplate;
    
    // 缓存过期时间：1小时
    private static final long CACHE_TTL_MINUTES = 60;

    public ExactCacheService(StringRedisTemplate redisTemplate) {
        this.redisTemplate = redisTemplate;
    }

    /**
     * 获取缓存，未命中返回 null
     */
    public String get(String prompt, String model, double temperature) {
        String key = buildKey(prompt, model, temperature);
        return redisTemplate.opsForValue().get(key);
    }

    /**
     * 写入缓存
     */
    public void put(String prompt, String model, double temperature, String response) {
        String key = buildKey(prompt, model, temperature);
        redisTemplate.opsForValue().set(key, response, CACHE_TTL_MINUTES, TimeUnit.MINUTES);
    }

    /**
     * 构建缓存Key：MD5(prompt|model|temperature)
     */
    private String buildKey(String prompt, String model, double temperature) {
        String raw = prompt + "|" + model + "|" + temperature;
        String hash = md5(raw);
        return "llm:cache:exact:" + hash;
    }

    private String md5(String input) {
        try {
            MessageDigest md = MessageDigest.getInstance("MD5");
            byte[] digest = md.digest(input.getBytes(StandardCharsets.UTF_8));
            StringBuilder sb = new StringBuilder();
            for (byte b : digest) {
                sb.append(String.format("%02x", b));
            }
            return sb.toString();
        } catch (Exception e) {
            throw new RuntimeException("MD5计算失败", e);
        }
    }
}
```

## 四、语义缓存：Embedding 相似度匹配

精确缓存要求输入**完全相同**。但在客服场景中：

- "怎么请假？"
- "请假流程是什么？"
- "如何申请请假？"

这三个问题问的是同一件事，精确缓存无法命中。**语义缓存正是为此而生。**

### 4.1 核心原理

```
        用户问题
           │
           ▼
      Embedding向量化
           │
           ▼
     Redis向量检索
    （余弦相似度搜索）
           │
    相似度 > 0.95？

    ┌────Yes───┐
    ▼           ▼
  命中缓存    未命中，调用LLM
  返回结果    ──→ 写入缓存
```

### 4.2 Redis 存储 Embedding 向量

```java
import org.springframework.data.redis.core.StringRedisTemplate;
import redis.clients.jedis.search.FTCreateParams;
import redis.clients.jedis.search.Schema;
import redis.clients.jedis.search.SearchResult;
import redis.clients.jedis.search.Document;
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

@Service
public class SemanticCacheService {

    private final StringRedisTemplate redisTemplate;
    private final EmbeddingService embeddingService;
    
    private static final String INDEX_NAME = "idx:llm:semantic";
    private static final double SIMILARITY_THRESHOLD = 0.95;

    public SemanticCacheService(StringRedisTemplate redisTemplate, 
                                EmbeddingService embeddingService) {
        this.redisTemplate = redisTemplate;
        this.embeddingService = embeddingService;
        initIndex();
    }

    private void initIndex() {
        try {
            Schema schema = new Schema()
                .addTextField("question", 1.0)
                .addTextField("answer", 1.0)
                .addVectorField("embedding", Schema.VectorField.VectorAlgo.FLAT, 
                    Map.of(
                        "TYPE", "FLOAT32",
                        "DIM", 1536,   // OpenAI embedding 维度
                        "DISTANCE_METRIC", "COSINE"
                    ));

            redisTemplate.execute((org.springframework.data.redis.connection.RedisConnection conn) -> {
                conn.execute("FT.CREATE", (INDEX_NAME + " " + schema.toString()).getBytes());
                return null;
            });
        } catch (Exception e) {
            // 索引可能已存在
            log.warn("语义缓存索引初始化: {}", e.getMessage());
        }
    }

    /**
     * 语义缓存查询
     */
    public Optional<String> get(String question) {
        // 1. 将问题向量化
        List<Float> queryVector = embeddingService.embed(question);

        // 2. Redis 向量相似度搜索
        byte[] queryVectorBytes = floatListToBytes(queryVector);
        String query = String.format(
            "*=>[KNN 1 @embedding $vec AS score]",
            queryVectorBytes
        );

        try {
            List<Document> docs = redisTemplate.execute((conn) -> {
                // 执行向量搜索（简化版，实际建议使用RediSearch客户端）
                return List.of(); // 实际需要调用 RediSearch 命令
            });
            
            if (docs != null && !docs.isEmpty()) {
                Document doc = docs.get(0);
                Double score = (Double) doc.get("score");
                if (score != null && score >= SIMILARITY_THRESHOLD) {
                    return Optional.of((String) doc.get("answer"));
                }
            }
        } catch (Exception e) {
            log.warn("语义缓存查询失败: {}", e.getMessage());
        }
        return Optional.empty();
    }

     * 将问题+答案写入语义缓存
     */
    public void put(String question, String answer) {
        List<Float> vector = embeddingService.embed(question);
        String vectorStr = vector.stream()
            .map(String::valueOf)
            .collect(Collectors.joining(","));

        String docId = "semantic:" + System.nanoTime();
        Map<String, Object> fields = Map.of(
            "question", question,
            "answer", answer,
            "embedding", vectorStr
        );

        // 写入Redis（简化版）
    }

    private byte[] floatListToBytes(List<Float> floats) {
        // 将float列表转换为字节数组
        // 实际应使用ByteBuffer等
        return new byte[floats.size() * 4];
    }
}
```

### 4.4 余弦相似度计算

```java
public class SimilarityUtils {

    /**
     * 计算两个向量的余弦相似度
     */
    public static double cosineSimilarity(float[] vectorA, float[] vectorB) {
        double dotProduct = 0.0;
        double normA = 0.0;
        double normB = 0.0;

        for (int i = 0; i < vectorA.length; i++) {
            dotProduct += vectorA[i] * vectorB[i];
            normA += Math.pow(vectorA[i], 2);
            normB += Math.pow(vectorB[i], 2);
        }

        if (normA == 0.0 || normB == 0.0) {
            return 0.0;
        }

        return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB));
    }

    /**
     * 判断两个文本是否语义相似
     */
    public static boolean isSimilar(String text1, String text2, 
                                     EmbeddingService embeddingService, 
                                     double threshold) {
        float[] vec1 = toArray(embeddingService.embed(text1));
        float[] vec2 = toArray(embeddingService.embed(text2));
        return cosineSimilarity(vec1, vec2) >= threshold;
    }

    private static float[] toArray(List<Float> list) {
        float[] arr = new float[list.size()];
        for (int i = 0; i < list.size(); i++) {
            arr[i] = list.get(i);
        }
        return arr;
    }
}
```

## 五、多级缓存架构

单层缓存无法同时满足**速度**和**命中率**的需求。生产环境的最佳实践是**三级缓存**：

```
请求 ──▶ L1: Caffeine（本地缓存）
  │          └─ 精确匹配，命中 5ms，过期5分钟
  ○
请求 ──▶ L2: Redis 精确缓存
  │          └─ 精确匹配，命中 20ms，过期1小时
  ○
请求 ──▶ L3: Redis 语义缓存
  │          └─ 向量相似度，命中 50ms，过期24小时
  ○
请求 ──▶ L4: LLM API 调用
             └─ 无命中，2~10秒 → 回写 L1/L2/L3
```

### 5.2 完整三级缓存实现

```java
import com.github.benmanes.caffeine.cache.Cache;
import com.github.benmanes.caffeine.cache.Caffeine;
import org.springframework.stereotype.Service;
import java.time.Duration;
import java.util.Optional;
import java.util.function.Supplier;

@Service
public class MultiLevelCacheService {

    // L1: 本地 Caffeine 缓存（精确匹配）
    private final Cache<String, String> localCache;

    // L2: Redis 精确缓存
    @Autowired
    private ExactCacheService exactCacheService;

    // L3: 语义缓存
    @Autowired
    private SemanticCacheService semanticCacheService;

    public MultiLevelCacheService() {
        this.localCache = Caffeine.newBuilder()
            .maximumSize(10000)          // 最多缓存10000条
            .expireAfterWrite(Duration.ofMinutes(5))   // 5分钟过期
            .recordStats()               // 开启统计
            .build();
    }

    /**
     * 多级缓存查询 + LLM调用
     */
    public String queryWithCache(String question, String model, double temperature,
                                  Supplier<String> llmCaller) {
        
        // L1: 本地缓存
        String l1Key = md5(question + model + temperature);
        String l1Result = localCache.getIfPresent(l1Key);
        if (l1Result != null) {
            cacheHit("L1", question);
            return l1Result;
        }

        // L2: Redis 精确缓存
        String l2Result = exactCacheService.get(question, model, temperature);
        if (l2Result != null) {
            cacheHit("L2", question);
            // 回写 L1
            localCache.put(l1Key, l2Result);
            return l2Result;
        }

        // L3: 语义缓存（仅当 temperature 较低时使用）
        if (temperature <= 0.3) {
            Optional<String> l3Result = semanticCacheService.get(question);
            if (l3Result.isPresent()) {
                cacheHit("L3", question);
                // 回写 L1 和 L2
                localCache.put(l1Key, l3Result.get());
                exactCacheService.put(question, model, temperature, l3Result.get());
                return l3Result.get();
            }
        }

        // L4: 调用 LLM
        cacheMiss(question);
        String llmResult = llmCaller.get();

        // 回写所有缓存层
        localCache.put(l1Key, llmResult);
        exactCacheService.put(question, model, temperature, llmResult);

        // 只有高质量答案才写入语义缓存
        if (temperature <= 0.3) {
            semanticCacheService.put(question, llmResult);
        }

        return llmResult;
    }

    // 缓存统计
    private long l1Hit = 0, l2Hit = 0, l3Hit = 0, miss = 0;

    private void cacheHit(String level, String question) {
        switch (level) {
            case "L1" -> l1Hit++;
            case "L2" -> l2Hit++;
            case "L3" -> l3Hit++;
        }
        log.info("[CACHE HIT] L={} question={}", level, 
            question.length() > 50 ? question.substring(0, 50) + "..." : question);
    }

    private void cacheMiss(String question) {
        miss++;
        log.info("[CACHE MISS] question={}", 
            question.length() > 50 ? question.substring(0, 50) + "..." : question);
    }

    public CacheStats getStats() {
        return new CacheStats(l1Hit, l2Hit, l3Hit, miss);
    }

    record CacheStats(long l1Hit, long l2Hit, long l3Hit, long miss) {
        public double getHitRate() {
            long total = l1Hit + l2Hit + l3Hit + miss;
            return total == 0 ? 0 : (double) (l1Hit + l2Hit + l3Hit) / total;
        }
    }

    private String md5(String input) {
        try {
            java.security.MessageDigest md = java.security.MessageDigest.getInstance("MD5");
            byte[] digest = md.digest(input.getBytes(java.nio.charset.StandardCharsets.UTF_8));
            StringBuilder sb = new StringBuilder();
            for (byte b : digest) sb.append(String.format("%02x", b));
            return sb.toString();
        } catch (Exception e) {
            throw new RuntimeException(e);
        }
    }
}
```

### 6.2 主动失效

```java
@Service
public class CacheInvalidationService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    /**
     * 按知识库更新批量失效
     */
    public void invalidateByKnowledgeBase(String kbId) {
        // 使用 Redis SCAN 匹配所有相关 Key
        String pattern = "llm:cache:*:kb:" + kbId + ":*";
        Set<String> keys = redisTemplate.keys(pattern);
        if (keys != null && !keys.isEmpty()) {
            redisTemplate.delete(keys);
            log.info("已清理缓存: kbId={}, count={}", kbId, keys.size());
        }
    }

    /**
     * 模型版本升级时全局失效
     */
    public void invalidateByModelVersion(String model, String newVersion) {
        String pattern = "llm:cache:*:model:" + model + ":*";
        Set<String> keys = redisTemplate.keys(pattern);
        if (keys != null && !keys.isEmpty()) {
            redisTemplate.delete(keys);
            log.info("模型升级，已清理缓存: model={}, version={}, count={}", 
                model, newVersion, keys.size());
        }
    }
}
```

## 八、语义缓存的反面：那些不该缓存的情况

```java
/**
 * 语义缓存的黑名单模式
 * 以下场景不应使用语义缓存
 */
public class SemanticCacheBlacklist {

    // 不应该被语义缓存的模式
    private static final List<String> NO_CACHE_PATTERNS = List.of(
        "生成.*代码",           // 代码生成：每次需求不同
        "写.*文案",             // 创意文案：需要原创
        "随机.*",              // 随机生成
        ".*{.*}",              // 含变量的模板
        "翻译.*成.*"            // 精确翻译应走精确缓存
    );

    public static boolean shouldUseSemanticCache(String prompt) {
        for (String pattern : NO_CACHE_PATTERNS) {
            if (prompt.matches(pattern)) {
                return false;
            }
        }
        return prompt.length() > 10;  // 太短的问题语义不明
    }
}
```

## 九、生产环境部署清单

- [ ] Caffeine 本地缓存（L1），命中率监控
- [ ] Redis 精确缓存（L2），TTL 按场景配置

## 十、总结

| 缓存层级 | 技术 | 延迟 | 命中率 | 适合场景 |
|---------|------|------|--------|---------|
| L1 本地 | Caffeine | <1ms | 5%~15% | 热点问题 |
| L2 Redis精确 | MD5索引 | 5~20ms | 10%~25% | 翻译/分类 |
| L3 语义 | Embedding向量 | 30~80ms | 10%~30% | 客服/FAQ |

**一句话总结**：精确缓存省钱，语义缓存省心，两者结合能省下 30%~50% 的 LLM API 成本。
