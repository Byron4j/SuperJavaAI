### 2.2 选品标准：什么值得翻译？

不是所有海外内容都值得翻译。我的筛选标准：

```java
public class ContentSelector {
    
    /**
     * 海外内容翻译价值评分系统
     */
    public static TranslationWorthiness evaluate(EnglishContent content) {
        int score = 0;
        List<String> reasons = new ArrayList<>();
        
        // 1. 是否有中文替代品？（没有替代品+30分）
        int chineseAlternatives = searchChineseAlternatives(content.getTopic());
        if (chineseAlternatives == 0) {
            score += 30;
            reasons.add("中文互联网没有同类内容");
        } else if (chineseAlternatives < 5) {
            score += 15;
            reasons.add("中文同类内容极少");
        }
        
        // 2. 内容深度（深度内容+25分）
        if (content.getWordCount() > 3000 && content.isInDepth()) {
            score += 25;
            reasons.add("深度长文，翻译价值高");
        } else if (content.getWordCount() > 1500) {
            score += 10;
        }
        
        // 3. 时效性（刚发布+20分）
        long hoursSincePublished = content.getHoursSincePublished();
        if (hoursSincePublished < 24) {
            score += 20;
            reasons.add("最新内容，时效性强");
        } else if (hoursSincePublished < 72) {
            score += 10;
        }
        
        // 4. 话题热度（当前热门+15分）
        if (content.getTopic().isTrending()) {
            score += 15;
            reasons.add("当前热门话题");
        }
        
        // 5. 作者权威性（知名作者+10分）
        if (content.getAuthor().isRecognized()) {
            score += 10;
            reasons.add("知名技术专家原创");
        }
        
        return new TranslationWorthiness(score, reasons, score >= 60);
    }
}
```

打分规则：60分以上 → 值得翻译。80分以上 → 优先翻译。

## 三、AI翻译+本地化的工作流

### 3.1 不是"翻译"，是"本地化改写"

直译的英文技术文章在中文语境下非常别扭。我做的不是翻译，是**本地化改写**。

```
原文（英文）：
"The Spring AI framework provides a clean abstraction over various AI 
providers. It follows the familiar Spring programming model, making it 
easy for Spring developers to integrate AI capabilities."

直译（差）：
"Spring AI框架为各种AI提供商提供了清晰的抽象。它遵循熟悉的Spring编程模型，
使Spring开发者能够轻松集成AI能力。"

本地化改写（好）：
"用过Spring Data或Spring Security的都知道，Spring的玩法就是'给乱七八糟的实现套一层干净的皮'。
Spring AI也是这个套路——你不需要操心后端接入的是GPT-4还是文心一言，
反正你的代码都是一样的写法。这对后端兄弟来说简直太爽了：不用看各种AI厂商的API文档，
用你熟悉的@Autowired直接怼就行。"
```

### 3.2 完整的翻译+改写Prompt

```
你是技术翻译专家，擅长将英文技术文章转化为适合中文读者阅读的本土化内容。

核心原则：
1. 不直译，而是"用中文开发者的方式说同一件事"
2. 保留原文的核心信息和数据，但表达完全中文化
3. 适量加入中文开发社区的常见表达和梗
4. 英文特有的比喻换成中文开发者熟悉的比喻
5. 技术术语保留英文（如RAG、Embedding），但第一次出现时用括号加注中文

改写规则：
- 长句拆分：英文一句话可能30个词，中文拆成2-3句
- 名词动词化：英文多用名词（"provides an abstraction"），中文多用动词（"把...封装成"）
- 被动变主动：英文多被动语态，中文多主动语态
- 增加口语感：适当加入"你猜怎么着"、"说实话"、"说白了就是"
- 代码注释也要翻译：但保留代码中的标识符

请将以下英文内容进行本地化改写：

【粘贴英文内容】
```

### 3.3 AI翻译工作流的代码实现

```java
@Service
public class TechTranslationService {
    
    private final ChatClient chatClient;
    private final TerminologyService termService;
    private final QualityChecker qualityChecker;
    
    /**
     * 完整的AI翻译+本地化改写流程
     */
    public TranslatedArticle translate(EnglishArticle source) {
        // Step 1: 术语提取和统一
        Map<String, String> terminology = termService.extractTerms(source.getContent());
        
        // Step 2: 分段落翻译（整篇一起翻译质量会下降）
        List<String> englishParagraphs = splitByMeaningfulUnit(source.getContent());
        List<String> chineseParagraphs = new ArrayList<>();
        
        for (String para : englishParagraphs) {
            String translated = translateParagraph(para, terminology);
            chineseParagraphs.add(translated);
        }
        
        // Step 3: 连贯性优化
        String fullText = String.join("\n\n", chineseParagraphs);
        String smoothed = smoothTransitions(fullText);
        
        // Step 4: 质量检查
        QualityReport report = qualityChecker.check(smoothed, source.getContent());
        
        if (report.hasIssues()) {
            log.warn("翻译质量问题: {}", report.getIssues());
            // 对有问题的部分重新翻译
            smoothed = fixIssues(smoothed, report);
        }
        
        // Step 5: 添加原创价值（解读、补充、评价）
        String enhanced = addOriginalValue(smoothed, source);
        
        // Step 6: 格式化为中文阅读习惯
        String formatted = formatForChineseReader(enhanced);
        
        return TranslatedArticle.builder()
            .original(source)
            .translated(formatted)
            .translator("AI辅助翻译 + 人工审校")
            .additions("补充了中文社区的实践案例和解读")
            .build();
    }
    
    /**
     * 翻译+本地化一个段落
     */
    private String translateParagraph(String english, Map<String, String> terms) {
        String prompt = """
            将以下英文技术段落改写为中文技术文章风格。
            
            术语表（保持以下翻译一致）：
            %s
            
            要求：
            1. 不是翻译，是"用中文开发者的方式重说一遍"
            2. 保留所有技术准确性
            3. 英文的每个信息点都要涵盖
            4. 符合中文技术文章的阅读习惯
            5. 适当的口语化表达
            
            原文：
            %s
            """.formatted(formatTerms(terms), english);
        
        return chatClient.prompt().user(prompt).call().content();
    }
    
    /**
     * 最重要的步骤：添加原创价值
     * 纯翻译没有壁垒，加入你的独有解读才是壁垒
     */
    private String addOriginalValue(String translated, EnglishArticle source) {
        String prompt = """
            你是一个中文技术博主。以下是翻译自英文的内容，请在此基础上加入你的原创解读。
            
            添加内容类型：
            1. 【你的解读】：对原文观点的个人理解（赞同/补充/质疑）
            2. 【中国视角】：这个技术在国内的使用情况
            3. 【实操经验】：如果你做过类似的项目，补充实际经验
            4. 【关联推荐】：推荐相关的国内资源和工具
            
            注意：
            - 原创内容用明显的标记标识（如"【博主注】"）
            - 不要改变原文的核心信息
            - 原创内容占比控制在20-30%
            
            翻译后的原文：
            %s
            """.formatted(translated);
        
        return chatClient.prompt().user(prompt).call().content();
    }
}
```

## 四、合规和版权问题（非常重要）

翻译海外内容最大的雷区是版权。我的处理原则：

### 原则1：必须获得授权

```
可行的内容来源：
✓ MIT/Apache2.0开源许可的文档
✓ 原作者明确声明"可以翻译"的内容
✓ 作者授权我翻译的内容（我会发邮件/推特私信询问）
✓ 公共领域的学术论文
✓ 新闻/行业报告（合理引用+原创解读）

不可行的内容来源：
✗ 没有声明许可的个人博客文章
✗ 付费墙后面的媒体内容
✗ Medium上明确写了"All Rights Reserved"的文章
✗ 商业公司未公开的内部文档
```

### 原则2：显著标注来源

每篇翻译文章的开头和结尾都标注：

> 本文翻译并改编自 [作者名] 的 [原文标题]（[原文链接]），已获作者授权。翻译过程中加入了译者基于中国技术社区的实践经验和解读。原文采用 [许可证类型] 许可。

### 原则3：原创内容要占一定比例

如果只是纯翻译，就算授权了，对读者价值也有限。我坚持在每篇翻译中加入20-30%的原创解读。
