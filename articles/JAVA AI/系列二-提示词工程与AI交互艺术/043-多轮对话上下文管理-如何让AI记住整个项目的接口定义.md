# 多轮对话上下文管理：如何让 AI 记住整个项目的接口定义

> 对话长了 AI 就"失忆"？上下文窗口、滑动窗口、摘要压缩三招搞定长对话记忆问题。

---

## 一、那个让人抓狂的瞬间

凌晨两点，你正在让 AI 帮你写一套微服务的 Java 代码。

前 30 轮对话里，你陆续定义了 10 个核心接口：

```java
public interface UserService {
    UserDTO getUserById(Long id);
    PageResult<UserDTO> listUsers(UserQuery query);
}

public interface OrderService {
    OrderDTO createOrder(OrderRequest request);
    OrderDTO getOrderByOrderNo(String orderNo);
}

public interface PaymentService {
    PaymentResult pay(PaymentRequest request);
    PaymentStatus queryStatus(String paymentId);
}

// ... 还有7个接口
```

AI 一路配合得天衣无缝。然后第 31 轮，你说：

> "帮我在 PaymentService 里加一个退款方法，参考 UserService 的分页风格。"

AI 沉默了一秒，然后回答：

> "抱歉，我没有在对话历史中看到您定义过 PaymentService 或 UserService，能否重新提供这两个接口的定义？"

你盯着屏幕，血压瞬间上来了——**AI 失忆了**。

这不是 AI 在装傻，而是**上下文窗口**这个底层机制在作祟。今天这篇文章，我们就来把这个问题彻底讲透，并给出三个可在生产环境落地的解决方案。

---

## 二、上下文窗口：AI 的"短期记忆"

### 2.1 Token 是什么？

LLM 处理文本的基本单位叫 Token。一个中文字大约 1.5-2 个 Token，一个英文单词大约 1-2 个 Token。一段 Java 代码因为特殊符号多，Token 消耗通常比纯文本大 30%-50%。

```
"public interface UserService {" → 约 8 个 Token
"你好世界" → 约 3 个 Token
"Hello World" → 约 2 个 Token
```

### 2.2 上下文窗口天花板

每个模型都有一个**上下文窗口**上限（Context Window），这是模型一次能"看到"的 Token 总量——**包括你的输入和 AI 的输出**。

| 模型 | 上下文窗口 |
|------|-----------|
| GPT-3.5-Turbo | 4K / 16K |
| GPT-4-Turbo | 128K |
| Claude 3 | 200K |
| Gemini 1.5 Pro | 1M |
| 国产主流模型 | 8K-128K |

看起来很充裕，对吧？128K Token ≈ 一本《三体》的体量。

但现实是残酷的：**多轮对话中，上下文是累积的。** 每一轮你的输入 + AI 的输出都会被追加到上下文里。假设每轮平均消耗 800 Token，30 轮就是 24,000 Token——对于 8K 窗口的模型，已经超了三倍。

### 2.3 滑动窗口：最粗暴的解决方案

当 Token 总数超过窗口限制，模型服务端通常会启动**滑动窗口**机制——直接**丢弃最早的对话**。

这就是你遇到"失忆"的根本原因：你前 10 轮定义的接口，在第 31 轮时已经被滑动窗口裁剪掉了。

```java
// 示意滑动窗口机制
public class SlidingWindowContext {
    private final int maxTokens;
    private final Deque<Message> messages = new ArrayDeque<>();

    public void addMessage(Message msg) {
        messages.addLast(msg);
        int totalTokens = messages.stream().mapToInt(Message::tokenCount).sum();
        while (totalTokens > maxTokens && !messages.isEmpty()) {
            Message removed = messages.removeFirst(); // 丢弃最早的消息！
            totalTokens -= removed.tokenCount();
        }
    }
}
```

丢掉的恰好是你最核心的接口定义，这是不可接受的。

## 三、方案一：手动摘要法——每轮结束让 AI 总结关键信息

### 3.1 核心思路

最简单的策略：在对话的关键节点让 AI 自己概括当前进展，然后把摘要作为下一次对话的"锚点"注入。

### 3.2 Java 实现

```java
public class ManualSummaryStrategy {
    
    // 对话历史管理
    private final List<Message> history = new ArrayList<>();
    private String contextSummary = "";
    
    /**
     * 在关键节点生成摘要
     */
    public String generateSummary(ChatClient client) {
        StringBuilder prompt = new StringBuilder();
        prompt.append("请总结当前对话中已定义的所有 Java 接口、实体类和关键约定。");
        prompt.append("输出格式如下：\n");
        prompt.append("## 已定义接口\n");
        prompt.append("- 接口名: 完整签名\n");
        prompt.append("- 接口名: 完整签名\n");
        prompt.append("## 已定义实体\n");
        prompt.append("- 实体名: 关键字段\n");
        prompt.append("## 技术约定\n");
        prompt.append("- 约定1\n");
        prompt.append("- 约定2\n");
        
        String summary = client.chat(prompt.toString());
        this.contextSummary = summary;
        System.out.println("摘要已生成，压缩比: " + 
            (summary.length() * 1.0 / totalHistoryTokens()) * 100 + "%");
        return summary;
    }
    
    /**
     * 构建带摘要的完整 Prompt
     */
    public String buildPromptWithSummary(String userInput) {
        if (contextSummary.isEmpty()) {
            return userInput;
        }
        return String.format("""
            [上下文摘要 - 以下是之前对话中的关键信息]
            %s
            
            [当前问题]
            %s
            
            请基于上下文摘要中的接口定义来回答。
            """, contextSummary, userInput);
    }
    
    private int totalHistoryTokens() {
        return history.stream()
            .mapToInt(m -> m.getContent().length() / 2) // 简化估算
            .sum();
    }
}
```

### 3.3 自动化摘要器实现

更进一步，我们可以做一个自动触发摘要的上下文管理器：

```java
public class AutoSummaryContextManager {
    
    private static final int SUMMARY_TRIGGER_TOKENS = 3000; // 3000 Token时触发
    private static final int MAX_HISTORY_ROUNDS = 20;       // 最多保留20轮原始对话
    
    private final List<Message> conversationHistory = new ArrayList<>();
    private String accumulatedSummary = "";
    private final ChatClient chatClient;
    
    public AutoSummaryContextManager(ChatClient chatClient) {
        this.chatClient = chatClient;
    }
    
    /**
     * 添加一轮对话，自动判断是否需要压缩
     */
    public String addTurn(String userInput, String aiResponse) {
        conversationHistory.add(new Message("user", userInput));
        conversationHistory.add(new Message("assistant", aiResponse));
        
        // 检查是否需要压缩
        if (estimateTotalTokens() > SUMMARY_TRIGGER_TOKENS) {
            compressHistory();
        }
        
        // 检查是否需要裁剪历史对话
        while (conversationHistory.size() > MAX_HISTORY_ROUNDS * 2) {
            conversationHistory.remove(0);
            conversationHistory.remove(0); // 移除最早的一轮
        }
        
        return buildContextPrompt();
    }
    
    /**
     * 压缩历史对话：让AI总结当前累积信息
     */
    private void compressHistory() {
        String summaryPrompt = String.format("""
            请将以下信息合并到现有摘要中，只保留与Java开发相关的技术内容：
            
            现有摘要：
            %s
            
            新增对话要点：
            %s
            
            请输出更新后的完整摘要，包含：
            1. 所有已定义的接口签名
            2. 所有数据实体及其关键字段
            3. 技术选型和约定
            4. 待处理的事项
            """, accumulatedSummary, recentConversations());
        
        accumulatedSummary = chatClient.chat(summaryPrompt);
        System.out.println("[上下文压缩] 压缩完成，摘要长度: " + accumulatedSummary.length() + " 字符");
    }
    
    private String recentConversations() {
        // 取最近10轮
        int start = Math.max(0, conversationHistory.size() - 20);
        return conversationHistory.subList(start, conversationHistory.size())
            .stream()
            .map(m -> m.getRole() + ": " + m.getContent())
            .collect(Collectors.joining("\n"));
    }
    
    private String buildContextPrompt() {
        if (accumulatedSummary.isEmpty()) return "";
        return "[项目上下文]\n" + accumulatedSummary + "\n";
    }
    
    private int estimateTotalTokens() {
        return conversationHistory.stream()
            .mapToInt(m -> m.getContent().length() / 2)
            .sum();
    }
    
    // 消息实体
    @Data
    @AllArgsConstructor
    static class Message {
        private String role;
        private String content;
    }
}
```

### 3.4 手动摘要法优缺点

| 优点 | 缺点 |
|------|------|
| 实现简单，无外部依赖 | 摘要过程本身消耗Token |
| 可控性强，随时调整 | 关键信息可能被压缩丢失 |
| 适合中小规模对话（<50轮） | 不适合需要精确回忆细节的场景 |

## 四、方案二：结构化上下文注入——上下文卡片模式

### 4.1 核心思路

与其让 AI 从散乱的对话中找信息，不如我们**主动构建结构化的上下文卡片**，在每次请求时注入。

就像给 AI 一个"项目速查手册"——接口清单、实体目录、技术约定，一目了然。

### 4.2 上下文卡片的数据结构

### 4.3 上下文卡片注入器

```java
public class ContextCardInjector {
    
    private final Map<String, InterfaceDef> interfaceRegistry = new LinkedHashMap<>();
    private final Map<String, EntityDef> entityRegistry = new LinkedHashMap<>();
    private final List<String> conventions = new ArrayList<>();
    private final Map<String, String> projectConfigs = new HashMap<>();
    
    /**
     * 注册一个接口定义到上下文
     */
    public void registerInterface(InterfaceDef iface) {
        interfaceRegistry.put(iface.getName(), iface);
        System.out.println("[上下文注册] 接口: " + iface.getName());
    }
    
    /**
     * 注册一个实体
     */
    public void registerEntity(EntityDef entity) {
        entityRegistry.put(entity.getClassName(), entity);
        System.out.println("[上下文注册] 实体: " + entity.getClassName());
    }
    
    /**
     * 添加一条技术约定
     */
    public void addConvention(String convention) {
        conventions.add(convention);
    }
    
    /**
     * 生成结构化的上下文注入文本
     */
    public String generateContextInjection() {
        StringBuilder sb = new StringBuilder();
        
        // ===== 项目概览 =====
        sb.append("## 项目上下文\n");
        sb.append("**技术栈**: ").append(String.join(", ", getTechStack())).append("\n\n");
        
        // ===== 接口清单 =====
        if (!interfaceRegistry.isEmpty()) {
            sb.append("### 接口定义清单\n");
            sb.append("```java\n");
            for (InterfaceDef iface : interfaceRegistry.values()) {
                sb.append(iface.getSignature()).append("\n");
                for (MethodDef method : iface.getMethods()) {
                    sb.append("    ").append(method.getReturnType()).append(" ")
                      .append(method.getName()).append("(");
                    sb.append(method.getParams().stream()
                        .map(p -> p.getType() + " " + p.getName())
                        .collect(Collectors.joining(", ")));
                    sb.append("); // ").append(method.getDescription()).append("\n");
                }
                sb.append("\n");
            }
            sb.append("```\n\n");
        }
        
        // ===== 实体清单 =====
        if (!entityRegistry.isEmpty()) {
            sb.append("### 数据实体\n");
            sb.append("```java\n");
            for (EntityDef entity : entityRegistry.values()) {
                sb.append("@Table(name = \"").append(entity.getTableName()).append("\")\n");
                sb.append("public class ").append(entity.getClassName()).append(" {\n");
                for (FieldDef field : entity.getFields()) {
                    sb.append("    private ").append(field.getType())
                      .append(" ").append(field.getName())
                      .append("; // ").append(field.getColumn())
                      .append(field.nullable ? " 可为空" : "").append("\n");
                }
                sb.append("}\n\n");
            }
            sb.append("```\n\n");
        }
        
        // ===== 技术约定 =====
        if (!conventions.isEmpty()) {
            sb.append("### 编码约定\n");
            for (int i = 0; i < conventions.size(); i++) {
                sb.append(i + 1).append(". ").append(conventions.get(i)).append("\n");
            }
            sb.append("\n");
        }
        
        // ===== Token 预算 =====
        int estimatedTokens = sb.length() / 2;
        sb.append("---\n");
        sb.append("[上下文预算: 约 ").append(estimatedTokens).append(" Token]");
        
        return sb.toString();
    }
    
    /**
     * 构建带上下文注入的完整 Prompt
     */
    public String wrapUserPrompt(String userInput) {
        return generateContextInjection() + "\n---\n## 当前任务\n" + userInput;
    }
    
    private List<String> getTechStack() {
        List<String> stack = new ArrayList<>();
        stack.add("Spring Boot 3.2");
        stack.add("MyBatis-Plus 3.5");
        stack.add("MySQL 8.0");
        return stack;
    }
}
```

### 4.5 结构化注入的优势

上下文卡片方案的 Token 效率极高。一个接口的完整定义通常只需 50-100 Token，而如果让 AI 从对话中自己找，可能需要翻阅 500-1000 Token 的对话。这就好比给你一本精心编排的目录 vs 让你在一堆散乱笔记里翻找。

## 五、方案三：RAG 式上下文检索——按需注入的智能方案

### 5.1 核心思路

前两个方案都有局限：摘要法会丢失细节，上下文卡片需要手动维护。

RAG（Retrieval-Augmented Generation）的思路是：**把你项目的代码/文档预先向量化存储，每次用户提问时，自动检索最相关的上下文片段，精准注入**。

### 5.2 代码索引器

```java
public class CodeIndexer {
    
    private final EmbeddingService embeddingService;
    private final VectorStore vectorStore;
    
    /**
     * 扫描 Java 源码目录，将每个接口/类作为独立文档索引
     */
    public void indexProject(String sourceRoot) throws IOException {
        Path root = Path.of(sourceRoot);
        
        Files.walk(root)
            .filter(p -> p.toString().endsWith(".java"))
            .forEach(this::indexFile);
        
        System.out.println("索引完成，总计文档数: " + vectorStore.count());
    }
    
    private void indexFile(Path filePath) {
        try {
            String content = Files.readString(filePath);
            String className = extractClassName(filePath);
            
            // 对于接口文件，以方法为单位切分
            if (content.contains("interface ")) {
                indexInterface(content, className);
            } else {
                // 普通类，整文件索引
                CodeDocument doc = new CodeDocument(
                    className,
                    filePath.toString(),
                    content,
                    "class",
                    extractImports(content)
                );
                indexDocument(doc);
            }
        } catch (IOException e) {
            System.err.println("索引文件失败: " + filePath);
        }
    }
    
    /**
     * 将接口按方法粒度索引 —— 提高检索精度
     */
    private void indexInterface(String content, String interfaceName) {
        // 简化演示：用正则提取每个方法签名作为独立文档
        Pattern methodPattern = Pattern.compile(
            "(//[^\\n]*\\n)?\\s*(@\\w+(?:\\([^)]*\\))?\\s*)*" +
            "\\s*(\\w+(?:<[^>]+>)?)\\s+(\\w+)\\s*\\([^)]*\\)\\s*(?:throws[^{]*)?;"
        );
        
        Matcher matcher = methodPattern.matcher(content);
        int methodCount = 0;
        
        while (matcher.find()) {
            String methodSignature = matcher.group().trim();
            CodeDocument doc = new CodeDocument(
                interfaceName + "#" + matcher.group(4), // 类名#方法名
                interfaceName,
                "// 接口: " + interfaceName + "\n" + methodSignature,
                "method",
                extractImports(content)
            );
            indexDocument(doc);
            methodCount++;
        }
        
        System.out.println("已索引接口 " + interfaceName + " (" + methodCount + " 个方法)");
    }
    
    private void indexDocument(CodeDocument doc) {
        // 向量化
        float[] embedding = embeddingService.embed(doc.getContentForEmbedding());
        
        // 存入向量数据库
        vectorStore.insert(doc.getId(), embedding, doc.toMetadata());
    }
    
    private String extractClassName(Path filePath) {
        String fileName = filePath.getFileName().toString();
        return fileName.substring(0, fileName.length() - 5); // 去掉.java
    }
    
    private List<String> extractImports(String content) {
        return Pattern.compile("import\\s+([\\w.]+);")
            .matcher(content)
            .results()
            .map(r -> r.group(1))
            .collect(Collectors.toList());
    }
}
```

### 5.3 代码文档模型

```java
@Data
@AllArgsConstructor
public class CodeDocument {
    private String id;            // 唯一标识
    private String source;        // 来源文件
    private String content;       // 原始内容
    private String type;          // class / interface / method
    private List<String> imports; // import列表
    
    /**
     * 构建用于向量化的文本
     * 不只索引代码本身，还包含其imports作为语义补充
     */
    public String getContentForEmbedding() {
        StringBuilder sb = new StringBuilder();
        sb.append("Type: ").append(type).append("\n");
        sb.append("Source: ").append(source).append("\n");
        sb.append("Imports: ").append(String.join(", ", imports)).append("\n");
        sb.append("Code:\n").append(content);
        return sb.toString();
    }
    
    public Map<String, String> toMetadata() {
        Map<String, String> meta = new HashMap<>();
        meta.put("id", id);
        meta.put("source", source);
        meta.put("type", type);
        meta.put("imports", String.join(",", imports));
        return meta;
    }
}
```

### 5.4 检索增强提示构建器

```java
public class RAGPromptBuilder {
    
    private final VectorStore vectorStore;
    private final EmbeddingService embeddingService;
    
    /**
     * 根据用户问题，检索最相关的代码片段，构建增强提示
     */
    public String buildAugmentedPrompt(String userQuestion, int topK) {
        // 1. 将用户问题向量化
        float[] queryEmbedding = embeddingService.embed(userQuestion);
        
        // 2. 向量检索：找相似度最高的K个代码片段
        List<SearchResult> results = vectorStore.search(queryEmbedding, topK);
        
        // 3. 构建上下文注入区块
        StringBuilder contextBlock = new StringBuilder();
        contextBlock.append("## [自动检索的相关代码上下文]\n\n");
        
        for (int i = 0; i < results.size(); i++) {
            SearchResult result = results.get(i);
            contextBlock.append("### 参考片段 ").append(i + 1)
                .append(" (相似度: ").append(String.format("%.2f", result.getScore())).append(")\n");
            contextBlock.append("```java\n");
            contextBlock.append(result.getContent());
            contextBlock.append("\n```\n\n");
        }
        
        // 4. 组装完整 Prompt
        return contextBlock.toString() + "\n---\n## 用户问题\n" + userQuestion + 
               "\n\n请基于上面提供的代码上下文来回答，保持代码风格一致。";
    }
    
    @Data
    @AllArgsConstructor
    public static class SearchResult {
        private String id;
        private String content;
        private double score;
        private Map<String, String> metadata;
    }
}
```

### 5.5 完整的 RAG 上下文管理器

```java
public class RAGContextManager {
    
    private final RAGPromptBuilder promptBuilder;
    private final CodeIndexer indexer;
    private final List<String> conversationMemory = new ArrayList<>();
    private String lastRetrievedContext = "";
    
    /**
     * 处理用户输入
     * 关键优化：如果连续提问在同一主题，复用上次检索结果，避免重复检索
     */
    public String processUserInput(String input) {
        // 判断是否需要重新检索
        boolean needRetrieval = shouldRetrieve(input);
        
        String contextPrompt;
        if (needRetrieval) {
            // 合并对话记忆中的关键词来增强检索
            String enhancedQuery = enhanceQueryWithMemory(input);
            contextPrompt = promptBuilder.buildAugmentedPrompt(enhancedQuery, 5);
            lastRetrievedContext = contextPrompt;
        } else {
            contextPrompt = lastRetrievedContext + "\n---\n## 用户问题\n" + input;
        }
        
        // 更新对话记忆
        conversationMemory.add(input);
        if (conversationMemory.size() > 10) {
            conversationMemory.remove(0);
        }
        
        return contextPrompt;
    }
    
    /**
     * 用最近的对话历史增强检索查询
     */
    private String enhanceQueryWithMemory(String currentInput) {
        if (conversationMemory.isEmpty()) return currentInput;
        
        // 取最近3轮的关键词合并
        List<String> recentQueries = conversationMemory.subList(
            Math.max(0, conversationMemory.size() - 3),
            conversationMemory.size()
        );
        
        return String.join(" | ", recentQueries) + " | " + currentInput;
    }
    
    /**
     * 判断是否需要触发新检索
     * 策略：如果问题中包含新的类名/方法名，说明切换了上下文
     */
    private boolean shouldRetrieve(String input) {
        if (lastRetrievedContext.isEmpty()) return true;
        
        // 提取可能的类名/接口名（首字母大写的驼峰词）
        Set<String> entities = Pattern.compile("\\b([A-Z][a-zA-Z]+)\\b")
            .matcher(input)
            .results()
            .map(r -> r.group(1))
            .collect(Collectors.toSet());
        
        // 检查这些实体是否出现在上次检索结果中
        for (String entity : entities) {
            if (!lastRetrievedContext.contains(entity)) {
                return true; // 新的实体，需要重新检索
            }
        }
        return false;
    }
}
```

## 六、三种方案对比与选型建议

```java
public enum ContextStrategy {
    MANUAL_SUMMARY,      // 手动摘要法
    STRUCTURED_INJECTION, // 结构化上下文注入
    RAG_RETRIEVAL         // RAG检索增强
}

public class ContextStrategySelector {
    
    public static ContextStrategy select(int fileCount, int conversationRounds) {
        if (fileCount <= 10 && conversationRounds <= 30) {
            // 小项目、短对话 → 手动摘要就够
            return ContextStrategy.MANUAL_SUMMARY;
        } else if (fileCount <= 50) {
            // 中等项目 → 结构化上下文卡片
            return ContextStrategy.STRUCTURED_INJECTION;
        } else {
            // 大项目 → RAG 检索增强
            return ContextStrategy.RAG_RETRIEVAL;
        }
    }
}
```

| 方案 | 适用场景 | Token 效率 | 实现成本 | 信息保真度 |
|------|---------|-----------|---------|-----------|
| 手动摘要法 | <10 文件，<30 轮 | 中 | 低 | 中 |
| 结构化注入 | 10-50 文件 | 高 | 中 | 高 |
| RAG 检索增强 | 50+ 文件，长期项目 | 极高 | 高 | 极高 |

### 实战建议：组合拳

实际项目中，最优方案是**三管齐下**：

1. **结构化注入**作为基础（始终注入接口清单和约定）
2. **RAG 检索**作为补充（按需检索具体方法实现）
3. **手动摘要**作为兜底（每 20 轮做一次对话摘要）

```java
public class HybridContextManager {
    
    private final ManualSummaryStrategy summaryStrategy;
    private final ContextCardInjector cardInjector;
    private final RAGContextManager ragManager;
    
    public String buildFullPrompt(String userInput) {
        StringBuilder finalPrompt = new StringBuilder();
        
        // 第1层：结构化上下文卡片（基础层，始终注入）
        finalPrompt.append(cardInjector.generateContextInjection());
        
        // 第2层：RAG检索增强（按需注入相关代码）
        String ragContext = ragManager.processUserInput(userInput);
        finalPrompt.append("\n").append(ragContext);
        
        // 第3层：对话摘要（长对话兜底）
        String summary = summaryStrategy.buildPromptWithSummary(userInput);
        if (!summary.isEmpty()) {
            finalPrompt.append("\n").append(summary);
        }
        
        return finalPrompt.toString();
    }
}

## 七、总结

AI 的"失忆"不是 bug，是上下文字窗机制决定的——理解了这个底层原理，我们就能用工程手段来弥补。

三层递进方案：
- **手动摘要法**：入门首选，先跑起来
- **结构化上下文注入**：规范化管理，Token 效率飞跃
- **RAG 检索增强**：终极方案，按需精准注入

最终目标是让 AI 在长达数百轮的对话中，**始终"记得"你项目的每一个接口、每一个实体、每一条约定**——就像你身边最靠谱的结对编程搭档。
