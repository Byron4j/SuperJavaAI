## 三、逐项深度解析

### 1. LangChain（90k+ Stars）

**一句话总结**：AI Agent 开发的"事实标准"，但 Java 生态还在追赶。

**核心亮点**：
- **链（Chain）**：将 LLM 调用、工具调用、输出解析等横块串联
- **Agent Executor**：内置 ReAct、OpenAI Functions、Structured Chat 等多种 Agent 模式
- **工具生态**：200+ 内置工具集成（搜索、数据库、API 调用、文件操作）
- **记忆系统**：ConversationBufferMemory、VectorStoreRetrieverMemory 等多种记忆模式

**架构图**：
```
LangChain Agent Architecture:
┌───────────────────────────────────────────┐
│               Agent Executor               │
│  ┌─────────────────────────────────────┐  │
│  │          Agent（ReAct/OpenAI/...）    │  │
│  │  Thought → Action → Observation      │  │
│  └─────────────────────────────────────┘  │
│         ↓              ↓           ↑        │
│  ┌──────────┐  ┌──────────┐  ┌─────────┐  │
│  │   LLM    │  │  Tools   │  │ Memory  │  │
│  │  (模型)   │  │ (工具集)  │  │ (记忆)   │  │
│  └──────────┘  └──────────┘  └─────────┘  │
└───────────────────────────────────────────┘
```

**Java 可用性评估**：⭐⭐⭐

- **Spring AI** 是目前最活跃的 Java 替代方案，已支持 ChatClient、Function Calling、RAG、多模态等功能
- 但 Spring AI 的 Agent 能力（ReAct 循环、多步骤工具调用）还比较基础
- **推荐方案**：使用 Spring AI 做 LLM 集成层，自己实现 Agent 决策循环

**快速上手 Spring AI Agent**：

```java
@RestController
public class SpringAIAgentController {
    
    private final ChatClient chatClient;
    
    public SpringAIAgentController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }
    
    /**
     * 使用 Spring AI 的 Function Calling 实现简单的 Agent 模式
     */
    @GetMapping("/agent/weather")
    public String agentWeather(@RequestParam String city) {
        return chatClient.prompt()
                .user("查询" + city + "的天气，并根据天气推荐穿衣建议")
                .functions("getWeather", "getClothingAdvice")
                .call()
                .content();
    }
}

// 工具函数定义
@Component
public class WeatherTools {
    
    @Bean
    @Description("获取指定城市的天气信息")
    public Function<WeatherRequest, WeatherResponse> getWeather() {
        return request -> {
            // 调用天气 API
            return new WeatherResponse(request.city(), "晴天", 25, "微风");
        };
    }
    
    @Bean
    @Description("根据天气信息推荐穿衣")
    public Function<WeatherInfo, String> getClothingAdvice() {
        return weather -> {
            if (weather.temperature() > 25) return "建议穿短袖";
            else if (weather.temperature() > 15) return "建议穿长袖薄外套";
            else return "建议穿厚外套";
        };
    }
}
```

### 2. CrewAI（33k+ Stars）

**一句话总结**：最火的角色扮演式多 Agent 框架，但 Java 需要自己实现。

**核心亮点**：
- **角色（Role）**：定义 Agent 的身份、目标和背景故事
- **工具（Tool）**：Agent 可调用的能力（搜索、代码执行、文件读写）
- **任务（Task）**：明确的任务描述、期望输出和分配 Agent
- **流程（Process）**：sequential（顺序执行）、hierarchical（层级管理）
- **委派（Delegation）**：Agent 可以将子任务委派给其他 Agent

**核心代码示例（Python）**：
```python
from crewai import Agent, Task, Crew

analyst = Agent(
    role='需求分析师',
    goal='将用户需求转化为清晰的PRD',
    backstory='你是一个经验丰富的产品经理'
)

developer = Agent(
    role='开发工程师',
    goal='编写高质量代码',
    backstory='你是一个资深Java开发',
    tools=[code_generator_tool]
)

task1 = Task(description='分析需求', agent=analyst)
task2 = Task(description='编写代码', agent=developer)

crew = Crew(agents=[analyst, developer], tasks=[task1, task2])
result = crew.kickoff()
```

**Java 可用性评估**：⭐⭐

- CrewAI 重度依赖 Python 生态（LangChain），Java 没有直接等价物
- **我们的文章 #147 给出了完整的 Java 化实现思路**，核心抽象可复用
- 如果团队以 Java 为主，建议参考 CrewAI 的设计理念自研
- 如果是新项目且不限于 Java，直接用 Python 版 CrewAI

### 3. AutoGen（35k+ Stars，微软出品）

**一句话总结**：对话驱动的多 Agent 框架，适合复杂对话场景。

**核心亮点**：
- **ConversableAgent**：可以通过消息与其他 Agent 对话
- **GroupChat**：多个 Agent 在一个群聊中协作
- **Human-in-the-Loop**：支持人工介入
- **Code Executor**：Agent 可以在 Docker 沙箱中执行代码

**Java 可用性评估**：⭐

- AutoGen 和 Python 的 asyncio 深度绑定，Java 移植成本高
- **学习建议**：理解其"对话式协作"的设计哲学，应用到自己的系统中
- 替代方案：可以考虑在 Java 中基于消息队列实现 Agent 对话（Kafka/RabbitMQ）

### 4. MetaGPT（48k+ Stars）

**一句话总结**：用 SOP（标准操作流程）驱动多 Agent 协作生成软件。

**Java 可用性评估**：⭐⭐

### 5. Dify（55k+ Stars）

**一句话总结**：可视化的 AI 应用构建平台，低代码 + Agent 编排。

**核心亮点**：
- **可视化工作流**：拖拽式编排 Agent 逻辑
- **知识库管理**：内置文档导入和向量检索
- **Chatflow/Workflow**：支持对话流和工作流两种模式
- **API 发布**：构建的应用可以一键发布为 API
- **企业级功能**：多租户、RBAC、审计日志等

**Java 可用性评估**：⭐⭐⭐

- Dify 提供 REST API，Java 应用可通过 HTTP 调用
- **混合架构推荐**：Dify 做前端 Agent 编排，Java 做后端业务逻辑
- Dify 和 Spring Boot 的组合是目前最务实的方案之一

**Java 集成示例**：

```java
@Service
public class DifyIntegrationService {
    
    private final RestClient restClient;
    private final String difyApiKey;
    
    public DifyIntegrationService(
            @Value("${dify.api-key}") String apiKey,
            @Value("${dify.base-url}") String baseUrl) {
        this.difyApiKey = apiKey;
        this.restClient = RestClient.builder()
                .baseUrl(baseUrl)
                .defaultHeader("Authorization", "Bearer " + apiKey)
                .build();
    }
    
    /**
     * 调用 Dify 工作流
     */
    public Map<String, Object> runWorkflow(String query, Map<String, Object> inputs) {
        Map<String, Object> request = Map.of(
                "inputs", inputs != null ? inputs : Map.of(),
                "query", query,
                "response_mode", "blocking",
                "user", "system"
        );
        
        return restClient.post()
                .uri("/v1/workflows/run")
                .contentType(MediaType.APPLICATION_JSON)
                .body(request)
                .retrieve()
                .body(Map.class);
    }
    
    /**
     * 调用 Dify Chatflow Agent
     */
    public String chatWithAgent(String conversationId, String message) {
        Map<String, Object> request = new HashMap<>();
        request.put("query", message);
        request.put("response_mode", "streaming");
        request.put("conversation_id", conversationId);
        request.put("user", "java-service");
        
        // 使用 SSE 流式接收
        return restClient.post()
                .uri("/v1/chat-messages")
                .contentType(MediaType.APPLICATION_JSON)
                .body(request)
                .retrieve()
                .body(String.class);
    }
}
```

### 6. Spring AI（3.5k+ Stars）

**一句话总结**：Java 开发者的 AI 集成首选。

**核心亮点**：
- **Spring 生态原生**：Auto Configuration、依赖注入、可观测性
- **多模型支持**：OpenAI、Azure、Ollama、Anthropic、Gemini、Mistral
- **Function Calling**：自动将 Java Bean 注册为 LLM 可调用的函数
- **Vector Store 集成**：PgVector、Redis、Milvus、Pinecone 等
- **ETL Pipeline**：文档加载、分块、嵌入、存储一条龙

**核心代码示例**：

```java
@Configuration
public class SpringAIConfig {
    
    @Bean
    public ChatClient chatClient(ChatClient.Builder builder) {
        return builder
                .defaultSystem("你是一个Java开发助手")
                .defaultFunctions("executeSQL", "searchCodebase")
                .build();
    }
    
    @Bean
    public VectorStore vectorStore(EmbeddingModel embeddingModel, 
                                    JdbcTemplate jdbcTemplate) {
        return new PgVectorStore(jdbcTemplate, embeddingModel);
    }
    
    /**
     * 构建带 RAG 和 Function Calling 的 Agent
     */
    @Bean
    public AgentService agentService(ChatClient chatClient, 
                                      VectorStore vectorStore) {
        return new AgentService(chatClient, vectorStore);
    }
}

@Service
public class AgentService {
    
    private final ChatClient chatClient;
    private final VectorStore vectorStore;
    
    /**
     * Agent 查询：先查知识库，再调用工具
     */
    public AgentResponse query(String userMessage) {
        // RAG 检索
        List<Document> relevantDocs = vectorStore.similaritySearch(
                SearchRequest.builder()
                        .query(userMessage)
                        .topK(5)
                        .similarityThreshold(0.7)
                        .build());
        
        // 拼装上下文
        String context = relevantDocs.stream()
                .map(Document::getText)
                .collect(Collectors.joining("\n---\n"));
        
        // Agent 决策
        String result = chatClient.prompt()
                .system(s -> s.text("""
                    你有一个知识库和工具，请先参考知识库内容，
                    如果知识库不能回答问题，使用工具执行操作。
                    
                    知识库内容:
                    {context}
                    """).param("context", context))
                .user(userMessage)
                .call()
                .content();
        
        return new AgentResponse(result, relevantDocs);
    }
}
```

**Java 可用性评估**：⭐⭐⭐⭐⭐

- 这是 Java 生态中最好的 AI 集成框架
- Agent 能力还在快速发展中，但底层能力（LLM 调用 + Function Calling + RAG）已经完善
- **强烈推荐**：所有 Java AI 项目从 Spring AI 开始

### 7. LangGraph（9k+ Stars）

**一句话总结**：有状态的 Agent 工作流引擎。

**核心亮点**：
- **StateGraph**：用图结构定义工作流，每个节点处理状态
- **Checkpoint**：自动保存状态快照，支持断点恢复
- **条件分支**：基于状态的动态路由
- **人机协作**：interrupt 节点等待人工输入
- **时间旅行**：回溯到任意 checkpoint

**Java 可用性评估**：⭐⭐

- 我们的文章 #146 给出了完整的 Java 实现
- LangGraph 的核心是设计模式层面的，不依赖特定语言特性
- 实现成本中等（核心类 ~800 行 Java 代码）

### 9. Swarm（OpenAI 开源，17k+ Stars）

**一句话总结**：轻量级、实验性的 Agent 编排框架，适合学习核心概念。

**核心亮点**：
- **极简设计**：核心代码仅几百行
- **Handoff（转交）**：Agent 之间可以无缝切换
- **Routines（例程）**：Agent 执行一组预设的指令和函数调用
- **无状态**：每次调用独立，由调用方管理上下文

**核心概念（Java 化）**：

```java
/**
 * Swarm 的核心理念——Agent + Handoff
 */
public class SwarmAgent {
    
    private final String name;
    private final String instructions;
    private final List<Function<Map<String, Object>, String>> functions;
    
    /**
     * 执行并可能转交给其他 Agent
     */
    public SwarmResult run(String userMessage, List<SwarmAgent> allAgents) {
        // 1. 执行当前 Agent 的逻辑
        String response = llmCall(instructions, userMessage);
        
        // 2. 检查是否需要 handoff
        for (SwarmAgent other : allAgents) {
            if (response.contains("转交给 " + other.getName())) {
                return new SwarmResult(null, other);
            }
        }
        
        return new SwarmResult(response, this);
    }
}
```

**Java 可用性评估**：⭐⭐

- 实验性项目，不适合生产环境
- 但非常适合学习：代码短、概念清晰、容易理解
- 建议花 2 小时阅读源码，理解 Agent 编排的核心模式

## 四、Java 开发者选型指南

基于不同的场景，我的推荐如下：

```
场景一：Spring Boot 项目，想快速集成 LLM/Agent
  → Spring AI（⭐⭐⭐⭐⭐）
  → 自己实现 Agent 循环 + Spring AI 做 LLM 层

场景二：需要多 Agent 协作的角色扮演式系统
  → 参考 CrewAI 设计理念 + 自研 Java 实现
  → 或使用 Dify 做可视化编排 + Java 后端

场景三：复杂工作流，需要断点恢复、条件分支
  → 参考 LangGraph 设计 + 自研轻量版
  → 或使用 Camunda/Flowable 流程引擎 + LLM 节点

场景四：快速验证 Agent 原型
  → Dify 或 Flowise + Java API 调用
  → 验证通过后再迁移到纯 Java 实现

场景五：企业内部工具（日志分析、代码审查等）
  → Spring AI + Function Calling + 自定义 Tool
  → 结合公司内部 API 和数据库
```

## 六、我对 Java Agent 开发的建议

经过这个系列 8 篇文章的深度探索，我对 Java 开发者进入 Agent 领域有几点建议：

**1. 不要等框架，先理解核心模式**

Agent 的核心就三个循环：
- **ReAct 循环**：Think → Act → Observe（思考 → 行动 → 观察）
- **工具调用**：让 LLM 输出的 JSON 变成真实的函数调用
- **上下文管理**：多轮对话和多步骤任务的状态管理

这三者理解透了，用什么语言实现都行。

**2. Spring AI 是最佳起点，但不是终点**

Spring AI 让 Java 项目接入 LLM 变得极其简单。但它目前的 Agent 抽象还很初级。在实际项目中，可以用 Spring AI 做 LLM 接入层，自己写 Agent 调度层。

**3. 混合架构是务实之选**

不要执着于"必须在 Java 中运行一切 Agent"。可以考虑：
- Dify/Flowise 做 Agent 编排 → Java 服务做业务逻辑
- Python 微服务做 LLM + Agent → Java 做核心业务系统
- 通过 REST API 或 gRPC 通信，各取所长

**4. Agent 本质不是技术问题，而是设计问题**

一个 Agent 好不好用，70% 取决于：
- System Prompt 设计
- 工具接口设计（清晰、幂等、容错）
- 错误处理机制
- 人机协作的交互设计

代码写得再漂亮，Prompt 写不好，Agent 也会像个智障。
