## 一、"老板，美国节点挂了，所有海外用户都在转圈圈"

凌晨 3:17，PagerDuty 把我从梦里炸醒。

`us-east-1` 区域的 GPU 集群宕机了——不是模型挂了，是整个可用区的网络交换机故障。海外用户集体白屏，0 秒内切到其他区域？不存在的，因为我们根本没做灾备。

那晚的故障复盘会上，架构师只说了四个字：**"必须多活"**。

对于大模型推理服务，单区域部署等于把鸡蛋放在一个篮子里：
- **可用区故障**：AWS us-east-1 2025 年平均每月 0.7 次 service disruption
- **GPU 资源紧张**：热门区域 GPU 竞价实例经常被抢光
- **跨境延迟**：美国用户连新加坡节点，P99 延迟 300ms+
- **合规要求**：欧盟 GDPR 要求数据不出境

本文给你一套**多区域模型部署架构**，核心解决三个问题：**就近推理（latency）**、**灾备切换（reliability）**、**数据合规（compliance）**。

## 三、Java 实现：区域健康管理器

### 3.1 健康状态 Gossip 同步

每个区域的 Java 服务定期向全局 Redis 上报自己的健康状态，同时读取其他区域的状态。

```java
@Component
public class RegionHealthManager {

    private static final String HEALTH_KEY_PREFIX = "region:health:";
    private static final int TTL_SECONDS = 30;  // 30秒无心跳 = 判定下线
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @Value("${app.region:us-east-1}")
    private String currentRegion;

    /**
     * 每 10 秒上报一次心跳
     */
    @Scheduled(fixedRate = 10000)
    public void reportHeartbeat() {
        RegionHealth health = RegionHealth.builder()
            .region(currentRegion)
            .status(collectLocalHealth())
            .gpuAvailable(getAvailableGPUCount())
            .avgLatency(getAvgLatency())
            .lastHeartbeat(System.currentTimeMillis())
            .build();
        
        String key = HEALTH_KEY_PREFIX + currentRegion;
        redisTemplate.opsForValue().set(
            key, 
            JSON.toJSONString(health), 
            TTL_SECONDS, 
            TimeUnit.SECONDS
        );
    }
    
    /**
     * 获取所有区域健康状态
     */
    public Map<String, RegionHealth> getAllRegionHealth() {
        Set<String> keys = redisTemplate.keys(HEALTH_KEY_PREFIX + "*");
        Map<String, RegionHealth> result = new HashMap<>();
        
        for (String key : keys) {
            String json = redisTemplate.opsForValue().get(key);
            if (json != null) {
                RegionHealth h = JSON.parseObject(json, RegionHealth.class);
                result.put(h.getRegion(), h);
            }
        }
        return result;
    }
    
    /**
     * 判断某区域是否健康
     */
    public boolean isRegionHealthy(String region) {
        String key = HEALTH_KEY_PREFIX + region;
        String json = redisTemplate.opsForValue().get(key);
        if (json == null) return false;
        
        RegionHealth health = JSON.parseObject(json, RegionHealth.class);
        // 心跳距今不超过 15 秒
        return (System.currentTimeMillis() - health.getLastHeartbeat()) < 15000;
    }
    
    /**
     * 收集本地健康信息
     */
    private String collectLocalHealth() {
        // 检查 GPU 推理服务是否正常
        try {
            boolean gpuOK = checkGPUInferenceService();
            boolean appOK = true; // 自己能运行到这里说明应用 OK
            return gpuOK && appOK ? "HEALTHY" : "DEGRADED";
        } catch (Exception e) {
            return "UNHEALTHY";
        }
    }
    
    private boolean checkGPUInferenceService() {
        String vllmHealthUrl = "http://localhost:8000/health";
        RestTemplate rt = new RestTemplate();
        try {
            ResponseEntity<String> resp = rt.getForEntity(vllmHealthUrl, String.class);
            return resp.getStatusCode().is2xxSuccessful();
        } catch (Exception e) {
            return false;
        }
    }
    
    @Data
    @Builder
    public static class RegionHealth {
        private String region;
        private String status;        // HEALTHY / DEGRADED / UNHEALTHY
        private int gpuAvailable;
        private double avgLatency;
        private long lastHeartbeat;
    }
}
```

### 3.2 就近路由：自动选择最优区域

```java
@Component
public class RegionRouter {

    @Autowired
    private RegionHealthManager healthManager;
    
    /** 区域优先级配置（延迟权重） */
    private static final Map<String, Map<String, Integer>> LATENCY_MATRIX = Map.of(
        "US_EAST", Map.of("us-east-1", 50, "eu-west-1", 120, "ap-south-1", 250),
        "EUROPE",  Map.of("us-east-1", 120, "eu-west-1", 30, "ap-south-1", 180),
        "ASIA",    Map.of("us-east-1", 220, "eu-west-1", 200, "ap-south-1", 60)
    );

    /**
     * 根据用户地理位置选择最优推理区域
     * 
     * 策略：
     * 1. 首选：用户最近区域（通过 IP/地理位置判断）
     * 2. 备选：健康区域中延迟最低的
     * 3. 兜底：任意健康区域
     */
    public String selectBestRegion(String userIp) {
        String userGeo = resolveUserGeo(userIp);
        Map<String, Integer> latencyPreference = LATENCY_MATRIX.getOrDefault(
            userGeo, LATENCY_MATRIX.get("ASIA"));
        
        // 按延迟排序，选第一个健康的
        return latencyPreference.entrySet().stream()
            .sorted(Map.Entry.comparingByValue())
            .filter(e -> healthManager.isRegionHealthy(e.getKey()))
            .map(Map.Entry::getKey)
            .findFirst()
            .orElseGet(this::getAnyHealthyRegion);
    }
    
    /**
     * 获取多区域路由列表（用于客户端重试）
     */
    public List<String> getFailoverRegions(String userIp) {
        String userGeo = resolveUserGeo(userIp);
        return LATENCY_MATRIX.getOrDefault(userGeo, LATENCY_MATRIX.get("ASIA"))
            .entrySet().stream()
            .sorted(Map.Entry.comparingByValue())
            .map(Map.Entry::getKey)
            .collect(Collectors.toList());
    }
    
    private String resolveUserGeo(String userIp) {
        // 简化版：实际使用 MaxMind GeoIP2 数据库
        if (userIp.startsWith("1.") || userIp.startsWith("52.")) return "US_EAST";
        if (userIp.startsWith("3.") || userIp.startsWith("18.")) return "EUROPE";
        return "ASIA";
    }
    
    private String getAnyHealthyRegion() {
        return healthManager.getAllRegionHealth().entrySet().stream()
            .filter(e -> "HEALTHY".equals(e.getValue().getStatus()))
            .map(Map.Entry::getKey)
            .findFirst()
            .orElseThrow(() -> new RuntimeException("所有区域不可用"));
    }
}
```

## 四、灾备切换：故障检测 + 自动流量迁移

### 4.1 故障检测器

```java
@Component
@Slf4j
public class FailoverDetector {

    @Autowired
    private RegionHealthManager healthManager;
    
    @Autowired
    private RegionRouter regionRouter;
    
    @Autowired
    private AlertService alertService;
    
    /** 连续故障次数阈值 */
    private static final int FAILURE_THRESHOLD = 3;
    
    /** 每个区域最近的故障计数 */
    private final Map<String, Integer> failureCount = new ConcurrentHashMap<>();

    /**
     * 每 5 秒检测一次
     */
    @Scheduled(fixedRate = 5000)
    public void detectAndFailover() {
        Map<String, RegionHealth> allRegions = healthManager.getAllRegionHealth();
        
        for (Map.Entry<String, RegionHealth> entry : allRegions.entrySet()) {
            String region = entry.getKey();
            boolean healthy = "HEALTHY".equals(entry.getValue().getStatus());
            
            if (!healthy) {
                int count = failureCount.merge(region, 1, Integer::sum);
                log.warn("区域 {} 健康检查失败 (连续 {} 次)", region, count);
                
                if (count >= FAILURE_THRESHOLD) {
                    triggerFailover(region);
                }
            } else {
                // 恢复后清零
                if (failureCount.getOrDefault(region, 0) > 0) {
                    log.info("区域 {} 已恢复", region);
                    triggerRecovery(region);
                }
                failureCount.remove(region);
            }
        }
    }
    
    /**
     * 触发区域切换
     */
    private void triggerFailover(String failedRegion) {
        log.error("🔥 区域 {} 故障确认，触发自动切换", failedRegion);
        
        // 1. 更新 Redis 状态标记
        String failoverKey = "region:failover:" + failedRegion;
        String backupRegion = selectBackupRegion(failedRegion);
        redisTemplate.opsForValue().set(failoverKey, backupRegion, 5, TimeUnit.MINUTES);
        
        // 2. 发送告警
        alertService.sendAlert(AlertLevel.CRITICAL, 
            String.format("区域 %s 已故障，流量自动切换至 %s", failedRegion, backupRegion));
        
        // 3. 记录审计
        log.info("FAILOVER_EVENT region={} backup={} time={}", 
            failedRegion, backupRegion, System.currentTimeMillis());
    }
    
    private void triggerRecovery(String region) {
        alertService.sendAlert(AlertLevel.INFO, 
            String.format("区域 %s 已恢复正常", region));
    }
    
    private String selectBackupRegion(String failedRegion) {
        return healthManager.getAllRegionHealth().entrySet().stream()
            .filter(e -> !e.getKey().equals(failedRegion))
            .filter(e -> "HEALTHY".equals(e.getValue().getStatus()))
            .min(Comparator.comparingDouble(e -> e.getValue().getAvgLatency()))
            .map(Map.Entry::getKey)
            .orElse(null);
    }
}
```

### 4.2 客户端侧故障转移

```java
@Service
public class ResilientAIClient {

    @Autowired
    private RegionRouter regionRouter;

    /**
     * 带故障转移的模型调用
     */
    public ModelResponse chatWithFailover(String userIp, ModelRequest request) {
        List<String> failoverRegions = regionRouter.getFailoverRegions(userIp);
        
        for (String region : failoverRegions) {
            try {
                String endpoint = getEndpointForRegion(region);
                return callRegionEndpoint(endpoint, request, 30_000);
            } catch (Exception e) {
                log.warn("区域 {} 调用失败: {}", region, e.getMessage());
                // 继续尝试下一个区域
            }
        }
        
        throw new AllRegionsFailedException("所有区域均不可用");
    }
    
    private ModelResponse callRegionEndpoint(String endpoint, ModelRequest request, int timeout) {
        RestTemplate rt = new RestTemplate();
        rt.setRequestFactory(() -> {
            HttpComponentsClientHttpRequestFactory factory = 
                new HttpComponentsClientHttpRequestFactory();
            factory.setConnectTimeout(5000);
            factory.setReadTimeout(timeout);
            return factory;
        });
        
        HttpEntity<ModelRequest> entity = new HttpEntity<>(request);
        ResponseEntity<ModelResponse> response = rt.postForEntity(
            endpoint + "/v1/chat/completions", entity, ModelResponse.class);
        
        if (!response.getStatusCode().is2xxSuccessful()) {
            throw new RegionCallException("HTTP " + response.getStatusCodeValue());
        }
        return response.getBody();
    }
}
```

### 7.2 渐变切换策略

```java
/**
 * 避免全量切换导致的"雪崩"：新区域需要预热（模型加载到GPU显存）
 * 使用 10% → 30% → 100% 的渐变策略
 */
@Component
public class GradualTrafficShift {

    private final AtomicInteger shiftPercent = new AtomicInteger(0);
    
    @Scheduled(fixedDelay = 30000)
    public void gradualShift() {
        int current = shiftPercent.get();
        if (current >= 100) return;
        
        int next = Math.min(current + 10, 100);
        shiftPercent.set(next);
        log.info("流量切换进度: {}%", next);
    }
    
    public boolean shouldRouteToNewRegion(String userId) {
        int hash = Math.abs(userId.hashCode());
        return (hash % 100) < shiftPercent.get();
    }
}
```

## 八、总结

多区域部署的核心不是"在多个地方部署同一套代码"，而是：

1. **健康状态同步**：Gossip 协议 + Redis，10 秒内感知故障
2. **就近路由**：GeoDNS + 延迟矩阵，用户总是连到最近的节点
3. **故障转移**：3 次检测失败 → 自动切流 ← 恢复后自动回切
4. **梯度切换**：新区域从 10% 流量开始预热，避免雪崩
5. **合规就绪**：GDPR 区域数据不出境，中国区独立部署
