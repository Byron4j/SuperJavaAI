## 二、选卡前必须懂的三个核心参数

### 2.1 显存是硬门槛

大模型推理的第一约束不是算力，是**显存大小**。

```java
/**
 * 模型显存需求计算器
 */
public class ModelMemoryCalculator {
    
    /**
     * 计算模型加载所需的显存
     * 
     * @param paramBillions 参数量（B）
     * @param quantBits 量化位数: 4(INT4), 8(INT8), 16(FP16), 32(FP32)
     * @param contextLength 上下文长度
     */
    public static double calculateVRAM(int paramBillions, int quantBits, int contextLength) {
        // 1. 模型权重
        double weightGB = paramBillions * (quantBits / 8.0);
        
        // 2. KV Cache（最容易被忽略的显存大户）
        // KV Cache = 2 * num_layers * hidden_size * context_length * bytes_per_element
        // 近似公式：每 1B 参数每 1K context 约 0.125GB
        double kvCacheGB = paramBillions * (contextLength / 1000.0) * 0.125;
        
        // 3. 推理框架开销（约 10%）
        double overhead = (weightGB + kvCacheGB) * 0.1;
        
        double total = weightGB + kvCacheGB + overhead;
        
        System.out.printf("模型权重: %.1f GB\n", weightGB);
        System.out.printf("KV Cache: %.1f GB\n", kvCacheGB);
        System.out.printf("框架开销: %.1f GB\n", overhead);
        System.out.printf("总计所需: %.1f GB\n", total);
        
        return total;
    }
    
    public static void main(String[] args) {
        // 70B 模型 FP16，8K 上下文
        calculateVRAM(70, 16, 8192);
        // 模型权重: 140 GB   ← 单卡根本塞不下
        // KV Cache:  70 GB
        // 框架开销:  21 GB
        // 总计所需: 231 GB    ← 需要 4×A100(80G) 或 2×H200(141G)
    }
}
```

### 2.2 显存带宽决定推理速度

推理是**内存密集型**任务（不是计算密集型）。每个 Token 的生成都需要读取一遍全部模型权重。

| GPU 型号 | 显存带宽 | 70B 模型理论生成速度 | 实测生成速度 |
|----------|---------|---------------------|-------------|
| RTX 4090 | 1,008 GB/s | 14.4 tok/s | 13.2 tok/s |
| A100 80G | 2,039 GB/s | 29.1 tok/s | 27.5 tok/s |
| H100 80G | 3,352 GB/s | 47.9 tok/s | 44.1 tok/s |
| H200 | 4,896 GB/s | 70.0 tok/s | 62.3 tok/s |

**算力公式**：单 Token 生成速度 ≈ GPU 带宽 / 模型权重大小

```
70B FP16: 140 GB 权重 ÷ 2039 GB/s (A100) ≈ 14.6 tok/s (每卡)
70B INT4:  17.5 GB 权重 ÷ 1008 GB/s (4090) ≈ 57.6 tok/s (每卡)
```

这就是为什么量化后的小显存卡可以跑得飞快。

### 2.3 FP16 算力（TFLOPS）——对推理影响有限

很多人盯着 TFLOPS 买卡，其实这个指标主要用于**训练**。推理时 compute-bound 的场景（Batch Size > 32）才会受到算力限制，而对延迟敏感的在线推理（Batch Size ≤ 4）基本只看显存带宽。

## 五、RTX 4090 跑 70B 模型的实战配置

### 5.1 硬件要求

```
2× RTX 4090 24GB (NVLINK 不需要，推理用 PCIe 4.0 x8 就够)
64GB 系统内存
2TB NVMe SSD
1500W 电源
```

### 5.2 模型量化配置

```bash
# Step 1: 下载 GGUF Q4_K_M 量化版（约 41GB）
# HuggingFace 上搜 "Llama-3-70B-Instruct-GGUF"
# 文件名: Llama-3-70B-Instruct-Q4_K_M.gguf

# Step 2: 用 llama.cpp 启动，分布在 2 张卡
./llama-server \
  -m /models/Llama-3-70B-Instruct-Q4_K_M.gguf \
  -ngl 80 \
  --tensor-split 24,24 \
  -c 8192 \
  --host 0.0.0.0 \
  --port 8080

# 参数说明：
# -ngl 80: 将所有 80 层都放到 GPU
# --tensor-split 24,24: 每张卡各放一半
# -c 8192: 8K 上下文
```

### 5.3 Java 客户端调用

```java
@Service
public class LocalLLMService {

    @Autowired
    private RestTemplate restTemplate;
    
    @Value("${llm.local.endpoint}")
    private String localEndpoint;

    public String chat(String prompt) {
        // llama.cpp 的 server 模式支持 OpenAI 兼容 API
        Map<String, Object> request = Map.of(
            "model", "local-llama-70b",
            "messages", List.of(
                Map.of("role", "user", "content", prompt)
            ),
            "temperature", 0.7,
            "max_tokens", 2048,
            "stream", false
        );
        
        ResponseEntity<Map> response = restTemplate.postForEntity(
            localEndpoint + "/v1/chat/completions",
            request,
            Map.class
        );
        
        Map body = response.getBody();
        List<Map> choices = (List<Map>) body.get("choices");
        Map message = (Map) choices.get(0).get("message");
        return (String) message.get("content");
    }
}
```

## 七、避坑指南：5 个常见选卡错误

### 错误 1：买 H100 做纯推理
H100 的强项是 FP8 训练（989 TFLOPS）。纯推理场景下，2×A100 比 1×H100 更便宜且性能相当。**除非你需要 H100 的 FP8 和 Transformer Engine**。

### 错误 2：忽略功耗和散热
一张 H100 满负载功耗 700W，4 张就是 2800W。普通办公室配电不够，需要专门的机柜和散热方案。这也是隐形成本。

### 错误 3：用游戏主板插专业卡
消费级主板通常只有 1-2 个 PCIe x16 槽，插 4 张卡需要服务器主板。而且 PCIe 通道数量直接影响多卡通信效率。

### 错误 4：显存够了但上下文炸了
你以为 80GB 能跑 70B 模型？实际还需要 KV Cache。1024 context 可能够，但 32K context 直接 OOM。**务必用上面的计算器验证**。

### 错误 5：只看 FP16 不看量化
多数应用场景不需要 FP16 精度。INT8 精度损失 < 0.5%，但显存减半、速度翻倍。除非做数学推理/代码生成，否则量化就够了。
