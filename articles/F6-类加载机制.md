## 引言：类加载机制的技术本质

类加载机制（Class Loading Mechanism）不是简单的"读取class文件"，而是Java运行时环境（JRE）将类的二进制字节流转化为内存中可用的Class对象的**完整工程体系**。

核心认知：

```
类加载的本质：将静态的.class字节码转化为动态的Runtime数据结构

ClassLoader的本质：通过命名空间隔离实现类的版本管理和运行时动态性

双亲委派的本质：通过层级委托实现核心类的安全沙箱和避免重复加载

打破委派的本质：在隔离性与灵活性之间寻找特定场景的最优解
```

**关键洞察**：类加载机制的设计体现了软件工程中**分层隔离**与**委托复用**的核心思想，理解其底层原理是掌握JVM调优、热部署、OSGi模块化等高级技术的基础。

## 理论基础：类加载的完整生命周期

### 1. 类加载的七个阶段

```
类加载完整生命周期：

┌─────────────────────────────────────────────────┐
│  加载（Loading）                                 │
│  目的：读取二进制字节流，生成Class对象             │
├─────────────────────────────────────────────────┤
│  链接（Linking）                                 │
│  ├── 验证（Verification）：确保字节码安全合法      │
│  ├── 准备（Preparation）：分配内存，设置默认值     │
│  └── 解析（Resolution）：符号引用转直接引用        │
├─────────────────────────────────────────────────┤
│  初始化（Initialization）                        │
│  目的：执行<clinit>()方法，初始化静态变量           │
├─────────────────────────────────────────────────┤
│  使用（Using）                                   │
│  目的：程序主动使用类（创建实例、调用方法等）        │
├─────────────────────────────────────────────────┤
│  卸载（Unloading）                               │
│  条件：类加载器实例被GC回收，且该类无实例存在       │
└─────────────────────────────────────────────────┘
```

### 2. 各阶段深度解析

#### 2.1 加载（Loading）

**核心任务**：
1. 通过全限定名获取二进制字节流
2. 将字节流代表的静态存储结构转化为方法区的运行时数据结构
3. 在堆中生成代表这个类的java.lang.Class对象

**字节码来源多样性**：

```java
public class LoadingSources {
    
    // 1. 本地文件系统：最常见的方式
    // 从classpath、jar包等加载
    
    // 2. 网络加载：Applet（已废弃）
    // URLClassLoader可以从网络URL加载
    
    // 3. 动态生成：动态代理、CGLIB、ASM
    // ProxyGenerator.generateProxyClass() 生成字节码
    
    // 4. 数据库加载：某些中间件场景
    // 将类字节码存储在BLOB字段中
    
    // 5. 加密文件：防止反编译
    // 自定义ClassLoader解密后加载
    
    // 6. 运行时计算生成：JSP编译
    // JSP文件被编译为Servlet类后加载
}
```

#### 2.2 验证（Verification）

验证阶段确保字节码不会危害JVM安全，是**类加载中最耗时但最必要**的阶段。

```
验证阶段的四个层次：

┌─────────────────────────────────────────────────┐
│  文件格式验证                                   │
│  - 魔数是否为0xCAFEBABE                        │
│  - 主/次版本号是否在当前JVM支持范围内            │
│  - 常量池中的常量是否有不被支持的类型            │
├─────────────────────────────────────────────────┤
│  元数据验证                                     │
│  - 类是否有父类（除了Object）                    │
│  - 是否继承了不允许被继承的类（final类）         │
│  - 非抽象类是否实现了所有抽象方法               │
├─────────────────────────────────────────────────┤
│  字节码验证（最复杂）                            │
│  - 操作数栈的数据类型与指令代码序列配合           │
│  - 跳转指令不会跳转到方法体以外的字节码上        │
│  - 保证类型转换是有效的                          │
├─────────────────────────────────────────────────┤
│  符号引用验证                                   │
│  - 通过字符串描述的全限定名是否能找到对应的类     │
│  - 指定类中是否存在符合描述符的方法/字段         │
│  - 符号引用中的访问性（public/private等）是否合法 │
└─────────────────────────────────────────────────┘
```

#### 2.3 准备（Preparation）

为类变量（static变量）分配内存并设置**默认值**（零值）。

```java
public class PreparationPhase {
    
    // 准备阶段后，这些变量的值：
    public static int intValue = 123;      // intValue = 0
    public static long longValue = 123L;   // longValue = 0L
    public static boolean flag = true;     // flag = false
    public static Object obj = new Object(); // obj = null
    
    // 编译期常量（final static）在准备阶段就赋值为123
    public static final int CONST = 123;   // CONST = 123（编译期已确定）
    
    // 但如果final值需要在运行时计算：
    public static final int RANDOM = new Random().nextInt(); 
    // RANDOM在准备阶段仍为0，在初始化阶段才赋值
}
```

**关键区分**：
- 普通static变量：准备阶段赋零值，初始化阶段赋实际值
- static final常量（编译期常量）：准备阶段直接赋值
- static final变量（运行时常量）：准备阶段赋零值，初始化阶段赋值

#### 2.4 解析（Resolution）

将常量池内的**符号引用**替换为**直接引用**。

```
符号引用 vs 直接引用：

符号引用（Symbolic Reference）：
- 以一组符号描述所引用的目标
- 与虚拟机内存布局无关，引用目标不一定已加载到内存
- 示例：java/lang/String、com/example/User.getName()Ljava/lang/String;

直接引用（Direct Reference）：
- 直接指向目标的指针、相对偏移量或句柄
- 与虚拟机内存布局相关，引用目标必须已存在于内存
- 示例：0x7f8a2b4c（内存地址）
```

```java
public class ResolutionPhase {
    
    // 符号引用示例：
    // 在Class文件的常量池中：
    // #1 = Class              #2             // java/lang/Object
    // #2 = Utf8               java/lang/Object
    // #3 = Fieldref           #4.#5          // ResolutionPhase.value:I
    
    // 解析前：常量池中存储的是符号引用（字符串描述）
    // 解析后：Fieldref指向方法区中该字段的实际内存地址
    
    private int value;
    
    public void method() {
        // 解析时机：可以是静态（加载时）或动态（运行时）
        // invokevirtual指令在运行时解析（多态性要求）
        Object obj = new Object(); // 解析Object类引用
    }
}
```

**解析时机**：JVM规范未强制规定解析阶段发生的时间，只要求在执行`anewarray`、`checkcast`、`getfield`等17个操作符号引用指令之前完成。

#### 2.5 初始化（Initialization）

执行类构造器`<clinit>()`方法的过程。这是类加载的最后一个阶段，也是**程序员可控性最强**的阶段。

```java
public class InitializationPhase {
    
    // <clinit>()方法的构成规则：
    // 1. 收集所有static变量的赋值语句
    // 2. 收集所有static代码块
    // 3. 按在源文件中出现的顺序执行
    
    static {
        System.out.println("static block 1");
        value = 10;  // 可以重新赋值前面声明的变量
    }
    
    static int value = 20;  // 最终value = 20（覆盖前面的赋值）
    
    static {
        System.out.println("static block 2");
        System.out.println("value = " + value);  // 可以访问前面初始化的变量
        // System.out.println(other);  // 编译错误：非法前向引用
    }
    
    static int other = 30;
    
    // 执行顺序：
    // 1. static block 1: value = 10
    // 2. value = 20
    // 3. static block 2: 打印 value = 20
    // 4. other = 30
}
```

**`<clinit>()` vs `<init>()`**：

```
┌─────────────────────────────────────────────────┐
│  <clinit>() 类构造器                              │
│  - 由编译器自动收集所有static语句生成              │
│  - 只执行一次（类加载时）                          │
│  - 不是实例构造器，不负责对实例变量的初始化         │
│  - 父类的<clinit>()优先于子类执行                  │
├─────────────────────────────────────────────────┤
│  <init>() 实例构造器                               │
│  - 对应类的构造方法（可能多个）                     │
│  - 每次创建实例时执行                              │
│  - 负责对实例变量的初始化                          │
│  - 先执行父类<init>()，再执行自身                  │
└─────────────────────────────────────────────────┘
```

#### 2.6 初始化触发时机

```java
public class InitTriggerCases {
    
    // JVM规范严格规定了有且仅有以下6种情况会触发类的初始化：
    
    // 1. new关键字实例化对象
    public void trigger1() {
        new InitTriggerCases();
    }
    
    // 2. 访问类的静态变量（非final编译期常量）
    public void trigger2() {
        int x = SomeClass.staticField;
    }
    
    // 3. 调用类的静态方法
    public void trigger3() {
        SomeClass.staticMethod();
    }
    
    // 4. 反射调用
    public void trigger4() throws Exception {
        Class.forName("com.example.SomeClass");
        // 或
        SomeClass.class.getDeclaredMethod("method").invoke(null);
    }
    
    // 5. 子类初始化触发父类初始化
    class Child extends Parent {
        // 初始化Child时，Parent会先初始化
    }
    
    // 6. 主类（包含main方法的类）
    public static void main(String[] args) {
        // main方法所在类会先初始化
    }
    
    // ========== 不会触发初始化的特殊情况 ==========
    
    // 情况1：通过子类引用父类的静态字段，只初始化父类
    public void notTrigger1() {
        int x = Child.staticField;  // 只初始化Parent，不初始化Child
    }
    
    // 情况2：定义数组类型
    public void notTrigger2() {
        SomeClass[] array = new SomeClass[10];  // 不初始化SomeClass
    }
    
    // 情况3：访问编译期常量（static final）
    public void notTrigger3() {
        int x = SomeClass.FINAL_CONST;  // 不初始化SomeClass（常量已存入调用类的常量池）
    }
    
    // 情况4：ClassLoader.loadClass()默认不初始化
    public void notTrigger4() throws Exception {
        ClassLoader.getSystemClassLoader().loadClass("com.example.SomeClass");
        // 只有Class.forName()才会触发初始化
    }
}

class Parent {
    static int staticField = 10;
    static {
        System.out.println("Parent initialized");
    }
}

class Child extends Parent {
    static {
        System.out.println("Child initialized");
    }
}
```

### 3. 类加载的线程安全性

```java
public class ClassLoadingThreadSafety {
    
    // 类加载过程是线程安全的！
    // JVM保证同一个ClassLoader在同一时间只加载一个类
    
    // 底层实现：ClassLoader.loadClass()使用了synchronized关键字
    // synchronized (getClassLoadingLock(name))
    
    // 这带来的问题：
    // 如果类加载过程耗时较长（如从网络加载），会阻塞其他线程
    
    public static void main(String[] args) {
        // 多线程同时加载同一个类
        for (int i = 0; i < 10; i++) {
            new Thread(() -> {
                try {
                    Class.forName("java.util.HashMap");
                } catch (ClassNotFoundException e) {
                    e.printStackTrace();
                }
            }).start();
        }
        // 实际只有一个线程执行完整的加载过程，其他线程等待锁释放后
        // 发现类已加载，直接返回
    }
}
```

## 源码深度分析：双亲委派机制的实现

### 1. 双亲委派的核心源码

```java
// java.lang.ClassLoader.loadClass(String name, boolean resolve)
// JDK 8 源码分析

protected Class<?> loadClass(String name, boolean resolve)
    throws ClassNotFoundException {
    
    // 1. 获取类加载锁，保证线程安全
    synchronized (getClassLoadingLock(name)) {
        
        // 2. 检查该类是否已被当前ClassLoader加载过
        Class<?> c = findLoadedClass(name);
        
        if (c == null) {
            // 记录开始时间（用于性能统计）
            long t0 = System.nanoTime();
            
            try {
                if (parent != null) {
                    // 3. 委派给父加载器加载
                    // 递归调用，直到Bootstrap ClassLoader
                    c = parent.loadClass(name, false);
                } else {
                    // 4. 父加载器为null（即当前是Bootstrap的下一层）
                    // 委派给Bootstrap ClassLoader
                    c = findBootstrapClassOrNull(name);
                }
            } catch (ClassNotFoundException e) {
                // 父加载器无法加载，这是正常的，继续向下执行
            }
            
            if (c == null) {
                // 5. 父加载器都无法加载，自己尝试加载
                long t1 = System.nanoTime();
                
                // 调用findClass()，由子类实现自定义加载逻辑
                c = findClass(name);
                
                // 记录性能统计信息（JVM内部使用）
                sun.misc.PerfCounter.getParentDelegationTime().addTime(t1 - t0);
                sun.misc.PerfCounter.getFindClassTime().addElapsedTimeFrom(t1);
                sun.misc.PerfCounter.getFindClasses().increment();
            }
        }
        
        // 6. 如果resolve为true，解析类的符号引用
        if (resolve) {
            resolveClass(c);
        }
        
        return c;
    }
}

// 获取类加载锁
protected Object getClassLoadingLock(String className) {
    Object lock = this;
    if (parallelLockMap != null) {
        // 支持并行加载的ClassLoader使用ConcurrentHashMap
        Object newLock = new Object();
        lock = parallelLockMap.putIfAbsent(className, newLock);
        if (lock == null) {
            lock = newLock;
        }
    }
    return lock;
}
```

```java
// Tomcat的WebappClassLoader.loadClass()核心逻辑（简化版）
public class WebappClassLoader extends URLClassLoader {
    
    @Override
    public Class<?> loadClass(String name, boolean resolve) 
            throws ClassNotFoundException {
        
        synchronized (getClassLoadingLock(name)) {
            // 1. 检查是否已经加载
            Class<?> clazz = findLoadedClass0(name);
            if (clazz != null) {
                return clazz;
            }
            
            // 2. 检查本地缓存（Tomcat特有）
            clazz = findLoadedClass(name);
            if (clazz != null) {
                return clazz;
            }
            
            // 3. 使用System类加载器加载（避免Web应用覆盖Java核心类）
            // 这是安全措施，不是双亲委派
            try {
                clazz = system.loadClass(name);
                if (clazz != null) {
                    return clazz;
                }
            } catch (ClassNotFoundException e) {
                // Ignore
            }
            
            // 4. 尝试在本地资源中查找（/WEB-INF/classes和/WEB-INF/lib）
            // 这就是"打破双亲委派"的关键步骤！
            try {
                clazz = findClass(name);  // 先自己找
                if (clazz != null) {
                    return clazz;
                }
            } catch (ClassNotFoundException e) {
                // Ignore
            }
            
            // 5. 本地找不到，再委派给父加载器
            try {
                clazz = parent.loadClass(name);  // 再委派
                if (clazz != null) {
                    return clazz;
                }
            } catch (ClassNotFoundException e) {
                // Ignore
            }
        }
        
        throw new ClassNotFoundException(name);
    }
}
```

```java
// OSGi（Open Service Gateway Initiative）
// 每个Bundle有自己的ClassLoader，实现真正的模块化隔离

public class OSGiClassLoading {
    
    // OSGi类加载规则（不同于双亲委派）：
    // 1. 首先检查java.*开头的类，委派给父加载器
    // 2. 检查是否在BootClassPath中，委派给父加载器
    // 3. 检查是否在Import-Package中，委派给导出该包的Bundle
    // 4. 检查是否在Require-Bundle中，委派给被依赖的Bundle
    // 5. 检查本地Bundle的类路径
    // 6. 检查是否在DynamicImport-Package中
    // 7. 检查Fragment Bundle
    
    // 典型应用场景：
    // Bundle A依赖commons-lang3 3.1
    // Bundle B依赖commons-lang3 3.5
    
    // 在OSGi中，两个Bundle分别加载各自的commons-lang3版本
    // 不会冲突，因为它们在不同的ClassLoader命名空间中
}

// OSGi类加载器伪代码：
class BundleClassLoader extends ClassLoader {
    
    private BundleWiring wiring;
    private List<BundleClassLoader> dependencies;
    
    @Override
    protected Class<?> loadClass(String name, boolean resolve) 
            throws ClassNotFoundException {
        
        // 1. 检查缓存
        Class<?> clazz = findLoadedClass(name);
        if (clazz != null) return clazz;
        
        // 2. java.* 包委托给Bootstrap
        if (name.startsWith("java.")) {
            return getParent().loadClass(name);
        }
        
        // 3. 检查Import-Package，委托给提供该包的Bundle
        String packageName = getPackageName(name);
        if (wiring.isImportedPackage(packageName)) {
            BundleClassLoader exporter = wiring.getExporter(packageName);
            return exporter.loadClass(name);
        }
        
        // 4. 本地加载
        try {
            return findClass(name);
        } catch (ClassNotFoundException e) {
            // 5. 检查Require-Bundle
            for (BundleClassLoader dep : dependencies) {
                try {
                    return dep.loadClass(name);
                } catch (ClassNotFoundException ignored) {}
            }
            throw e;
        }
    }
}
```

```java
import java.io.*;

/**
 * 基础自定义类加载器
 * 从指定目录加载类文件
 */
public class BasicCustomClassLoader extends ClassLoader {
    
    private String classPath;
    
    public BasicCustomClassLoader(String classPath) {
        this.classPath = classPath;
    }
    
    public BasicCustomClassLoader(String classPath, ClassLoader parent) {
        super(parent);
        this.classPath = classPath;
    }
    
    /**
     * 重写findClass方法（遵循双亲委派）
     * 只负责从自定义路径加载类
     */
    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        // 1. 读取类文件的字节码
        byte[] classData = loadClassData(name);
        
        if (classData == null) {
            throw new ClassNotFoundException("Class not found: " + name);
        }
        
        // 2. 调用defineClass将字节码转化为Class对象
        return defineClass(name, classData, 0, classData.length);
    }
    
    /**
     * 从文件系统读取类文件
     */
    private byte[] loadClassData(String name) {
        // 将全限定名转换为文件路径
        String path = classPath + File.separatorChar 
            + name.replace('.', File.separatorChar) + ".class";
        
        try (InputStream is = new FileInputStream(path);
             ByteArrayOutputStream baos = new ByteArrayOutputStream()) {
            
            byte[] buffer = new byte[1024];
            int length;
            while ((length = is.read(buffer)) != -1) {
                baos.write(buffer, 0, length);
            }
            return baos.toByteArray();
        } catch (IOException e) {
            return null;
        }
    }
    
    public static void main(String[] args) throws Exception {
        // 使用自定义类加载器加载类
        String classPath = "/tmp/classes";
        BasicCustomClassLoader loader = new BasicCustomClassLoader(classPath);
        
        Class<?> clazz = loader.loadClass("com.example.MyService");
        Object instance = clazz.getDeclaredConstructor().newInstance();
        
        System.out.println("Class loaded by: " + clazz.getClassLoader());
        System.out.println("Instance class: " + instance.getClass().getName());
    }
```

```java
import java.io.*;
import java.nio.file.*;

/**
 * 热部署类加载器
 * 支持运行时重新加载修改后的类
 */
public class HotSwapClassLoader extends ClassLoader {
    
    private String classPath;
    
    public HotSwapClassLoader(String classPath) {
        super(HotSwapClassLoader.class.getClassLoader());
        this.classPath = classPath;
    }
    
    /**
     * 热加载方法：每次调用都重新读取字节码
     * 不检查findLoadedClass缓存
     */
    public Class<?> hotLoad(String name) throws ClassNotFoundException {
        // 直接调用findClass，绕过双亲委派的缓存检查
        return findClass(name);
    }
    
    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        byte[] classData = loadClassData(name);
        if (classData == null) {
            throw new ClassNotFoundException(name);
        }
        return defineClass(name, classData, 0, classData.length);
    }
    
    private byte[] loadClassData(String name) {
        String path = classPath + File.separatorChar 
            + name.replace('.', File.separatorChar) + ".class";
        
        try {
            return Files.readAllBytes(Paths.get(path));
        } catch (IOException e) {
            return null;
        }
    }
}

/**
 * 热部署管理器
 * 监控类文件变化并自动重新加载
 */
class HotSwapManager {
    
    private HotSwapClassLoader classLoader;
    private String classPath;
    private String className;
    private Object currentInstance;
    
    public HotSwapManager(String classPath, String className) {
        this.classPath = classPath;
        this.className = className;
        this.classLoader = new HotSwapClassLoader(classPath);
    }
    
    /**
     * 获取当前实例（可能是最新重新加载的）
     */
    public Object getInstance() throws Exception {
        // 检查类文件是否已修改
        if (isClassModified()) {
            reloadClass();
        }
        return currentInstance;
    }
    
    private boolean isClassModified() {
        // 简化实现：每次都重新加载
        // 实际生产环境应该比较文件修改时间戳
        return true;
    }
    
    private void reloadClass() throws Exception {
        // 1. 创建新的ClassLoader
        // 关键：必须创建新的ClassLoader，否则defineClass会报错（类已存在）
        classLoader = new HotSwapClassLoader(classPath);
        
        // 2. 重新加载类
        Class<?> clazz = classLoader.hotLoad(className);
        
        // 3. 创建新实例
        currentInstance = clazz.getDeclaredConstructor().newInstance();
        
        System.out.println("Class reloaded: " + className);
    }
    
    /**
     * 演示：循环执行，支持热更新
     */
    public static void main(String[] args) throws Exception {
        HotSwapManager manager = new HotSwapManager(
            "/tmp/hotswap", 
            "com.example.Service"
        );
        
        while (true) {
            Object service = manager.getInstance();
            service.getClass()
                   .getMethod("execute")
                   .invoke(service);
            
            Thread.sleep(5000);  // 5秒后重新加载
        }
    }
}
```

### 3. 加密类加载器

```java
import javax.crypto.Cipher;
import javax.crypto.spec.SecretKeySpec;
import java.io.*;
import java.nio.file.Files;
import java.nio.file.Paths;
import java.security.Key;

/**
 * 加密类加载器
 * 加载经过AES加密的类文件，防止反编译
 */
public class EncryptedClassLoader extends ClassLoader {
    
    private String classPath;
    private Key secretKey;
    
    public EncryptedClassLoader(String classPath, byte[] keyBytes) {
        this.classPath = classPath;
        this.secretKey = new SecretKeySpec(keyBytes, "AES");
    }
    
    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        // 1. 读取加密后的类文件
        byte[] encryptedData = loadEncryptedClass(name);
        
        // 2. 解密
        byte[] decryptedData = decrypt(encryptedData);
        
        // 3. 定义类
        return defineClass(name, decryptedData, 0, decryptedData.length);
    }
    
    private byte[] loadEncryptedClass(String name) {
        String path = classPath + File.separatorChar 
            + name.replace('.', File.separatorChar) + ".class.encrypted";
        try {
            return Files.readAllBytes(Paths.get(path));
        } catch (IOException e) {
            throw new RuntimeException("Failed to load encrypted class", e);
        }
    }
    
    private byte[] decrypt(byte[] encryptedData) {
        try {
            Cipher cipher = Cipher.getInstance("AES");
            cipher.init(Cipher.DECRYPT_MODE, secretKey);
            return cipher.doFinal(encryptedData);
        } catch (Exception e) {
            throw new RuntimeException("Failed to decrypt class", e);
        }
    }
    
    /**
     * 加密工具方法（用于部署前加密类文件）
     */
    public static void encryptClassFile(String inputPath, String outputPath, 
                                         byte[] keyBytes) throws Exception {
        byte[] classData = Files.readAllBytes(Paths.get(inputPath));
        
        Key key = new SecretKeySpec(keyBytes, "AES");
        Cipher cipher = Cipher.getInstance("AES");
        cipher.init(Cipher.ENCRYPT_MODE, key);
        
        byte[] encryptedData = cipher.doFinal(classData);
        Files.write(Paths.get(outputPath), encryptedData);
    }
    
    public static void main(String[] args) throws Exception {
        // 加密密钥（实际生产环境应使用密钥管理系统）
        byte[] key = "MySecretKey12345".getBytes();  // 16字节AES密钥
        
        // 使用加密类加载器加载类
        EncryptedClassLoader loader = new EncryptedClassLoader("/tmp/encrypted", key);
        Class<?> clazz = loader.loadClass("com.example.ProtectedClass");
        
        Object instance = clazz.getDeclaredConstructor().newInstance();
        System.out.println("Encrypted class loaded successfully");
    }
```

```java
        this.exportedPackages = exportedPackages != null ? 
            exportedPackages : new HashSet<>();
    }
    
    /**
     * 控制类的可见性：
     * - 导出的包中的类可以被其他插件使用
     * - 未导出的包中的类仅自己可见
     */
    @Override
    public Class<?> loadClass(String name, boolean resolve) 
            throws ClassNotFoundException {
        
        // 1. 检查是否是导出的包
        String packageName = getPackageName(name);
        boolean isExported = exportedPackages.stream()
            .anyMatch(pkg -> packageName.equals(pkg) || packageName.startsWith(pkg + "."));
        
        // 2. 如果是导出的包，遵循双亲委派（可被父加载器缓存）
        if (isExported) {
            return super.loadClass(name, resolve);
        }
        
        // 3. 如果不是导出的包，先自己加载（隔离）
        Class<?> clazz = findLoadedClass(name);
        if (clazz == null) {
            try {
                clazz = findClass(name);  // 自己加载
            } catch (ClassNotFoundException e) {
                // 自己加载失败，再委派给父加载器
                clazz = super.loadClass(name, resolve);
            }
        }
        
        if (resolve) {
            resolveClass(clazz);
        }
        return clazz;
    }
    
    private String getPackageName(String className) {
        int lastDot = className.lastIndexOf('.');
        return lastDot == -1 ? "" : className.substring(0, lastDot);
    }
    
    public String getPluginId() {
        return pluginId;
    }
}

/**
 * 插件管理器
 */
class PluginManager {
    
    private Map<String, PluginClassLoader> pluginLoaders = new HashMap<>();
    
    /**
     * 加载插件
     */
    public void loadPlugin(String pluginId, String pluginPath,
                           Set<String> exportedPackages) throws Exception {
        File pluginDir = new File(pluginPath);
        URL[] urls = {pluginDir.toURI().toURL()};
        
        // 每个插件使用独立的ClassLoader，parent为System ClassLoader
        PluginClassLoader loader = new PluginClassLoader(
            pluginId, urls, 
            ClassLoader.getSystemClassLoader(),
            exportedPackages
        );
        
        pluginLoaders.put(pluginId, loader);
        
        // 加载插件入口类
        Class<?> pluginClass = loader.loadClass("plugin.Main");
        Object plugin = pluginClass.getDeclaredConstructor().newInstance();
        
        System.out.println("Plugin loaded: " + pluginId);
    }
    
    /**
     * 卸载插件（通过释放ClassLoader实现）
     */
    public void unloadPlugin(String pluginId) {
        PluginClassLoader loader = pluginLoaders.remove(pluginId);
        if (loader != null) {
            try {
                loader.close();
                System.out.println("Plugin unloaded: " + pluginId);
            } catch (IOException e) {
                e.printStackTrace();
            }
        }
    }
    
    /**
     * 获取插件中的类（用于插件间通信）
     */
    public Class<?> getPluginClass(String pluginId, String className) 
            throws ClassNotFoundException {
        PluginClassLoader loader = pluginLoaders.get(pluginId);
        if (loader == null) {
            throw new IllegalArgumentException("Plugin not found: " + pluginId);
        }
        return loader.loadClass(className);
    }
```

```java
    // 注册为并行 capable 的 ClassLoader 可以并行加载不同类

     * 类预加载（Eager Loading）
     */
    public static void preloadClasses() {
        // 在应用启动时预加载关键类
        String[] criticalClasses = {
            "java.util.HashMap",
            "java.util.ArrayList",
            "java.util.concurrent.ConcurrentHashMap",
            "com.example.CriticalService"
        };
        
        for (String className : criticalClasses) {
            try {
                Class.forName(className);
                System.out.println("Preloaded: " + className);
            } catch (ClassNotFoundException e) {
                System.err.println("Failed to preload: " + className);
            }
        }
    }

     * 使用线程池并行加载多个类
     */
    public static void parallelLoadClasses(String[] classNames) 
            throws InterruptedException, ExecutionException {
        
        ExecutorService executor = Executors.newFixedThreadPool(4);
        List<Future<Class<?>>> futures = new ArrayList<>();
        
        for (String className : classNames) {
            futures.add(executor.submit(() -> {
                return Class.forName(className);
            }));
        }
        
        // 等待所有类加载完成
        for (Future<Class<?>> future : futures) {
            Class<?> clazz = future.get();
            System.out.println("Loaded: " + clazz.getName());
        }
        
        executor.shutdown();
    }
    
    public static void main(String[] args) throws Exception {
        // 1. 预加载关键类
        preloadClasses();
        
        // 2. 并行加载多个类
        String[] classes = {
            "java.util.HashSet",
            "java.util.TreeMap",
            "java.util.LinkedList",
            "java.util.PriorityQueue"
```

## 面试题与参考答案

### Q1：类加载的完整过程是什么？每个阶段的作用？

**答**：类加载过程分为七个阶段：

1. **加载**：通过全限定名获取二进制字节流，在堆中生成Class对象
2. **验证**：确保字节码安全合法（文件格式、元数据、字节码、符号引用）
3. **准备**：为类变量分配内存并设置零值
4. **解析**：将符号引用替换为直接引用
5. **初始化**：执行`<clinit>()`方法，初始化静态变量
6. **使用**：程序主动使用类
7. **卸载**：类加载器被GC回收时卸载类

其中**验证**阶段最耗时（约占40%），但关闭验证（`-Xverify:none`）会带来安全风险。

### Q2：双亲委派机制是什么？为什么要用它？

**答**：

**机制**：类加载器收到加载请求时，先将请求委派给父加载器；父加载器无法加载时，子加载器才自己尝试加载。

**优点**：
1. **安全性**：防止核心类被篡改（如自定义`java.lang.String`会被Bootstrap拦截）
2. **避免重复加载**：父加载器加载的类对子加载器可见，不会重复加载
3. **保证扩展性**：核心API由Bootstrap加载，所有应用共享，保证稳定性

**源码实现**：`ClassLoader.loadClass()`方法中，先调用`findLoadedClass()`检查缓存，再递归调用`parent.loadClass()`委派，最后调用`findClass()`自己加载。

### Q3：哪些场景需要打破双亲委派？如何打破？

**答**：

**场景1：SPI机制（如JDBC）**
- 问题：`DriverManager`由Bootstrap加载，但需要加载AppClassLoader的驱动类
- 解决：使用`Thread.currentThread().getContextClassLoader()`

**场景2：Web应用隔离（Tomcat）**
- 问题：不同Web应用需要同一库的不同版本
- 解决：WebappClassLoader先自己加载`/WEB-INF/classes`和`/WEB-INF/lib`，失败再委派

**场景3：OSGi模块化**
- 问题：Bundle间需要类的版本隔离
- 解决：每个Bundle有自己的ClassLoader，通过Import-Package/Export-Package控制可见性

**打破方式**：重写`loadClass()`方法，改变"先委派后自己"的顺序为"先自己后委派"。

### Q4：Tomcat为什么要打破双亲委派？

**答**：

1. **Web应用隔离**：不同Web应用可能依赖同一库的不同版本（如Spring 4.x和5.x），双亲委派会导致版本冲突
2. **优先加载Web应用类**：WebappClassLoader优先加载`/WEB-INF/classes`和`/WEB-INF/lib`，确保应用自己的类优先于容器的类
3. **热部署支持**：每个Web应用独立的ClassLoader，更新时只需重建该ClassLoader，不影响其他应用
4. **安全性**：Web应用的类不会覆盖容器的核心类（`java.*`等仍然委派给Bootstrap）

**Tomcat的加载顺序**：先检查缓存 → 委派Bootstrap加载核心类 → 自己加载Web应用类 → 委派父加载器加载共享类。

### Q5：如何实现一个简单的热部署？

**答**：

```java
public class HotSwapClassLoader extends ClassLoader {
    private String classPath;
    
    public HotSwapClassLoader(String classPath) {
        this.classPath = classPath;
    }
    
    // 关键：绕过findLoadedClass缓存
    public Class<?> hotLoad(String name) throws ClassNotFoundException {
        return findClass(name);  // 直接重新加载
    }
    
    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        byte[] data = loadClassData(name);
        return defineClass(name, data, 0, data.length);
    }
}

// 使用：每次创建新的ClassLoader
public void reload() throws Exception {
    // 必须创建新的ClassLoader，因为同一个ClassLoader不能重复defineClass()
    HotSwapClassLoader newLoader = new HotSwapClassLoader("/tmp/classes");
    Class<?> clazz = newLoader.hotLoad("com.example.Service");
    Object instance = clazz.getDeclaredConstructor().newInstance();
}
```

**关键点**：
1. 重写`findClass()`而非`loadClass()`，保持对核心类的安全保护
2. 每次热部署创建新的ClassLoader（不能复用）
3. 旧ClassLoader和其实例必须被GC回收，否则导致Metaspace OOM
4. 旧实例不能强引用新ClassLoader加载的类（会出现ClassCastException）

### Q6：Bootstrap ClassLoader为什么获取为null？

**答**：Bootstrap ClassLoader由C++实现，不是Java对象，因此在Java代码中调用`getParent()`或`String.class.getClassLoader()`时返回null。

**设计原因**：
1. Bootstrap是JVM启动时最早需要的类加载器，此时Java对象系统尚未完全初始化
2. 使用C++可以直接操作底层资源，效率更高
3. null作为特殊标识，表示"最顶层的启动类加载器"

### Q7：自定义ClassLoader时应该重写loadClass()还是findClass()？

**答**：

**应该重写findClass()**，原因：
1. `loadClass()`包含了双亲委派的核心逻辑（检查缓存、委派父加载器）
2. 重写`loadClass()`容易破坏双亲委派，导致核心类被覆盖（安全风险）
3. `findClass()`只负责"从何处加载类"，符合单一职责原则
4. JDK设计意图就是让开发者重写`findClass()`

**例外情况**：如果需要打破双亲委派（如Tomcat、OSGi），则需要重写`loadClass()`，但必须谨慎处理核心类（`java.*`等仍应委派给Bootstrap）。

### Q8：Class.forName()和ClassLoader.loadClass()有什么区别？

**答**：

| 特性 | Class.forName() | ClassLoader.loadClass() |
|------|----------------|------------------------|
| 初始化 | 默认会触发类初始化 | 不会触发初始化（懒加载） |
| 类加载器 | 使用调用者的类加载器 | 使用指定的类加载器 |
| 使用场景 | 需要立即初始化（如JDBC驱动注册） | 只需要加载类定义 |

```java
// Class.forName() 触发初始化
Class.forName("com.mysql.cj.jdbc.Driver");  // 会执行static块注册驱动

// ClassLoader.loadClass() 不触发初始化
ClassLoader.getSystemClassLoader().loadClass("com.mysql.cj.jdbc.Driver");  
// 只加载类，不执行static块
```

### Q9：什么是类加载器的命名空间？不同命名空间的类可以互转吗？

**答**：

**命名空间**：每个类加载器实例都有自己的命名空间，由该加载器及其所有父加载器加载的类组成。同一个类在不同命名空间中被视为不同的类。

**互转限制**：
- 同一命名空间内的类可以正常互转
- 不同命名空间的类即使全限定名相同，也不能直接强制转换（会抛出ClassCastException）
- 解决方式：使用反射或公共接口（由父加载器加载）

```java
// 演示：不同ClassLoader加载的同一类不能互转
ClassLoader loader1 = new CustomClassLoader();
ClassLoader loader2 = new CustomClassLoader();

Class<?> class1 = loader1.loadClass("com.example.User");
Class<?> class2 = loader2.loadClass("com.example.User");

System.out.println(class1 == class2);  // false！
System.out.println(class1.equals(class2));  // false！
```

### Q10：JVM如何卸载一个类？类卸载的条件是什么？

**答**：

**类卸载条件**（必须同时满足）：
1. 该类的所有实例都已被GC回收
2. 加载该类的ClassLoader实例已被GC回收
3. 该类的Class对象没有在任何地方被引用（反射等）

**触发时机**：
- 类卸载发生在Full GC时
- JVM会检查满足上述条件的类，将其从方法区（Metaspace）中移除

**实践注意**：
- 自定义ClassLoader实现热部署时，必须确保旧ClassLoader及其加载的所有实例都被释放
- 常见的阻碍：ThreadLocal未清理、静态集合持有引用、监听器未注销
