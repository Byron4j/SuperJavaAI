## 引言：分布式锁的本质与挑战

分布式锁不是"在分布式环境下实现互斥"这么简单，而是一门**在不可靠网络环境中保证互斥性、活性与容错性**的分布式协调技术。

核心认知：

```
单机锁的本质：P(lock_acquired | single_jvm) ∈ {0, 1}
分布式锁的本质：P(lock_acquired | distributed_system) ∈ [0, 1]

质量差异的根源：
- 差的分布式锁：网络分区下互斥性失效 → 数据竞争、超卖、重复处理
- 好的分布式锁：在分区容忍的前提下，最大化可用性和一致性
```

**关键洞察**：分布式锁的效果不取决于"某个方案的绝对好坏"，而取决于**业务场景对CAP的权衡**是否匹配锁方案的保证级别。

## 理论基础：分布式锁原理

### 1. 为什么需要分布式锁？

单机环境下用`synchronized`或`ReentrantLock`即可保证线程安全。分布式环境下：

```
┌─────────────────────────────────────────────────────┐
│                    负载均衡器                        │
│                      Nginx                          │
└───────────┬─────────────────────────────┬───────────┘
            │                             │
    ┌───────▼────────┐          ┌────────▼────────┐
    │   应用服务 A    │          │    应用服务 B    │
    │  (JVM实例1)    │          │   (JVM实例2)     │
    │                │          │                 │
    │ synchronized   │          │  synchronized   │
    │ (只保护JVM1内)  │          │ (只保护JVM2内)   │
    └───────┬────────┘          └────────┬────────┘
            │                             │
            └──────────────┬──────────────┘
                           │
                    ┌──────▼──────┐
                    │   共享资源   │
                    │  (库存/订单) │
                    └─────────────┘

问题：synchronized只能保护单个JVM内的线程互斥
      两个JVM实例可以同时操作共享资源！
```

分布式锁解决的核心问题：
- **多节点竞争**：多个服务实例竞争同一资源
- **跨进程互斥**：需要独立于进程的协调机制
- **容错性要求**：锁服务必须具备故障恢复能力

### 2. 分布式锁的形式化定义

**分布式锁是一个五元组 (L, acquire, release, timeout, fencing_token)**：

- **L**：锁的状态 {LOCKED(token), UNLOCKED}
- **acquire(resource, client_id)**：获取锁
- **release(resource, token)**：释放锁
- **timeout**：锁自动过期时间
- **fencing_token**：单调递增的令牌

**必须满足的核心属性**：

#### 互斥性
```
∀t₁, t₂, client₁ ≠ client₂:
    hold_lock(t₁, client₁) ∧ hold_lock(t₂, client₂) ∧ (t₁ ∩ t₂ ≠ ∅)
    ⇒ client₁ = client₂
```

#### 无死锁
```
∀client: crashed(client) ⇒ ∃T: after_time(T) ⇒ lock_status = UNLOCKED
```

#### 活性
```
∀client, resource: try_acquire(client, resource) ∧ ¬crashed(client)
    ⇒ ◇(hold_lock(client, resource))
```

#### 可重入
```
∀client, resource: hold_lock(client, resource) ∧ acquire(client, resource)
    ⇒ hold_count(client, resource) = hold_count + 1
```

### 2. 基础实现：SET NX EX

```java
@Component
public class RedisDistributedLock {
    
    private final StringRedisTemplate redisTemplate;
    private final String lockKey;
    private final String lockValue;
    private final long expireTime;
    
    public RedisDistributedLock(StringRedisTemplate redisTemplate, 
                                 String lockKey, long expireTime) {
        this.redisTemplate = redisTemplate;
        this.lockKey = lockKey;
        this.lockValue = UUID.randomUUID().toString() + "_" + Thread.currentThread().getId();
        this.expireTime = expireTime;
    }
    
    public boolean tryLock() {
        Boolean success = redisTemplate.opsForValue()
            .setIfAbsent(lockKey, lockValue, expireTime, TimeUnit.SECONDS);
        return Boolean.TRUE.equals(success);
    }
    
    public boolean tryLock(long waitTime, TimeUnit unit) throws InterruptedException {
        long deadline = System.nanoTime() + unit.toNanos(waitTime);
        while (true) {
            if (tryLock()) return true;
            long remaining = deadline - System.nanoTime();
            if (remaining <= 0) return false;
            Thread.sleep(Math.min(remaining / 1_000_000, 100));
        }
    }
    
    public void unlock() {
        String script = 
            "if redis.call('get', KEYS[1]) == ARGV[1] then " +
            "    return redis.call('del', KEYS[1]) " +
            "else " +
            "    return 0 " +
            "end";
        
        Long result = redisTemplate.execute(
            new DefaultRedisScript<>(script, Long.class), 
            Collections.singletonList(lockKey), lockValue);
        
        if (result != null && result == 1) {
            log.info("锁释放成功: {}", lockKey);
        } else {
            log.warn("锁释放失败: {}", lockKey);
        }
    }
}
```

**为什么必须用Lua脚本释放锁？**

```
非原子操作的问题：

t=0: Client A 获取锁，设置 value=tokenA, TTL=30s
t=1: Client A 检查 value == tokenA（GET操作，返回tokenA）
t=2: 锁过期（TTL=30s到期）
t=3: Client B 获取锁，设置 value=tokenB, TTL=30s
t=4: Client A 执行 DEL（基于t=1的检查结果）
      → 删除了 Client B 的锁！
t=5: Client C 获取锁成功
      → Client B 和 Client C 同时持有锁！

Lua脚本解决方案：
- Lua脚本在Redis服务端原子执行
- GET 和 DEL 在一个脚本中完成
- 不会被其他命令打断
```

### 3. Redisson实现深度解析

```java
@Configuration
public class RedissonConfig {
    
    @Bean
    public RedissonClient redissonClient() {
        Config config = new Config();
        config.useSingleServer()
            .setAddress("redis://localhost:6379")
            .setConnectionMinimumIdleSize(10)
            .setConnectionPoolSize(64)
            .setConnectTimeout(10000)
            .setTimeout(3000)
            .setRetryAttempts(3)
            .setRetryInterval(1500);
        return Redisson.create(config);
    }
}

@Service
public class OrderService {
    
    @Autowired
    private RedissonClient redissonClient;
    
    public void createOrder(Long orderId) {
        RLock lock = redissonClient.getLock("order:" + orderId);
        try {
            boolean locked = lock.tryLock(3, 10, TimeUnit.SECONDS);
            if (!locked) {
                throw new BusinessException("获取锁失败，订单正在处理中");
            }
            try {
                doCreateOrder(orderId);
            } finally {
                if (lock.isHeldByCurrentThread()) {
                    lock.unlock();
                }
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new BusinessException("获取锁被中断");
        }
    }
    
    public void createOrderFair(Long orderId) {
        RLock fairLock = redissonClient.getFairLock("order:fair:" + orderId);
        try {
            fairLock.lock();
            doCreateOrder(orderId);
        } finally {
            fairLock.unlock();
        }
    }
    
    public void readOrder(Long orderId) {
        RReadWriteLock rwLock = redissonClient.getReadWriteLock("order:rw:" + orderId);
        RLock readLock = rwLock.readLock();
        try {
            readLock.lock();
            return getOrder(orderId);
        } finally {
            readLock.unlock();
        }
    }
    
    public void updateOrder(Long orderId) {
        RReadWriteLock rwLock = redissonClient.getReadWriteLock("order:rw:" + orderId);
        RLock writeLock = rwLock.writeLock();
        try {
            writeLock.lock();
            doUpdateOrder(orderId);
        } finally {
            writeLock.unlock();
        }
    }
}
```

### 4. Redisson看门狗机制

```java
public class WatchdogMechanism {
    
    public void demo() {
        RLock lock = redissonClient.getLock("myLock");
        lock.lock(); // 不指定leaseTime时，启用看门狗
        try {
            doLongRunningTask(); // 业务逻辑可能执行很长时间
            // 看门狗线程每隔10秒检查一次
            // 如果锁仍被当前线程持有，续期到30秒
        } finally {
            lock.unlock(); // 释放锁时，看门狗停止续期
        }
    }
    
    class Watchdog {
        private final long lockWatchdogTimeout = 30 * 1000; // 30秒
        private final Timer timer = new Timer();
        
        public void scheduleExpirationRenewal(String lockKey, String threadId) {
            TimerTask task = new TimerTask() {
                @Override
                public void run() {
                    if (isHeldByCurrentThread(lockKey, threadId)) {
                        renewExpiration(lockKey, threadId);
                        scheduleExpirationRenewal(lockKey, threadId);
                    }
                }
            };
            timer.schedule(task, lockWatchdogTimeout / 3); // 10秒后检查
        }
    }
}
```

### 6. Redis锁的完整Lua脚本集合

```lua
-- 1. 获取锁（原子操作，支持可重入）
if redis.call('exists', KEYS[1]) == 0 then
    redis.call('hset', KEYS[1], 'value', ARGV[1])
    redis.call('hincrby', KEYS[1], 'count', 1)
    redis.call('pexpire', KEYS[1], ARGV[2])
    return nil
end

if redis.call('hexists', KEYS[1], 'value') == 1 and 
   redis.call('hget', KEYS[1], 'value') == ARGV[1] then
    redis.call('hincrby', KEYS[1], 'count', 1)
    redis.call('pexpire', KEYS[1], ARGV[2])
    return nil
end

return redis.call('pttl', KEYS[1])

-- 2. 释放锁（原子操作）
if redis.call('hexists', KEYS[1], 'value') == 0 then
    return nil
end

local counter = redis.call('hincrby', KEYS[1], 'count', -1)

if counter > 0 then
    redis.call('pexpire', KEYS[1], ARGV[2])
    return 0
else
    redis.call('del', KEYS[1])
    return 1
end

-- 3. 强制释放（不检查持有者）
redis.call('del', KEYS[1])
return 1

-- 4. 检查锁状态
return redis.call('exists', KEYS[1])
```

### 7. Redis锁的优缺点

**优点**：
- **性能极高**：内存操作，QPS 10万+
- **使用广泛**：社区活跃，文档丰富
- **功能完善**：Redisson支持可重入、看门狗、读写锁、红锁
- **运维简单**：单节点或主从部署成本低

**缺点**：
- **主从延迟**：主从切换时可能丢失锁
- **时钟依赖**：TTL判断依赖系统时钟
- **无强一致**：AP模型，不保证强一致性
- **RedLock争议**：算法本身有争议，不能替代CP方案

### 2. 实现原理：临时顺序节点

```
Zookeeper分布式锁的核心机制：

1. 创建阶段：
   客户端在 /locks/{resource} 下创建临时顺序节点
   /locks/order/lock-00000001  ← Client A创建
   /locks/order/lock-00000002  ← Client B创建
   /locks/order/lock-00000003  ← Client C创建

2. 判断阶段：
   获取 /locks/order 下的所有子节点，按序号排序
   如果自己的节点序号最小，获得锁
   
3. 等待阶段：
   如果自己的节点不是最小，监听前一个节点
   Client B 监听 /locks/order/lock-00000001
   Client C 监听 /locks/order/lock-00000002

4. 通知阶段：
   前一个节点删除（释放锁），收到Watcher通知
   重新判断自己是否是序号最小的节点

5. 容错阶段：
   客户端断开连接，临时节点自动删除，释放锁

为什么用临时顺序节点？
- 临时节点：客户端断开后自动删除，防止死锁
- 顺序节点：保证公平性，先请求的客户端先获得锁
```

```java
@Component
public class ZookeeperDistributedLock {
    
    private final CuratorFramework client;
    private final ConcurrentMap<String, InterProcessMutex> lockCache = 
        new ConcurrentHashMap<>();
    
    public ZookeeperDistributedLock(String zkAddress) {
        this.client = CuratorFrameworkFactory.newClient(
            zkAddress,
            new ExponentialBackoffRetry(1000, 3)
        );
        this.client.start();
    }
    
    public void lock(String lockPath) throws Exception {
        InterProcessMutex lock = lockCache.computeIfAbsent(
            lockPath, 
            path -> new InterProcessMutex(client, "/locks/" + path)
        );
        lock.acquire();
    }
    
    public boolean tryLock(String lockPath, long timeout, TimeUnit unit) 
            throws Exception {
        InterProcessMutex lock = lockCache.computeIfAbsent(
            lockPath,
            path -> new InterProcessMutex(client, "/locks/" + path)
        );
        return lock.acquire(timeout, unit);
    }
    
    public void unlock(String lockPath) throws Exception {
        InterProcessMutex lock = lockCache.get(lockPath);
        if (lock != null && lock.isAcquiredInThisProcess()) {
            lock.release();
        }
    }
    
    public boolean acquireLock(String lockPath, long timeout, TimeUnit unit) 
            throws Exception {
        String path = client.create()
            .creatingParentsIfNeeded()
            .withMode(CreateMode.EPHEMERAL_SEQUENTIAL)
            .forPath("/locks/" + lockPath + "/lock-");
        
        try {
            long deadline = System.currentTimeMillis() + unit.toMillis(timeout);
            
            while (true) {
                List<String> children = client.getChildren()
                    .forPath("/locks/" + lockPath);
                Collections.sort(children);
                
                String nodeName = path.substring(path.lastIndexOf("/") + 1);
                int index = children.indexOf(nodeName);
                
                if (index == 0) {
                    return true;
                }
                
                String prevNode = children.get(index - 1);
                final CountDownLatch latch = new CountDownLatch(1);
                
                Stat stat = client.checkExists()
                    .usingWatcher((Watcher) event -> {
                        if (event.getType() == EventType.NodeDeleted) {
                            latch.countDown();
                        }
                    })
                    .forPath("/locks/" + lockPath + "/" + prevNode);
                
                if (stat == null) {
                    continue;
                }
                
                long waitTime = deadline - System.currentTimeMillis();
                if (waitTime <= 0) {
                    client.delete().forPath(path);
                    return false;
                }
                
                if (!latch.await(waitTime, TimeUnit.MILLISECONDS)) {
                    client.delete().forPath(path);
                    return false;
                }
            }
            
        } catch (Exception e) {
            client.delete().quietly().forPath(path);
            throw e;
        }
    }
}
```

```java
     * 推荐：
     * - 生产环境：30秒（tickTime的15倍）
     * - 业务执行时间必须小于Session超时时间
     */
}
```

### 6. Zookeeper锁的优缺点

**优点**：
- **强一致性**：ZAB协议保证写操作的原子性和顺序性
- **自动释放**：临时节点随Session过期自动删除，防死锁
- **无时钟问题**：不依赖TTL，基于Session心跳
- **可重入**：Curator的InterProcessMutex支持
- **公平锁**：顺序节点保证FIFO

**缺点**：
- **性能较低**：需要创建节点、设置Watcher，QPS约1万
- **运维成本**：需要维护Zookeeper集群
- **Session超时**：网络闪断可能导致锁提前释放
- **羊群效应**：大量客户端同时监听同一个节点，释放时惊群

### 2. Lease机制详解

```java
@Component
public class EtcdDistributedLock {
    
    private final Client etcdClient;
    private final Lease leaseClient;
    private final KV kvClient;
    private final Lock lockClient;
    
    public EtcdDistributedLock(String endpoints) {
        this.etcdClient = Client.builder()
            .endpoints(endpoints.split(","))
            .build();
        this.leaseClient = etcdClient.getLeaseClient();
        this.kvClient = etcdClient.getKVClient();
        this.lockClient = etcdClient.getLockClient();
    }
    
    public LockResult tryLock(String lockKey, long ttlSeconds) throws Exception {
        long leaseId = leaseClient.grant(ttlSeconds).get().getID();
        
        leaseClient.keepAlive(leaseId, new StreamObserver<LeaseKeepAliveResponse>() {
            @Override
            public void onNext(LeaseKeepAliveResponse response) {
                log.debug("Lease续租成功, leaseId={}, TTL={}", 
                    response.getID(), response.getTTL());
            }
            
            @Override
            public void onError(Throwable t) {
                log.error("KeepAlive error", t);
            }
            
            @Override
            public void onCompleted() {
                log.info("KeepAlive completed");
            }
        });
        
        ByteSequence key = ByteSequence.from(lockKey, StandardCharsets.UTF_8);
        ByteSequence value = ByteSequence.from("locked", StandardCharsets.UTF_8);
        
        PutOption putOption = PutOption.newBuilder()
            .withLeaseId(leaseId)
            .build();
        
        Txn txn = kvClient.txn();
        Cmp cmp = new Cmp(key, Cmp.Op.EQUAL, CmpTarget.version(0));
        
        TxnResponse response = txn.If(cmp)
            .Then(Op.put(key, value, putOption))
            .commit()
            .get();
        
        if (response.isSucceeded()) {
            return new LockResult(true, leaseId, null);
        } else {
            leaseClient.revoke(leaseId).get();
            return new LockResult(false, -1, "锁已被其他客户端持有");
        }
    }
    
    public void unlock(String lockKey, long leaseId) throws Exception {
        ByteSequence key = ByteSequence.from(lockKey, StandardCharsets.UTF_8);
        kvClient.delete(key).get();
        leaseClient.revoke(leaseId).get();
        log.info("锁释放成功: {}", lockKey);
    }
    
    @Data
    @AllArgsConstructor
    public static class LockResult {
        private boolean success;
        private long leaseId;
        private String message;
    }
}
```

### 2. Java实现

```java
public class RedLock {
    
    private final List<Jedis> jedisNodes;
    private final int quorum;
    private final int defaultTtl;
    
    public RedLock(List<Jedis> nodes, int defaultTtl) {
        this.jedisNodes = nodes;
        this.quorum = nodes.size() / 2 + 1;
        this.defaultTtl = defaultTtl;
    }
    
    public boolean tryLock(String resource, String value, int ttl) {
        long startTime = System.currentTimeMillis();
        int successCount = 0;
        List<Jedis> lockedNodes = new ArrayList<>();
        
        for (Jedis jedis : jedisNodes) {
            try {
                String result = jedis.set(resource, value, "NX", "EX", ttl);
                if ("OK".equals(result)) {
                    successCount++;
                    lockedNodes.add(jedis);
                }
            } catch (Exception e) {
                log.warn("Failed to lock node: {}", jedis.getClient().getHost(), e);
            }
        }
        
        long elapsed = System.currentTimeMillis() - startTime;
        
        if (successCount >= quorum && elapsed < ttl * 1000) {
            log.info("RedLock acquired, success: {}/{}, elapsed: {}ms", 
                successCount, jedisNodes.size(), elapsed);
            return true;
        }
        
        log.warn("RedLock failed, success: {}/{}, releasing partial locks", 
            successCount, jedisNodes.size());
        
        for (Jedis jedis : lockedNodes) {
            try {
                String unlockScript = 
                    "if redis.call('get', KEYS[1]) == ARGV[1] then " +
                    "    return redis.call('del', KEYS[1]) " +
                    "else " +
                    "    return 0 " +
                    "end";
                
                jedis.eval(unlockScript, 
                    Collections.singletonList(resource),
                    Collections.singletonList(value));
            } catch (Exception e) {
                log.warn("Failed to release lock on node", e);
            }
        }
        
        return false;
    }
    
    public void unlock(String resource, String value) {
        String unlockScript = 
            "if redis.call('get', KEYS[1]) == ARGV[1] then " +
            "    return redis.call('del', KEYS[1]) " +
            "else " +
            "    return 0 " +
            "end";
        
        for (Jedis jedis : jedisNodes) {
            try {
                jedis.eval(unlockScript,
                    Collections.singletonList(resource),
                    Collections.singletonList(value));
            } catch (Exception e) {
                log.warn("Failed to release lock on node", e);
            }
        }
    }
}
```

```
    /         \   /        \   /    \

   ▼          ▼  ▼          ▼  ▼     ▼

详细决策路径：

路径1：强一致性 + 已有ZK集群 → Zookeeper
      理由：无需引入新组件，ZAB保证强一致

路径2：强一致性 + 无ZK + 性能不敏感 → etcd
      理由：云原生友好，Raft强一致，gRPC高性能

路径3：强一致性 + 无ZK + 性能敏感 → etcd（集群优化）
      理由：etcd性能优于ZK，且保证强一致

路径4：最终一致 + 高并发 → Redis（Redisson）
      理由：10万+QPS，看门狗自动续期，功能完善

路径5：最终一致 + 低并发 + 简单场景 → 数据库锁
      理由：无需额外中间件，实现简单
```

```java
@Service
public class SeckillService {
    
    @Autowired
    private CuratorFramework zkClient;
    
    @Autowired
    private StringRedisTemplate redisTemplate;
    
    @Autowired
    private InventoryMapper inventoryMapper;
    
    @Autowired
    private RocketMQTemplate rocketMQTemplate;
    
    private static final String STOCK_KEY_PREFIX = "seckill:stock:";
    private static final String LOCK_PATH_PREFIX = "/locks/seckill/";
    
    public SeckillResult deductStock(Long skuId, Long userId, int quantity) {
        String stockKey = STOCK_KEY_PREFIX + skuId;
        String lockPath = LOCK_PATH_PREFIX + skuId;
        
        // 1. Redis预减库存（快速失败，大部分请求在这里被拦截）
        Long stock = redisTemplate.opsForValue().decrement(stockKey, quantity);
        
        if (stock == null || stock < 0) {
            if (stock != null) {
                redisTemplate.opsForValue().increment(stockKey, quantity);
            }
            return SeckillResult.fail("库存不足");
        }
        
        // 2. 使用Zookeeper锁保护数据库扣减（强一致）
        InterProcessMutex lock = new InterProcessMutex(zkClient, lockPath);
        
        try {
            if (!lock.acquire(3, TimeUnit.SECONDS)) {
                redisTemplate.opsForValue().increment(stockKey, quantity);
                return SeckillResult.fail("系统繁忙，请重试");
            }
            
            try {
                // 3. 双重检查：查数据库真实库存
                Integer dbStock = inventoryMapper.getStock(skuId);
                
                if (dbStock == null || dbStock < quantity) {
                    redisTemplate.opsForValue().increment(stockKey, quantity);
                    return SeckillResult.fail("库存不足");
                }
                
                // 4. 扣减数据库库存
                int updated = inventoryMapper.decrementStock(skuId, quantity);
                
                if (updated == 0) {
                    redisTemplate.opsForValue().increment(stockKey, quantity);
                    return SeckillResult.fail("库存不足");
                }
                
                // 5. 发送创建订单消息（异步）
                SeckillOrderMessage message = new SeckillOrderMessage();
                message.setSkuId(skuId);
                message.setUserId(userId);
                message.setQuantity(quantity);
                rocketMQTemplate.asyncSend("seckill-order-topic", message, new SendCallback() {
                    @Override
                    public void onSuccess(SendResult sendResult) {
                        log.info("秒杀订单消息发送成功");
                    }
                    
                    @Override
                    public void onException(Throwable throwable) {
                        log.error("秒杀订单消息发送失败", throwable);
                    }
                });
                
                return SeckillResult.success("抢购成功");
                
            } finally {
                lock.release();
            }
            
        } catch (Exception e) {
            redisTemplate.opsForValue().increment(stockKey, quantity);
            log.error("秒杀扣减库存失败", e);
            return SeckillResult.fail("系统异常");
        }
    }
}
```

```java
            "local now = tonumber(ARGV[1]) " +
            "local window = tonumber(ARGV[2]) " +

            "local current = redis.call('ZCARD', key) " +
            "if current < max then " +
            "    redis.call('ZADD', key, now, now) " +

            RScript.ReturnType.INTEGER,
            Collections.singletonList(key),
            now, windowSeconds * 1000, maxRequests
        );
```

```java
@Component
public class DistributedScheduler {
    
    @Autowired
    private Client etcdClient;
    
    private static final String LEADER_KEY = "/leader/scheduler";
    private volatile boolean isLeader = false;
    private long leaseId = -1;
    
    @PostConstruct
    public void campaignLeader() {
        new Thread(() -> {
            while (!Thread.currentThread().isInterrupted()) {
                try {
                    if (!isLeader) {
                        if (tryBecomeLeader()) {
                            isLeader = true;
                            log.info("成为Leader，开始执行定时任务");
                        }
                    } else {
                        keepAlive();
                    }
                    
                    Thread.sleep(5000);
                } catch (Exception e) {
                    log.error("Leader选举异常", e);
                    isLeader = false;
                }
            }
        }, "leader-election-thread").start();
    }
    
    private boolean tryBecomeLeader() throws Exception {
        Lease leaseClient = etcdClient.getLeaseClient();
        KV kvClient = etcdClient.getKVClient();
        
        leaseId = leaseClient.grant(10).get().getID();
        
        leaseClient.keepAlive(leaseId, new StreamObserver<LeaseKeepAliveResponse>() {
            @Override
            public void onNext(LeaseKeepAliveResponse response) {}
            
            @Override
            public void onError(Throwable t) {
                isLeader = false;
            }
            
            @Override
            public void onCompleted() {
                isLeader = false;
            }
        });
        
        ByteSequence key = ByteSequence.from(LEADER_KEY, StandardCharsets.UTF_8);
        ByteSequence value = ByteSequence.from(getInstanceId(), StandardCharsets.UTF_8);
        
        PutOption putOption = PutOption.newBuilder()
            .withLeaseId(leaseId)
            .build();
        
        Txn txn = kvClient.txn();
        Cmp cmp = new Cmp(key, Cmp.Op.EQUAL, CmpTarget.version(0));
        
        TxnResponse response = txn.If(cmp)
            .Then(Op.put(key, value, putOption))
            .commit()
            .get();
        
        return response.isSucceeded();
    }
    
    private void keepAlive() {
        // KeepAlive由etcd客户端自动处理
    }
    
    @Scheduled(fixedRate = 60000)
    public void scheduledTask() {
        if (!isLeader) {
            return;
        }
        
        try {
            log.info("Leader执行定时任务");
            doScheduledWork();
        } catch (Exception e) {
            log.error("定时任务执行失败", e);
        }
    }
    
    private String getInstanceId() throws UnknownHostException {
        return InetAddress.getLocalHost().getHostAddress() + ":" + System.currentTimeMillis();
    }
}
```

## 常见陷阱与最佳实践

### 陷阱1：锁未释放导致死锁

```java
// 错误做法：异常时未释放锁
public void badExample() {
    RLock lock = redisson.getLock("myLock");
    lock.lock();
    doSomething(); // 可能抛出异常
    lock.unlock(); // 异常时不会执行，导致死锁！
}

// 正确做法：使用try-finally确保释放
public void goodExample() {
    RLock lock = redisson.getLock("myLock");
    lock.lock();
    try {
        doSomething();
    } finally {
        lock.unlock(); // 确保释放
    }
}

// 更安全的做法：带超时的非阻塞锁
public void bestExample() {
    RLock lock = redisson.getLock("myLock");
    try {
        if (lock.tryLock(3, 10, TimeUnit.SECONDS)) {
            try {
                doSomething();
            } finally {
                if (lock.isHeldByCurrentThread()) {
                    lock.unlock();
                }
            }
        } else {
            log.warn("获取锁超时");
        }
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}
```

### 陷阱3：锁的可重入性

```java
// 错误：不可重入锁导致死锁
public void nonReentrantDeadlock() {
    Lock lock = new NonReentrantLock(); // 假设这是不可重入锁
    lock.lock();
    try {
        innerMethod(lock); // 内部再次获取同一把锁 → 死锁！
    } finally {
        lock.unlock();
    }
}

private void innerMethod(Lock lock) {
    lock.lock(); // 如果不可重入，这里会阻塞
    try {
        // do something
    } finally {
        lock.unlock();
    }
}

// 正确：使用可重入锁
public void reentrantLock() {
    RLock lock = redisson.getLock("myLock"); // Redisson默认可重入
    lock.lock();
    try {
        lock.lock(); // 可重入，计数+1
        try {
            // do something
        } finally {
            lock.unlock(); // 计数-1
        }
    } finally {
        lock.unlock(); // 计数-1，变为0，真正释放
    }
}
```

### 陷阱4：RedLock的误用

```
错误认知：
"RedLock是强一致的分布式锁，可以用于金融场景。"

实际情况：
- RedLock有争议（Martin Kleppmann的批评）
- 依赖系统时钟，时钟漂移会导致锁失效
- GC停顿可能导致锁过期后业务继续执行
- 不能替代Zookeeper/etcd的强一致性

正确做法：
- 强一致场景（金融、库存）：使用Zookeeper/etcd
- 一般场景（缓存、限流）：使用Redis（Redisson）
```

### 陷阱5：忽视业务幂等性

```java
// 错误：认为有了分布式锁就不需要幂等

public class NonIdempotentService {
    public void createOrder(OrderRequest request) {
        RLock lock = redisson.getLock("order:" + request.getOrderNo());
        try {
            if (lock.tryLock(3, 30, TimeUnit.SECONDS)) {
                try {
                    // 直接创建订单
                    doCreateOrder(request); // 如果锁失效，可能重复创建！
                } finally {
                    lock.unlock();
                }
            }
        } catch (Exception e) {
            throw new BusinessException("创建订单失败", e);
        }
    }
}

// 正确：分布式锁 + 业务幂等
@Service
public class IdempotentOrderService {
    
    @Autowired
    private OrderMapper orderMapper;
    
    public void createOrder(OrderRequest request) {
        RLock lock = redisson.getLock("order:" + request.getOrderNo());
        
        try {
            if (!lock.tryLock(3, 30, TimeUnit.SECONDS)) {
                throw new BusinessException("获取锁失败");
            }
            
            try {
                // 1. 幂等性检查（数据库唯一索引）
                if (orderMapper.exists(request.getOrderNo())) {
                    log.info("订单已存在，忽略重复提交");
                    return;
                }
                
                // 2. 执行业务
                doCreateOrder(request);
                
            } finally {
                lock.unlock();
            }
            
        } catch (Exception e) {
            throw new BusinessException("创建订单失败", e);
        }
    }
}
```

### 陷阱6：锁的过期时间设置不当

```java
// 错误：过期时间太短
public void shortExpireTime() {
    RLock lock = redisson.getLock("task");
    // 过期时间10秒，但任务可能执行30秒
    lock.lock(10, TimeUnit.SECONDS); // 任务执行到一半锁就过期了！
    try {
        doLongTask(); // 执行30秒
    } finally {
        lock.unlock(); // 可能释放的是别人的锁！
    }
}

// 正确：过期时间 = 业务最大执行时间 * 2
public void properExpireTime() {
    RLock lock = redisson.getLock("task");
    // 或者使用看门狗自动续期（推荐）
    lock.lock(); // 不指定过期时间，启用看门狗
    try {
        doLongTask();
    } finally {
        lock.unlock();
    }
}
```

### 陷阱7：未处理锁获取超时

```java
// 错误：无限期等待锁
public void infiniteWait() {
    RLock lock = redisson.getLock("resource");
    lock.lock(); // 如果锁一直被持有，会永远等待！
    try {
        doWork();
    } finally {
        lock.unlock();
    }
}

// 正确：设置等待超时
public void timeoutWait() {
    RLock lock = redisson.getLock("resource");
    try {
        // 最多等待5秒
        if (lock.tryLock(5, TimeUnit.SECONDS)) {
            try {
                doWork();
            } finally {
                lock.unlock();
            }
        } else {
            throw new BusinessException("获取锁超时，请稍后重试");
        }
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
        throw new BusinessException("获取锁被中断");
    }
}
```

## 面试题与参考答案

### Q1：Redis分布式锁的RedLock算法有什么问题？生产环境应该如何选择？

**参考答案**：

```
RedLock算法问题：

1. 时钟依赖：
   - RedLock依赖系统时钟计算超时
   - 如果某个Redis节点时钟比客户端快，锁可能提前过期
   - 时钟漂移（NTP同步）可能导致误判

2. GC停顿：
   - 客户端获取锁后发生Full GC（Stop-The-World）
   - 停顿期间锁过期，但客户端不知道
   - GC恢复后客户端继续执行业务，其他客户端可能已获取锁

3. 网络延迟：
   - 客户端向Redis发送请求，网络延迟导致超时
   - 客户端认为获取锁失败，但Redis实际上已设置锁
   - 导致锁泄漏

Martin Kleppmann的结论：
- RedLock不能提供比单节点Redis更强的一致性保证
- 如果需要强一致，应使用Zookeeper或etcd

生产环境选择：
┌──────────────────┬──────────────────────────────┐
│ 场景             │ 推荐方案                     │
├──────────────────┼──────────────────────────────┤
│ 强一致（金融）   │ Zookeeper/etcd               │
│ 一般场景（缓存） │ Redis（Redisson）            │
│ 高可用要求       │ Zookeeper/etcd（集群部署）   │
│ 性能优先         │ Redis（单节点或集群）        │
│ 云原生环境       │ etcd                         │
└──────────────────┴──────────────────────────────┘
```

### Q2：Zookeeper分布式锁为什么不会死锁？如果客户端崩溃会怎样？

**参考答案**：

```
不会死锁的原因：

1. 临时节点：
   - 客户端创建的是临时顺序节点（EPHEMERAL_SEQUENTIAL）
   - 临时节点的生命周期与客户端Session绑定

2. Session机制：
   - 客户端与Zookeeper维护长连接Session
   - 定期发送心跳维持Session

3. 自动清理：
   - 客户端崩溃或断连后，Session超时
   - Zookeeper自动删除该Session创建的所有临时节点
   - 锁被释放，等待的客户端可以获取锁

客户端崩溃处理流程：

t=0: Client A 创建临时节点 /locks/order/lock-00000001
t=1: Client A 获得锁，开始执行业务
t=2: Client A 崩溃（未释放锁）
t=3: Zookeeper Session超时（如30秒）
t=4: Zookeeper 自动删除 lock-00000001
t=5: Client B（监听 lock-00000001）收到删除通知
t=6: Client B 检查自己是否是序号最小的节点，获得锁

Session超时时间设置：
- 太短：网络闪断导致频繁重新连接和临时节点抖动
- 太长：客户端崩溃后，锁长时间不释放
- 推荐：2-5秒（tickTime的2-20倍）
```

### Q3：etcd的Lease机制如何保证锁的可靠性？与Redis的过期时间有什么区别？

**参考答案**：

```
etcd Lease机制：

1. 创建Lease：
   - 客户端创建Lease时指定TTL（如60秒）
   - etcd服务端统一管理Lease的过期时间

2. KeepAlive续租：
   - 客户端定期发送KeepAlive请求（如每10秒）
   - etcd服务端收到KeepAlive后重置Lease的过期时间
   - 续租是自动的，不需要客户端计算时间

3. 过期处理：
   - 客户端宕机或网络断开，无法发送KeepAlive
   - Lease到期后，etcd自动删除关联的key
   - 锁被释放，其他客户端可以获取

4. 一致性保证：
   - Lease状态通过Raft协议复制到所有节点
   - 即使Leader切换，Lease信息不会丢失

与Redis TTL的区别：

┌────────────────┬─────────────────┬──────────────────┐
│ 特性           │ Redis TTL       │ etcd Lease       │
├────────────────┼─────────────────┼──────────────────┤
│ 管理方         │ Redis服务端     │ etcd服务端       │
│ 时钟依赖       │ 依赖Redis时钟   │ 依赖etcd集群时钟 │
│ 续期方式       │ 客户端主动设置  │ 客户端KeepAlive  │
│ 过期精度       │ 可能有几秒误差  │ 更精确           │
│ 一致性         │ 最终一致        │ 强一致（Raft）   │
│ 容错性         │ 主从切换可能丢失│ Leader切换不丢失 │
└────────────────┴─────────────────┴──────────────────┘

etcd的优势：
- 强一致性：Lease状态通过Raft复制
- 更可靠：服务端统一管理，不受客户端时钟影响
- 可监听：可以监听Lease过期事件
- 云原生：Kubernetes核心组件，生态完善
```

### Q4：Redis主从延迟会导致锁丢失吗？详细分析。

**参考答案**：

```
会导致锁丢失。

场景分析：

t=0: Client A 在 Redis Master 获取锁
       SET mylock tokenA NX EX 30
       → Master 写入成功
       
t=1: Master 宕机（mylock 未同步到 Slave）
       → 由于主从是异步复制，锁数据可能还在Master内存中
       
t=2: Redis Sentinel 将 Slave 提升为 Master
       → 新Master没有mylock数据
       
t=3: Client B 在新 Master 获取锁
       SET mylock tokenB NX EX 30
       → 新Master没有mylock，写入成功
       
t=4: Client A 仍在执行业务（认为锁仍有效）
     Client B 也在执行业务
      → Client A 和 Client B 同时持有锁！

解决方案：

1. RedLock（有争议）：
   - 在多个独立Redis实例上加锁
   - 多数成功才算获取锁
   - 但RedLock本身有争议（时钟依赖、GC停顿）

2. 使用CP方案（推荐）：
   - 强一致场景使用Zookeeper或etcd
   - 写操作需要过半节点确认
   - 不存在主从切换导致的数据丢失

3. 业务层幂等性（兜底）：
   - 即使锁失效，业务也不会重复执行
   - 数据库唯一索引防止重复数据
   - 状态机校验防止重复处理

4. Redisson的看门狗（缓解）：
   - 自动续期减少过期窗口
   - 但不能解决主从切换的根本问题
```

### Q6：如何实现一个支持可重入的分布式锁？

**参考答案**：

```java
public class ReentrantDistributedLock {
    
    private final String lockName;
    private final RedissonClient redisson;
    
    // ThreadLocal记录当前线程持有的锁信息
    private final ThreadLocal<Map<String, LockData>> lockHolder = 
        ThreadLocal.withInitial(HashMap::new);
    
    @Data
    private static class LockData {
        final String lockName;
        final RLock lock;
        final AtomicInteger lockCount = new AtomicInteger(1);
        
        LockData(String lockName, RLock lock) {
            this.lockName = lockName;
            this.lock = lock;
        }
    }
    
    public void lock() {
        Map<String, LockData> locks = lockHolder.get();
        LockData lockData = locks.get(lockName);
        
        if (lockData != null) {
            lockData.getLockCount().incrementAndGet();
            return;
        }
        
        RLock lock = redisson.getLock(lockName);
        lock.lock();
        
        lockData = new LockData(lockName, lock);
        locks.put(lockName, lockData);
    }
    
    public void unlock() {
        Map<String, LockData> locks = lockHolder.get();
        LockData lockData = locks.get(lockName);
        
        if (lockData == null) {
            throw new IllegalStateException("Lock not held by current thread");
        }
        
        int count = lockData.getLockCount().decrementAndGet();
        
        if (count > 0) {
            return;
        }
        
        lockData.getLock().unlock();
        locks.remove(lockName);
        
        if (locks.isEmpty()) {
            lockHolder.remove();
        }
    }
}
```
