## 为什么需要与现有系统集成

### 企业现状

```markdown
典型企业技术栈：
├── 后端：Java/Spring Boot（80%）
├── 数据库：MySQL/PostgreSQL/Oracle
├── 缓存：Redis
├── 消息：Kafka/RabbitMQ/RocketMQ
├── 搜索：Elasticsearch
├── 微服务：Dubbo/Spring Cloud
├── 容器：Docker/Kubernetes
└── 监控：Prometheus/Grafana

问题：
1. 遗留系统无法替换
2. 数据分散在各系统
3. 技术栈已固定
4. 团队技能栈匹配
```

### 集成价值

```markdown
不集成的问题：
├── 数据孤岛
├── 重复开发

└── 成本高

集成的价值：
├── 复用现有资产
├── 平滑过渡
├── 降低风险
└── 快速落地
```

### 4. 使用 Agent

```java
@Service
public class OrderService {
    
    @Autowired
    private MindraClient mindraClient;
    
    @Autowired
    private OrderRepository orderRepo;
    
    /**
     * 使用 Agent 处理订单查询
     */
    public OrderResult queryOrder(String orderId, String userQuery) {
        // 1. 构建任务
        Task task = Task.builder()
            .type("ORDER_QUERY")
            .context(Map.of(
                "orderId", orderId,
                "userQuery", userQuery,
                "userRole", getCurrentUserRole()
            ))
            .build();
        
        // 2. 提交给 Agent
        TaskResult result = mindraClient.submit(task);
        
        // 3. 处理结果
        if (result.requiresHumanApproval()) {
            // 需要人工审批
            return OrderResult.pending(result.getApprovalTicketId());
        }
        
        return OrderResult.success(result.getData());
    }
    
    /**
     * 使用 Agent 处理退款
     */
    @MindraTask(agent = "order-processing", governance = true)
    public RefundResult processRefund(String orderId, BigDecimal amount) {
        // 此方法会自动经过治理检查
        
        Task task = Task.builder()
            .type("REFUND")
            .parameters(Map.of(
                "orderId", orderId,
                "amount", amount
            ))
            .build();
        
        return mindraClient.execute(task);
    }
}
```

### 5. 自定义 Agent

```java
/**
 * 自定义订单处理 Agent
 */
@Component
@MindraAgent(name = "custom-order-agent")
public class CustomOrderAgent implements Agent {
    
    @Autowired
    private OrderRepository orderRepo;
    
    @Autowired
    private PaymentService paymentService;
    
    @Override
    public AgentCapability getCapability() {
        return AgentCapability.builder()
            .name("custom-order-agent")
            .description("处理复杂订单场景")
            .supportedTasks(Arrays.asList("ORDER_QUERY", "ORDER_MODIFY", "BULK_CANCEL"))
            .build();
    }
    
    @Override
    public TaskResult execute(Task task) {
        return switch (task.getType()) {
            case "ORDER_QUERY" -> handleQuery(task);
            case "ORDER_MODIFY" -> handleModify(task);
            case "BULK_CANCEL" -> handleBulkCancel(task);
            default -> throw new UnsupportedTaskException(task.getType());
        };
    }
    
    private TaskResult handleQuery(Task task) {
        String orderId = task.getParameter("orderId");
        Order order = orderRepo.findById(orderId)
            .orElseThrow(() -> new OrderNotFoundException(orderId));
        
        return TaskResult.builder()
            .status(TaskStatus.SUCCESS)
            .data(order)
            .build();
    }
    
    private TaskResult handleBulkCancel(Task task) {
        List<String> orderIds = task.getParameter("orderIds");
        
        // 批量取消逻辑
        List<CancelResult> results = orderIds.stream()
            .map(this::cancelOrder)
            .collect(Collectors.toList());
        
        return TaskResult.builder()
            .status(TaskStatus.SUCCESS)
            .data(results)
            .build();
    }
    
    private CancelResult cancelOrder(String orderId) {
        try {
            Order order = orderRepo.findById(orderId)
                .orElseThrow(() -> new OrderNotFoundException(orderId));
            
            if (!order.canCancel()) {
                return CancelResult.failed(orderId, "Order cannot be cancelled");
            }
            
            // 执行取消
            order.cancel();
            orderRepo.save(order);
            
            // 触发退款（异步）
            paymentService.refundAsync(order);
            
            return CancelResult.success(orderId);
        } catch (Exception e) {
            return CancelResult.failed(orderId, e.getMessage());
        }
    }
}
```

## Mindra + 消息队列

### Kafka 集成

```java
/**
 * Kafka 消费者 - 接收任务
 */
@Component
public class MindraTaskConsumer {
    
    @KafkaListener(topics = "mindra-tasks", groupId = "mindra-agents")
    public void consumeTask(ConsumerRecord<String, Task> record) {
        Task task = record.value();
        
        // 提交给 Agent 执行
        TaskResult result = agentService.execute(task);
        
        // 发送结果到结果 Topic
        kafkaTemplate.send("mindra-results", result);
    }
}

/**
 * Kafka 生产者 - 发送结果
 */
@Component
public class MindraResultProducer {
    
    @Autowired
    private KafkaTemplate<String, TaskResult> kafkaTemplate;
    
    public void sendResult(TaskResult result) {
        kafkaTemplate.send("mindra-results", result.getTaskId(), result)
            .addCallback(
                success -> log.info("Result sent: {}", result.getTaskId()),
                failure -> log.error("Failed to send result", failure)
            );
    }
}
```

```java
@Configuration
public class DataSourceConfig {

    }

        return DataSourceBuilder.create().build();
    }
    
    @Bean
    public JdbcTemplate mindraJdbcTemplate(@Qualifier("mindraDataSource") DataSource ds) {
        return new JdbcTemplate(ds);
    }
}

/**
 * Mindra 数据访问
 */
@Repository
public class MindraRepository {
    
    @Autowired
    @Qualifier("mindraJdbcTemplate")
    private JdbcTemplate jdbcTemplate;
    
    public void saveTask(Task task) {
        String sql = "INSERT INTO mindra_tasks (id, type, status, data, created_at) VALUES (?, ?, ?, ?, ?)";
        jdbcTemplate.update(sql, 
            task.getId(), 
            task.getType(), 
            task.getStatus(),
            JsonUtils.toJson(task),
            Timestamp.from(Instant.now()));
    }
    
    public List<Task> findPendingTasks() {
        String sql = "SELECT * FROM mindra_tasks WHERE status = 'PENDING' ORDER BY created_at";
        return jdbcTemplate.query(sql, new TaskRowMapper());
    }
}
```

```java
                Tags.of("agent_type", agentType),

    }

    }
}
```

```java
@Service
public class EcommerceService {

                "browsingHistory", getBrowsingHistory(userId)

    }

     */
    public BigDecimal dynamicPricing(String productId) {

            .type("DYNAMIC_PRICING")

                "currentInventory", getInventory(productId),
                "competitorPrices", getCompetitorPrices(productId),
                "demandForecast", getDemandForecast(productId)
            ))
            .build();
        
        TaskResult result = mindraClient.execute(task);
        return result.getData();
    }
    
    /**
     * 库存预警
     */
    @Scheduled(fixedRate = 300000)  // 每5分钟检查

                .context(Map.of(
                    "productId", product.getId(),
                    "currentStock", product.getStock(),
                    "reorderPoint", product.getReorderPoint()
                ))
                .build();
            
            mindraClient.submitAsync(task);
        }
    }
}
```

## 常见陷阱与最佳实践

### 陷阱1：同步调用导致阻塞

```markdown
❌ 错误：
同步调用 Mindra Agent，等待结果返回

✅ 正确：
- 使用异步调用
- 消息队列解耦
- 设置超时时间
- 提供降级方案
```

### 陷阱2：忽视错误处理

```markdown
❌ 错误：
try {
    result = mindraClient.execute(task);
} catch (Exception e) {
    // 忽略错误
}

✅ 正确：
try {
    result = mindraClient.execute(task);
} catch (MindraTimeoutException e) {
    // 降级处理
    return fallbackService.handle(task);
} catch (MindraException e) {
    // 记录错误，人工介入
    alertService.alert(e);
    throw e;
}
```

### 陷阱3：资源泄漏

```markdown
❌ 错误：
每次调用都创建新的连接

✅ 正确：
- 使用连接池
- 复用客户端实例
- 及时释放资源
- 监控连接数
```

### 最佳实践

```markdown
1. 异步优先：使用消息队列解耦
2. 熔断降级：防止级联故障
3. 超时控制：避免长时间阻塞
4. 幂等设计：防止重复处理
5. 监控告警：及时发现问题
6. 配置外置：便于动态调整
7. 灰度发布：降低风险
8. 文档完善：便于维护
```

## 面试题与参考答案

### 1. Mindra 与 Spring Boot 集成的核心步骤？

**答案：**
- 添加 mindra-spring-boot-starter 依赖
- 配置 application.yml（API key、Agent、治理）
- 使用 @EnableMindra 启用
- 注入 MindraClient 使用
- 可选：自定义 Agent、治理规则

### 2. 如何保证 Mindra Agent 的高可用？

**答案：**
- K8s Deployment + HPA 自动扩缩容
- 服务网格（Istio）流量管理
- 多实例部署 + 负载均衡
- 健康检查 + 自动重启
- 熔断降级机制

### 3. Mindra 与消息队列集成的优势？

**答案：**
- 解耦：生产者和消费者独立
- 异步：非阻塞处理
- 削峰：平滑流量高峰
- 可靠：消息持久化
- 扩展：独立扩展消费者

### 4. 如何处理 Mindra Agent 的故障？

**答案：**
- 超时机制：设置合理超时时间
- 重试策略：指数退避重试
- 熔断器：失败率达到阈值后熔断
- 降级方案：返回默认值或缓存数据
- 告警通知：及时通知运维

### 5. Mindra 与现有数据库如何共存？

**答案：**
- 多数据源配置（业务库 + Mindra 库）
- 事务管理：分布式事务（Seata）
- 数据同步：Canal/Debezium
- 读写分离：主从架构
- 数据隔离：Schema 分离
